# 两份升级指导的对比分析

- 对比对象：
  - A：上一份《三套投研 Skill 对标分析与「市场概况 / 持仓分析」升级指导》
  - B：新上传《ETF 持仓分析动态研究层重构指导书》
- 结论先行：**两份不是替代关系，而是“战略/能力层”与“实施/基础设施层”的互补。**
  - A 回答“三套 Skill 各有什么可借、市场页和持仓页该补什么能力”。
  - B 回答“如何在本仓库新增一个可校验、可回写、可降级的动态研究层”。

---

## 1. 定位差异

| 维度 | A：上一份 | B：新上传 |
|---|---|---|
| 文档性质 | 竞品/机制对标 + 升级方向 | 仓库架构审计 + 重构设计 + 参考实现 |
| 主要读者 | 产品/架构决策者 | 实施工程师 |
| 范围 | 三套 Skill + 市场页 + 持仓页 | 本仓库全链路 + 三套附件机制映射 |
| 核心目标 | 补分析能力、信息架构、组合诊断 | 补动态研究闭环、证据链、LLM 契约、隐私与校验 |
| 交付物 | 原则、方案、字段、路线图、验收清单 | 文件树、JSON Schema、参考代码、测试矩阵、迁移阶段 |
| 基线 | 以代码阅读为主 | 明确审计 commit，并声明 130 项测试通过 |

一句话：**A 更像“升级白皮书”，B 更像“重构施工图”。**

---

## 2. 关键差异

| 主题 | A 的立场 | B 的立场 | 差异实质 |
|---|---|---|---|
| LLM 定位 | 生产不调用 LLM；LLM 只做 P2 可选解释层 | 新增独立“动态研究层”，LLM 每日生成受约束 JSON | B 把 LLM 产品化，A 把 LLM 边缘化 |
| 隐私与发布 | 未展开 | **P0：明文持仓发布口径冲突，公开/私密通道物理分离** | B 补上了 A 的最大盲区 |
| 研究输入 | 建议结构化 `market/legs` 字段 | 统一 `research_input.json`，作为模型最小充分事实 | B 更完整，直接服务模型与校验 |
| 证据链 | 建议 `evidence_ids` | 完整 `EvidenceLedger`：来源、观测/发布/采集时间、质量、哈希、路径 | B 可落地，A 只到概念 |
| 历史差异 | `market.delta` + `decision_diff` | 私有历史库 + 确定性 `change_set` | 目标一致，B 的契约更细 |
| 市场页 | 状态向量、扩散、情景、主题暴露 | 字段级时效、当日变化、背景/因果分离、冲突可见 | A 偏分析深度，B 偏数据诚实与叙事基础 |
| 持仓页 | 结论卡、风险穿透、归因、压力测试 | 今日研究首屏、逐仓研究卡、证据抽屉、指纹绑定 | A 偏组合分析，B 偏研究闭环与呈现 |
| 校验 | 测试与验收清单 | 六层校验 + 一次纠错 + 失败降级 + 指纹失效 | B 更工程化 |
| 优先级 | P0 结论卡/结构化/上期快照/差异/风险穿透 | P0 隐私 + 研究地基；P1 人工/Agent 闭环；P2 自动模型 | B 更强调“先地基、后模型” |
| 概率 | 未校准不得称置信度 | 第一阶段不输出概率，P4 仅 Shadow 校准 | **高度一致** |

---

## 3. 高度一致的部分

两份文档在以下原则上没有分歧，可以直接合并：

1. **决策层冻结**：`methodology.decide()` 仍是唯一动作来源，LLM 不得生成或修改交易动作。
2. **缺数据不填 0**：`ABSTAIN ≠ HOLD`，缺失写 `unavailable`，不用常识补齐。
3. **上期快照是刚需**：没有上一有效快照，就不能说“改善/恶化/扩散/收缩”。
4. **结论先行、证据可回查**：顶部先给主要矛盾，细节折叠，判断能回到字段与来源。
5. **不引入未校准概率**：不把评分当胜率，不把缠论加权分当动作依据。
6. **不照搬缠论决策**：只吸收结构、冲突、多级别和呈现方式。

---

## 4. B 明显强于 A 的地方

1. **隐私 P0**：指出 `daily.sh` / `run_update.py` 会把已存在的明文持仓报告与 packet 加入提交，而运行指导又要求不公开；这是发布级风险，A 完全没覆盖。
2. **独立叙事契约**：`portfolio_decision` 与 `portfolio_narrative` 分离，避免把 LLM 字段混进交易决策边界。
3. **指纹绑定**：`run_id + input_hash + decision_fingerprint + data_date`，修改持仓后旧研究自动失效，防止“旧分析当今日结论”。
4. **六层校验与降级**：Schema、证据引用、代码一致性、指纹、语义、发布门禁；失败一次纠错，仍失败则回退确定性摘要。
5. **具体工程资产**：文件树、Schema、`evidence.py`/`history.py`/`diff.py`/`validate.py` 参考实现、测试矩阵。
6. **具体缺陷定位**：`app.js` 的 `marketCompare=null`、`weighted_returns` 在 packet 顶层与旧文档路径不一致，都是可直接修的 bug。
7. **安全与成本**：提示词注入、外部模型脱敏、调用预算、缓存、故障矩阵。

---

## 5. A 明显强于 B 的地方

1. **三套 Skill 的横向拆解更完整**：aistock、缠论、etf-assistant 的定位、架构、可借/不可借对照更系统。
2. **市场分析深度**：状态向量（趋势/波动/广度/结构）、广度扩散、经验分位情景、波动分位，B 没有展开。
3. **组合分析深度**：权重变化归因（价格漂移 vs 主动交易）、风险贡献、高相关簇、三情景压力测试，B 只覆盖了集中度/相关性/基准比较。
4. **“证据完整度”替代“置信度”**：对三套 Skill 的 confidence 进行了统一批判，B 虽不输出概率，但没有展开这一层。
5. **分级更轻**：A 的 P0/P1/P2 更适合先做“看得见的分析升级”，B 的 P0 偏基础设施，短期页面变化不明显。

---

## 6. 冲突点与裁决建议

| 冲突点 | A | B | 建议裁决 |
|---|---|---|---|
| LLM 什么时候做 | P2 可选 | P1 人工/Agent 闭环，P2 自动 API | **先做 B 的 P0 地基；P1 人工/Agent 导入；自动 API 放 P2** |
| 结论卡由谁生成 | 确定性生成 | 从已验证叙事渲染 | **确定性摘要为强制兜底，LLM 叙事为可选覆盖；两者都不得改动作** |
| 持仓是否公开 | 未讨论 | 默认私密通道 | **采纳 B：持仓、证据、叙事、私密 HTML 不进入公开仓库** |
| 市场页先做什么 | 状态向量/情景 | 字段级时效 + 当日变化 | **先做时效与变化（P0），再做状态向量与情景（P1）** |
| 是否做压力测试 | 建议做 | 未展开 | **保留 A 的压力测试，但只做解释，不进订单** |
| 是否做归因 | 建议做 | 未展开 | **保留 A 的归因，前置条件是 B 的历史快照** |
| 概率预测 | 不校准不输出 | 第一阶段不输出，P4 Shadow | **完全一致，按 B 的 Shadow 路线执行** |

---

## 7. 合并后的推荐路线

| 阶段 | 目标 | 主要工作 | 来源 |
|---|---|---|---|
| P0 | 先止血、打地基 | 隐私硬门禁；公开/私密分离；`research_input`；`evidence`；历史快照；确定性 `change_set`；结构化市场字段 | B 为主，A 补充字段设计 |
| P1 | 让“每日研究”跑起来 | `portfolio_narrative` Schema；prompt 导出/response 导入；六层校验；指纹绑定；今日研究首屏；逐仓研究卡；修复 `marketCompare`；暴露风险穿透 | B 为主，A 补 UI 与风险展示 |
| P2 | 提升分析深度 | 市场状态向量；广度扩散；经验分位情景；组合归因；压力测试；自动模型适配与预算 | A 为主，B 提供契约与校验 |
| P3 | 扩展数据与研究面 | 字段级时效；多源健康/交叉验证；新闻去重与事件化；ETF 专项；日周联动；共振矩阵 | B 为主 |
| P4 | 预测与校准 | 预测记录；样本外评估；Brier/ECE；仅 Shadow | B 为主 |

**合并原则**：

- B 的 P0 隐私与地基优先于 A 的任何页面升级。
- A 的市场/组合分析能力，统一作为 `research_input` 的确定性字段输入，不另起一套事实源。
- B 的叙事层只消费 A 的结构化结果，不反向修改决策。
- 两份文档都要求的“上期快照 + 差异”，只实现一次，命名为 `change_set` / `decision_diff` 均可，但契约唯一。

---

## 8. 一句话总结

**A 解决“升级什么能力”，B 解决“如何安全地落地并每日回写”；正确顺序是先用 B 补隐私与研究地基，再用 A 补市场/组合分析深度，最后才让 LLM 叙事层覆盖在确定性结果之上。**
