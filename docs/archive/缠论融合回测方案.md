# 缠论与沉关河规则的融合回测方案

## 1. 要回答的问题

在**不修改**沉关河生产规则（`config/methodology.yaml`）的前提下，
把缠论结构信号作为**加仓过滤器**，是否能在时间外样本上改善风险调整后收益？

结论只有两种用途：

- 通过：作为 `methodology.decide` 之外的一层可选过滤，先以配置开关形式接入；
- 不通过：保留现状，缠论只做展示，不进入执行链。

## 2. 对照组设计

| 组 | 说明 | 用途 |
|---|---|---|
| A | 纯规则：现状 `features.frame + methodology.decide` | 基准 |
| B | 规则 + 缠论过滤：**只对 ADD 增加结构条件**；CLEAR/TRIM/HOLD 不变 | 待验证方案 |
| C | 纯缠论：仅有买卖点，不接沉关河规则 | 参考上界，不进入候选 |

选择只过滤 ADD 的原因：退出规则是风险纪律，不应被结构信号放宽；
收益主要来自加仓与持有，过滤加仓对回撤的影响更可控。

## 3. 缠论信号口径（必须无前视）

在每日 T 的窗口中，只用截至 T 日（含）的 K 线计算：

1. 包含处理 → 分型 → 笔 → 中枢（ZD/ZG）→ 走势方向 → 背驰 → 一/三类买卖点；
2. 与前端 `src/etfquant/web_assets/app.js` 的 `rsChan` 保持同一实现口径；
3. 数据先用 `sanitizeBars` 同规则清洗（去重、OHLC 校验、剔除未收盘、陈旧判断）。

### B 组候选过滤条件（先各测一版，不叠加调参）

- **B1 结构位置**：ADD 仅当价格不在中枢下方（`pos != below`）
- **B2 背驰确认**：ADD 仅当非顶背驰（`divergence.type != top`）
- **B3 底背驰优先**：ADD 仅当出现底背驰或 1B/3B
- **B4 组合**：B1 且 B2（只在 B1/B2 各自有效时才测，避免一次调太多）

明确不做的：

- 不用缠论分数覆盖 `CLEAR`
- 不把「主力 / 筹码 / 吸筹」等不可观测词加入规则
- 不为迎合结果修改规则阈值、`regime_fit` 或成本假设

## 4. 数据与时间切分

沿用 `scripts/run_backtest.py` 的固定池与切分：

- 训练：2023-01-01 ~ 2024-12-31（只用于开发与初步筛选）
- 验证：2025-01-01 ~ 2025-12-31（选参数，允许有限次对比）
- 最终测试：2026-01-01 ~ 2026-11-12（**只跑一次**）

固定标的池 16 只，基准 000300。报告需披露：

- 每只 ETF 的实际覆盖区间（部分标的上市较晚）
- 缺失标的与缺失天数
- 回测目标权重是参数（`leg_weight_pct`），不等于生产按 regime 动态给的权重

## 5. 评估指标

必须同时报告：

- 年化收益、最大回撤、Sharpe、Calmar
- 换手率、交易次数、平均持仓天数、暴露时间
- 胜率、盈亏比、profit factor
- 分年度、分市场状态（上行 / 震荡 / 下行）
- 成本敏感性：基准成本与 2 倍成本各跑一次

## 6. 事先写死的通过门槛

B 组相对 A 组，**同时**满足才进入接入讨论：

1. 最大回撤相对改善 ≥ 15%，或 Sharpe 提升 ≥ 0.15；
2. 年化收益不低于 A − 1 个百分点；
3. 交易次数增加不超过 30%；
4. 训练期与验证期方向一致（不能只靠单段样本）；
5. 最终测试只跑一次，结果不用于回改参数。

任一条不满足，结论就是「不接入」，保留缠论展示层。

## 7. 需要改动的代码点

1. `src/etfquant/analysis/chan.py`（新增）
   Python 版分型 / 笔 / 中枢 / 背驰 / 买卖点，与 `rsChan` 对齐。
2. `src/etfquant/backtest/engine.py`
   增加 `entry_filter(code, date, feats) -> bool` 钩子，默认 `None` 时行为不变。
3. `scripts/run_backtest.py`
   增加 `--variant A|B|C` 与 `--chan-filter B1|B2|B3`，一次输出对比表。
4. `tests/test_chan_parity.py`（新增）
   固定一段 K 线，Python 与 JS 的分型数量、笔数量、中枢区间、背驰标记一致。
5. `docs/回测报告.md`
   增加「规则 vs 规则+缠论」对比章节，旧结论仍然不可引用。

## 8. 执行顺序

1. 先落 Python `chan.py` + 对拍测试（不接引擎）
2. 引擎加 `entry_filter` 钩子，跑 A 组确认结果与现状完全一致（回归基线）
3. 跑 B1，训练期筛选，验证期确认
4. 通过门槛后，最终测试只跑一次
5. 写报告，决定是否接入配置开关

## 9. 已知限制

- ETF 到申万行业的映射是静态近似，回测中不能把行业暴露当作精确因子
- 缠论笔/中枢是简化实现，不等同严格级别递归
- 回测池与真实持仓不同，结论只能说明「过滤是否稳健」，不能直接外推个人组合收益
- 任何「曾多轮优化」的说法都不构成样本外有效性证明

## 10. 与页面的关系

本方案不改页面。若回测通过，再考虑：

- 在个股卡显示「规则动作 + 结构过滤结果」两行
- 用配置开关控制是否启用过滤，默认关闭
- 页面明确标注「结构过滤仅影响加仓，不影响退出」
