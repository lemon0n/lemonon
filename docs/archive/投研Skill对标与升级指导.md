# 三套投研 Skill 对标分析与「市场概况 / 持仓分析」升级指导

- 版本：2026-11-18
- 对标对象：`aistockresearcher v14`、`chanlun-multidimensional-tech-analysis`、`etf-assistant`
- 服务对象：本仓库 ETF 量化观察台的「市场概况」「持仓分析」两个页面及其数据链路
- 结论口径：只提研究性升级建议，不引入新的交易决策源，不改变 `config/methodology.yaml` 的规则语义

---

## 0. 一页结论

| Skill | 一句话定位 | 最值得借 | 不要照搬 |
|---|---|---|---|
| aistockresearcher | 全资产、多源、可导出报告的研究中枢 | 数据质量分级、证据链、经验分布与弃权、批量 diff | 大而全的工具面、LLM 叙事、启发式“置信度” |
| 缠论多维技术分析 | 单标的结构化技术分析与结论卡 | 结论先行、结构失效位、多级别、方法论可溯源 | 40/20/20/20 加权分做动作、建议性文案、Windows 路径耦合 |
| etf-assistant | 轻量 ETF CLI 查询工具 | ETF 分类速查、定投这个用户任务视角 | Yahoo `.SS` 取价、固定 8% 收益假设、无质量门禁 |

对本仓库的五条判断：

1. **升级重点不是“再加指标”，而是把已有事实变成结构化、可追溯、可比较的数据。**
   当前页面信息不少，但 `market.regime.observations` 是字符串，逐腿证据卡没有“与上次相比变了什么”，风险引擎算出的相关性/穿透/风险贡献没有充分呈现。
2. **市场页最缺“变化”和“扩散”，持仓页最缺“归因”和“差异”。**
   单日截面只能描述状态，不能回答“参与面在改善还是收缩”“今天和昨天有什么实质变化”。
3. **继续坚持单一决策源。**
   所有新增内容只能落在数据、质量、特征、组合模拟、解释呈现五层；`methodology.decide()` 仍是唯一动作出口，前端不得出现第二套规则。
4. **没有校准就不要叫“置信度”。**
   三套 Skill 都输出 confidence/信心分，但只有 aistock 的经验分布带样本量与 Brier 校准；其余都是规则加权。本仓库应优先输出 **数据质量 + 证据完整度**，而不是伪精确概率。
5. **优先级应按“证据价值/实现风险”排序。**
   P0：结论卡、结构化字段、上期快照、决策差异、风险穿透；P1：状态向量、扩散、情景、归因、压力测试；P2：主题暴露、导出、LLM 解释层。

## 1. 分析范围与方法

对三套 Skill 按同一分层拆解：

| 层 | 关注点 |
|---|---|
| 入口层 | SKILL 描述、触发词、CLI/MCP 入口、边界声明 |
| 数据层 | 数据源、降级顺序、时效、缺失语义、交叉验证 |
| 分析层 | 指标、因子、结构识别、打分与融合 |
| 决策层 | 动作如何产生、是否有唯一出口、是否有仓位/约束 |
| 组合层 | 现金、权重、集中度、相关性、执行后模拟 |
| 输出层 | 报告结构、可视化、导出、可追溯性 |
| 工程层 | 依赖、路径、测试、可移植性、可复现性 |

本仓库基线以 `src/etfquant/pipeline.py`、`webgen.py`、`portfolio/analysis.py`、`portfolio/positions.py`、`web/analysis_packet.json` 与 `docs/持仓分析每日运行指导.md` 为准。

## 2. 三套 Skill 解构

### 2.1 aistockresearcher（全球智能投研 v14）

**架构（六层）**

1. **多源路由层**：`MultiSourceRouter` 按市场/类别维护有序源列表，逐级降级；每个结果带 `source`、`freshness`、`tried_sources`、`source_count`、`confidence`；源失败进入冷却，`unavailable` 不计成功。
2. **统一编排层**：`ResearchHub.analyze()` 并行获取行情、历史、新闻、资金、基本面、基金/期货快照，归一化后进入分析。
3. **因子分析层**：`ResearchAnalyzer` 产出趋势、动量、MACD、RSI、波动率、量价、资金流、基本面、新闻等因子；`weighted_score()` 按权重与因子置信度合成评分。
4. **概率预测层**：`EmpiricalForecastEngine` 用 20 日动量 + 已实现波动做 kNN 邻域，输出 1d/5d/1M/3M/6M 的分位数、方向概率、区间、样本量与 Brier 技能分；样本不足或校准失败主动弃权。
5. **证据链层**：`EvidenceLedger` 给每条结论绑定 `evidence_id`、来源、时间、质量；报告可回溯。
6. **产物层**：Markdown/JSON、Word/PPT/PDF（格式中立 IR）、批量研究、两份报告 diff、MCP 26 工具。

**值得借**

- **数据诚实三铁律**：拿不到就报不可用，不拿 0 价/空表冒充；预测样本不足就弃权；评分不等于盈利保证。与本仓库 `ABSTAIN` 语义同源。
- **质量分级**：`actual / derived / estimated / unavailable / insufficient` 比单一状态更细，适合映射到本仓库的 `OK / DEGRADED / ABSTAIN / DEMO`。
- **经验分布而非点预测**：分位数 + 样本量 + 弃权条件，是“情景分析”的合规范本。
- **批量 diff 的实质性变化阈值**：评分变化、方向翻转、质量状态变化、概率变化超过阈值才提示，可直接借鉴到持仓日报。
- **报告 IR**：一份结构化结果多格式输出，避免报告与页面各写一套事实。

**不要照搬**

- 约 6 万行（含脚本与测试）、26 个 MCP 工具、跨 12 个市场的工具面，与本仓库“单一 ETF 组合、每日一次确定性运行”不匹配，维护成本过高。
- 因子评分与 confidence 是启发式加权，不是校准概率；不能直接变成页面上的“上涨概率”。
- 国内免费接口的时效、反爬与合规风险，不能成为生产链路的单点依赖。
- LLM 分析属于解释层，不能进入确定性决策链。

### 2.2 缠论多维技术分析

**架构**

- 取数：`tdx-pro`/pytdx 为主路径，TDX MCP 为备用；ETF 代码前缀自动分流。
- 引擎：`chan_engine`（包含处理 → 分型 → 笔 → 线段 → 中枢 → 一/二/三类买卖点）、K 线形态、资金流、成交量、技术指标、信号融合。
- 决策：5 维分析 + 1 决策打分；默认权重缠论 40%、K 线 20%、资金 20%、量能 20%；信心 0–10 = 一致性 4 + 强度 3 − 背离惩罚 2 + 交叉确认 1。
- 输出：结论速览五档（强烈看多/看多/中性/观望/看空/强烈看空）+ 量化操作建议（动作、仓位、止损、结构失效位）+ 技术细节折叠 + 日线/周线多级别 + 方法论四模块 + HTML/技能卡。

**值得借**

- **结论先行**：顶部固定“结论速览 + 操作建议”，技术细节默认折叠。本仓库市场页和持仓页都可以采用同样的信息层级。
- **结构失效位**：不只给动作，还给“什么价格/什么条件会推翻当前判断”，与本仓库证据卡的 `invalidation` 天然契合。
- **多级别视角**：周线定方向、日线找点位；只做展示与方向增强，不回流融合权重。对应本仓库可做“月/周/日”或“基准/行业/个股”三层。
- **方法论可溯源**：理论、识别、决策 SOP、风控、ETF 适配五份 references，规则能回查到书源。
- **报告信息架构**：长报告有锚点导航、折叠区、打印样式，阅读体验成熟。

**不要照搬**

- **40/20/20/20 加权分作为动作依据**：权重与阈值是经验值，没有时间外验证；加权还会掩盖维度冲突。
- **建议性文案**：“强烈看多、建议积极布局”与本仓库“研究辅助、不构成投资建议”的边界冲突。
- **单标的视角**：没有组合约束、现金、相关性、执行后模拟，不能直接用于持仓页。
- **工程耦合**：Windows 绝对路径、`tdx-pro` 强依赖、ECharts CDN 依赖，不适合当前 Linux + 单文件 HTML 的发布方式。

### 2.3 etf-assistant

**事实**：约 9.5KB / 318 行 Bash 脚本；14 只静态 ETF 列表；用 Yahoo Finance chart 接口取现价；compare 只比现价；定投计算器固定 8% 年化；无历史序列、无数据质量、无风险、无组合。

**可取**

- ETF 分类速查：宽基、行业主题、港股/海外、Smart Beta，适合作为页面筛选或帮助文案。
- CLI 的低门槛交互：`list / price / hot / search / compare / calc`，任务导向清晰。
- 定投计算器代表的“用户任务”视角：用户不只想知道涨跌，还想知道定投结果。

**问题**

- 所有代码拼 `.SS`，深市 ETF（`15xxxx`）会取错市场。
- `get_etf_name()` 的 `sed` 兜底会把未命中名称写成“未知ETF”，属于静默错误。
- 固定 8% 年化是演示假设，不能作为分析结论或收益承诺。

**结论**：只作为 IA/交互参考，不作为方法论或数据源。

## 4. 本仓库现状基线

### 4.1 已有优势（不要推倒）

- **单一决策源**：`config/methodology.yaml` + `methodology.decide()`；前端 `rules.js` 只是同构镜像，没有第二套等级映射。
- **数据质量门禁**：`OK / DEGRADED / ABSTAIN / DEMO / ERROR`；缺价不填 0；`ABSTAIN ≠ HOLD`。
- **执行后闭环**：目标权重 → 目标份额 → 费用 → 现金 → 约束校验；明确“静态模拟不是成交”。
- **分母纪律**：`weight/position_pct` 以含现金总资产为分母，`category_of_invested` 以已投资市值为分母。
- **发布前校验**：`run_id / input_hash / validation` + `--verify`，保证页面、数据包、清单同源。
- **证据卡七块**：事实、比较、规则、组合含义、反证、未知项、失效条件，已经优于大多数同类工具。
- **无 LLM 参与生产决策**：LLM 只在个人解读工作流中使用。

### 4.2 市场概况的缺口

| 缺口 | 现状 | 影响 | 升级方向 |
|---|---|---|---|
| 单基准、单尺度 | 只用 `000300` 的收盘/MA20/MA60/vol20/vol60 | 无法区分“指数下跌但广度改善” | 状态向量：趋势、波动、广度、结构、外围 |
| 无变化视角 | 只有当日截面 | 无法判断扩散/收缩、轮动加速/减速 | 上期快照 + `market.delta` |
| 观察项是字符串 | `observations: ["基准收盘 …", "MA5 低于 MA20", …]` | 前端无法复用、无法校验、无法做差异 | 结构化字段 + 保留人话渲染 |
| 快照与实时混排 | 宏观/新闻/政策为离线快照 | 容易被误读为当日事实 | 逐项 `as_of/source/quality` |
| 无情景 | 只有仓位区间 | 无法回答“如果明天破位会怎样” | 经验分位情景 + 触发条件 |
| 行业与持仓无映射 | 页面只有 regime 联动条 | 无法回答“我的持仓暴露在哪个主线” | `track` → 行业/主题映射 |
| 来源健康不可见 | `fallback` 只在 `last_run.json` | 页面无法判断当日可信度 | `data_quality.channels` |

### 4.3 持仓分析的缺口

| 缺口 | 现状 | 影响 | 升级方向 |
|---|---|---|---|
| 逐腿中期特征不足 | 逐腿只有 MA5/10/20 + vol20 | 无法判断 MA60 与中期趋势（文档已承认） | 补 MA60/MA120、均线斜率、vol60、60 日回撤 |
| 无上期快照 | 每次只算当前组合 | 无法区分价格漂移与主动交易 | 保存上一交易日快照，做权重变化分解 |
| 风险结果未充分呈现 | 后端已算相关性、穿透、风险贡献 | 页面主要展示名义集中度，信息浪费 | 风险穿透区块 + 高相关簇 + 贡献占比 |
| 无决策差异 | 每天一份完整报告 | 难以判断“今天和昨天有什么实质变化” | `decision_diff`：新增/解除/未变/质量变化 |
| 无压力测试 | 执行后仓位是单点静态估算 | 无法回答“市场再跌 5% 会怎样” | 基准 −5%、波动 ×1.5、相关性上升三情景 |
| 证据卡长 | 七块信息完整但阅读成本高 | 用户先看到细节，后看到矛盾 | 顶部“三个主要矛盾”摘要 |
| 分类启发式 | 名称关键词/代码段 | 未分类会阻断结构结论 | 保留 `category_basis`，页面提供修正入口 |

## 5. 升级总原则与目标架构

### 5.1 五条原则

1. **单一事实源**：页面、报告、审计都只读 `analysis_packet`；新增字段也必须由后端产出，前端不推导第二套结论。
2. **结构化优先**：所有新增判断先落结构化字段，再渲染人话；不要先写一段文字再让前端解析。
3. **质量分层**：每个新增字段带 `as_of / source / quality`；缺失写 `unavailable`，不写 0、不写空表。
4. **结论可证伪**：每个结论配 `invalidation` 与“下一次核对什么”；没有失效条件的结论不允许发布。
5. **解释与决策分离**：LLM 与文案只解释 packet，不得修改 `action / target_shares / orders / validation`。

### 5.2 目标分层

| 层 | 职责 | 本次是否改动 |
|---|---|---|
| L0 数据通道 | 东财/腾讯/新浪/离线快照，逐通道健康 | 可增强 |
| L1 质量与契约 | `quality`、`packet`、`schema` | 可增强 |
| L2 特征与状态 | `features`、`market_regime`、`relative_strength` | 主要升级区 |
| L3 唯一决策 | `methodology.decide()` | **不改语义** |
| L4 组合模拟 | `execution`、`risk` | 可增强 |
| L5 解释与呈现 | `analysis`、`webgen`、`app.js` | 主要升级区 |
| L6 产物与校验 | `run_update`、`--verify`、`daily.sh` | 跟随契约升级 |

> 一句话：**L3 冻结，L1/L2/L4/L5 增强。**

## 6. 市场概况升级方案

### 6.1 M1 市场状态向量（P1，先结构化）

保留现有 `regime` 标签与 `regime_fit` 映射，新增维度字段，避免破坏兼容性：

```json
{
  "regime": {
    "label": "下行趋势",
    "fit_lo": 30,
    "fit_hi": 40,
    "as_of": "2026-11-17",
    "quality": "actual",
    "coverage": 0.8,
    "dimensions": {
      "trend": {
        "state": "down",
        "close_vs_ma20_pct": -1.84,
        "close_vs_ma60_pct": -8.12,
        "ma20_slope_5d_pct": -0.63,
        "ma60_slope_20d_pct": -0.41
      },
      "volatility": {
        "vol20": 17.09,
        "vol60": 14.70,
        "state": "normal",
        "percentile_1y": 62
      },
      "breadth": {
        "up": 1200,
        "down": 3600,
        "flat": 200,
        "median_chg_pct": -1.2,
        "diffusion": 0.25
      },
      "structure": {
        "leaders": ["银行", "红利"],
        "laggards": ["创业板", "半导体"],
        "concentration": 0.41
      }
    },
    "evidence_ids": ["MKT-TREND-1", "MKT-VOL-1", "MKT-BREADTH-1"]
  }
}
```

要点：

- `regime` 标签仍是唯一进入 `regime_fit` 的字段，维度只做解释与证据，不直接产生动作。
- `coverage` 表示“有几个维度拿到数据”，不是概率；不要命名为 `confidence`。
- 波动维度优先使用 **1 年分位**，避免“17% 算高还是低”没有参照。
- 趋势维度增加斜率，区分“跌破均线但走平”和“跌破均线且加速下行”。

### 6.2 M2 变化与扩散（P0）

新增 `market.delta`，只在“上一份快照的数据日 = 上一交易日”时计算，否则明确 `unavailable`：

```json
{
  "delta": {
    "available": true,
    "prev_data_date": "2026-11-14",
    "regime_change": null,
    "breadth_delta": {"up": -320, "down": 410, "median_chg_pct": -0.6},
    "diffusion_delta": -0.08,
    "leaders_entered": ["银行"],
    "leaders_dropped": ["煤炭"],
    "amount_chg_pct": 8.4,
    "note": "参与面收缩，成交放大，属于结构性走弱而非全面反弹"
  }
}
```

价值：

- 回答“扩散还是收缩”“轮动加速还是减速”，这是当前单日截面无法回答的。
- 复用 `data/runs/` 已有归档；不需要新增外部数据源。
- 必须做 **无前视校验**：上一份快照的 `data_date` 必须严格早于当前 `data_date`。

### 6.3 M3 情景分析（P1，经验分位，不给点预测）

借鉴 aistock 的经验分布，但只做“条件情景”，不做“明日涨跌预测”：

- 条件：当前 `regime` 标签 + 波动分档（低/中/高）。
- 样本：基准指数历史上同条件后的 5/20 日收益。
- 输出：`p25 / p50 / p75`、样本量、历史命中率、区间。
- 弃权：样本 `< 60` 或数据不足时写 `unavailable`，不给方向。
- 展示：熊/基准/牛三情景 + 触发条件，不写“预计上涨 X%”。

### 6.4 M4 证据与来源（P0）

- 每个市场区块的条目统一带 `as_of / source / quality`。
- `data_quality.channels` 记录每个通道的最后成功时间、延迟、状态、降级原因。
- 页面顶部来源徽章从“实时/降级”升级为“逐通道健康”，但保持一句话可读。
- 离线快照的宏观/新闻/政策必须显式标注“快照，仅背景，不定仓”。

### 6.5 M5 主题→持仓暴露（P2）

- 用 `universe.yaml` 的 `track` 字段建立“行业/主题 → ETF”映射。
- 市场页展示：今日主线/落后方向中，我的持仓暴露分别是多少。
- 只做暴露描述，不做“因为政策所以某 ETF 会涨”的因果推断。

### 6.6 M6 页面信息架构（P0）

当前市场页是“总览 → 指数 → 热力图 → 宏观 → 政策”的长仪表盘。建议改为：

1. **结论速览**：3 条判断 + 1 条失效条件 + 仓位区间。
2. **状态向量**：趋势 / 波动 / 广度 / 结构四张小卡。
3. **今日变化**：扩散、轮动、成交、情绪的变化。
4. **情景**：熊/基准/牛与触发条件。
5. **明细**：现有热力图、行业表、宏观、政策、新闻，默认折叠。

原则：**先回答“今天市场怎么样、什么会推翻它”，再给明细。**

## 7. 持仓分析升级方案

### 7.1 H1 组合结论卡（P0）

在页面顶部固定三块：

1. **三个主要矛盾**：从 `S1 仓位偏离`、`S2 结构偏离`、`plan.violations`、`data_quality` 中按优先级取前三。
2. **组合姿态**：防守 / 中性 / 进攻，由现有 `S1` 与执行后仓位确定性推导，不新增评分。
3. **什么会改变结论**：引用逐腿 `invalidation` 与市场 `invalidation`，只列最关键的两三条。

禁止：新增“健康分”“综合置信度”之类的单一分数。

### 7.2 H2 逐腿证据卡 v2（P0）

在现有七块基础上补：

- **中期结构**：MA60、MA120、MA20/MA60 斜率、60 日最大回撤。
- **波动**：vol60，与 vol20 的对比。
- **相对强弱**：5/20/60 日超额，基准缺失时写“不可比较”。
- **变化**：与上一交易日相比，规则命中、等级、数据状态、权重是否变化。
- **下一次核对**：具体到字段与阈值，例如“收盘是否重新站上 MA10 连续 2 日”。

建议结构：

```json
{
  "facts": [],
  "comparisons": [],
  "rules": [],
  "portfolio_impact": [],
  "counter_evidence": [],
  "unknowns": [],
  "invalidation": [],
  "changes_since_last_run": [],
  "next_check": [],
  "evidence_ids": []
}
```

### 7.3 H3 风险穿透（P0）

后端 `portfolio/risk.py` 已经计算：

- `nominal`：单只最大、HHI、有效只数。
- `lookthrough`：按跟踪指数/类别合并的底层敞口。
- `correlation`：高相关持仓对。
- `risk_contribution`：成分风险贡献。

页面目前主要展示名义集中度，建议新增“风险穿透”区块：

- 底层敞口 Top 5。
- 高相关簇（≥0.7）与“看似分散、实则同向”的提示。
- 风险贡献占比，与权重占比对比，指出“权重不大但风险贡献高”的腿。
- 相关性不可估计时，明确写“不做分散结论”。

### 7.4 H4 归因（P1）

需要上一交易日快照。权重变化分解：

```text
权重变化 = 价格漂移 + 主动交易 + 现金变化 + 残差
```

- 价格漂移：用上一日份额 × 当日收益估算。
- 主动交易：份额变化 × 当日价格。
- 现金变化：现金/总资产变化。
- 无上期快照或交易流水时，写“不可归因，仅能说明当前权重偏高/偏低”。

这条能直接提升持仓报告的“专业感”，但必须先有历史快照，不能凭常识推断。

### 7.5 H5 决策差异（P0）

新增 `decision_diff`，回答“今天和昨天有什么实质变化”：

```json
{
  "new_triggers": [{"code": "510300", "rule": "R-D1", "action": "CLEAR"}],
  "resolved": [{"code": "510500", "rule": "R-D1"}],
  "unchanged": 2,
  "quality_changes": [{"code": "588000", "from": "OK", "to": "DEGRADED"}],
  "material": true
}
```

实质性变化阈值建议放在配置中：

- 动作变化（ADD/TRIM/CLEAR/HOLD 任一变化）。
- 等级变化（A/B/C/D）。
- 权重变化超过不换仓带（如 2pct）。
- 数据质量状态变化（OK ↔ DEGRADED/ABSTAIN）。
- 市场状态标签变化。

### 7.6 H6 压力测试（P1）

对“执行后组合”做三个确定性情景：

| 情景 | 假设 | 输出 |
|---|---|---|
| 基准回调 | 基准 −5% | 组合估算回撤、风险贡献变化 |
| 波动抬升 | 各腿 vol ×1.5 | 风险预算占用、集中度是否恶化 |
| 相关性上升 | 高相关对升至 0.8 | 有效只数下降、分散失效提示 |

明确标注“情景推演，不是预测”，且不改变 `orders`。

### 7.7 H7 报告与导出（P2）

- `scripts/analyze_positions.py` 增加“三个主要矛盾”“今日变化”“风险穿透”“压力测试”四节。
- 可选输出 JSON/Markdown 双格式；继续以 packet 为唯一事实源。
- 不新增 PDF/PPT，除非有明确使用场景。

## 10. 反模式与风险控制

1. **不要把缠论的 40/20/20/20 加权分直接变成动作。** 它是解释性评分，不是校准概率；加权会掩盖冲突。
2. **不要引入“强烈看多/建议买入”文案。** 本仓库只做研究辅助，动作语义必须来自规则卡。
3. **不要把 aistock 的 LLM 叙事放进生产页面。** LLM 只能解释 packet，不能新增事实或修改动作。
4. **不要给未校准概率。** 任何概率必须有样本量、区间、弃权条件；否则只报证据完整度。
5. **不要用 ETF assistant 的 Yahoo `.SS` 取价。** 深市 ETF 会取错市场；固定 8% 定投收益也不可引用。
6. **不要让快照数据伪装实时。** 宏观/新闻/政策必须标注快照与日期。
7. **不要在前端写第二套规则。** 新增谓词必须先落后端，再同步 `rules.js`，并加同构测试。
8. **不要混用分母。** 含现金总资产与已投资市值必须字段名区分。
9. **不要用不可观测因果。** “主力吸筹/出货/诱多”不得作为证据。
10. **不要用未来数据。** 上期快照、基准对齐、回测都必须做时间隔离。
