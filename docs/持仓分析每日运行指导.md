# 持仓分析每日运行指导

> **已归档，不用于每日刷新。** 每日刷新只看仓库根目录的 `AGENTS.md`，执行 `bash scripts/daily.sh`；本文仅作历史参考。

## 目的

每个交易日运行一次，把当日市场数据与持仓数据整理成一份有分析深度的组合解读。

- 本文件规定**分析什么、依据什么判断、如何论证**，不提供可套用的固定句子，也不预设每天的结论、仓位或买卖动作。
- 输出**栏目固定**（便于每天在同一位置看到同类分析），但**内容必须由当日证据推导**，不允许复制昨日表述。
- 本文件供你个人的 LLM/MCP 工作流读取，不显示在 HTML 页面，应用不会自动调用 LLM。
- 规则动作、目标份额、订单、风险门禁只来自结构化数据；LLM 负责解释与推理，不得修改、重算或新增。

## 〇、工作流边界（先确认读的是哪一套）

仓库里有两类 LLM 任务，输出约束不同，不能混用：

| 工作流 | 用途 | 约束文件 | 是否允许解释持仓动作 |
|---|---|---|---|
| A. 公开市场摘要 | 只总结公开市场概况 | `docs/每日运行说明.md` 第四节 | 否（不得出现交易字段） |
| B. 本机持仓深度解读 | 结合本机解密后的持仓做组合分析 | **本文件** | 是，但只能原样解释，不能修改 |

执行本文件的任务属于 B。若同一次输出既包含公开市场摘要又包含持仓解读，应按 B 的规则处理持仓部分，并在开头注明"以下含本机持仓解读，不用于公开发布"。不要因为工作流 A 的"禁止交易字段"要求，而删掉持仓动作的解释。

## 一、数据源与字段路径

分析所需信息分散在三个来源，字段不存在时按第二节降级规则处理，不得凭常识补齐。

### 1.1 公开市场：`web/index.html` 内嵌 `window.DASHBOARD`

| 行业涨跌与成交 | `market.heat[]`（`name`/`chg`/`v`/`cap`）、`market.flow[]`（`sector`/`turnover`/`share`/`chg`/`cap`） |

注意：`market.regime.observations` 是**当前唯一提供基准 MA60 与 20/60 日波动的字段**。该数组为空时，趋势与波动分析必须降级，见 2.2。

### 1.2 持仓报告：`/tmp/持仓分析报告.md`

这是信息最完整的人工可读文本，包含：

- 一、运行与数据可信度
- 二、组合前视图（总资产、现金、仓位、浮盈亏、逐只持仓表）
- 三、逐标的证据卡，每只含：**可观测事实**、**市场关联**、**比较**、**规则结果**、**组合含义**、**反证**、**未知项**、**失效条件**
- 四、组合决策与执行后视图（S1 市场定仓、S2 结构核对、S4 目标份额、执行后复核）

逐仓的 `comparisons`、`portfolio_impact`、`invalidation` 与完整市场关联只在这里完整出现，**packet 里没有**。

## 二、能力边界与降级硬规则

以下规则优先于任何"深度"要求。**缺数据时写"当前输入不支持该判断"，不得用常识、经验或行业印象补出结论。**

### 2.1 必须降级的典型情形

| 想做的判断 | 需要的数据 | 数据不足时只能怎么写 |
|---|---|---|
| 判断行业参与面扩散/收缩、市场改善/恶化 | 前一交易日或指定窗口的行业数据 | "仅有当日截面，无法判断扩散或收缩" |
| 判断超配来自价格漂移还是主动加仓 | 上期持仓或交易流水 | "无交易流水，无法归因；仅能说明当前权重偏高" |
| 判断持仓中期趋势（MA60、MA20 方向） | 逐仓 MA60 或均线序列 | "逐仓数据仅含 MA5/10/20，无法判断 MA60 与中期趋势" |
| 判断某只 ETF 的行业/宏观/政策/新闻驱动 | 明确成分、行业权重或敏感度映射 | "无可验证逐仓关联，仅作组合级背景" |
| 判断"新变化" | 明确的上一期对照 | "无历史对照，只陈述当前观察" |
| 判断真实账户收益 | 完整交易流水 | "只有成本口径浮动盈亏，不代表账户累计绩效" |
| 判断底层资金流、机构行为 | 资金流与持仓穿透数据 | "输入未提供，无法判断" |

### 2.2 三个明确的降级边界

1. **`market.regime.observations` 为空** → 不能写基准均线排列与波动对比，只能写"市场状态为 X，具体均线与波动依据未提供"。
2. **`extras.links[code].relative_strength.known=false` 或基准缺失** → 该只只能写"相对基准不可比较"，禁止改用沪深300 或其他指数替代。
3. **`validation.ok=false` 或 `status` 为 `ABSTAIN`/`DEMO`/`ERROR`** → 不发布调仓结论；可解释原因与影响，但不得写成"继续持有""可以买入""建议减仓"。

### 2.3 单位口径

- 百分比字段已按百分数给出（如 `position_pct=61.10` 表示 61.10%），**不要除以 100，也不要把小数与百分数混算**。
- `weight_coverage` 是覆盖的权重百分点（如 60.0 表示覆盖总资产 60%），不是 0–1 的比例。
- 引用时保留原值与原单位标签（%、pct、元、份），不自行换算或二次四舍五入。

## 三、分析框架

输出保留以下栏目，但每栏要求做**推理**，不是填表。

### 1. 证据效力与判断边界

先判断今天的数据能支撑到什么程度的结论。需要说明：行情日与基准日是否一致、市场与行业数据是实时还是快照、持仓是否完整定价、分类是否完整、基准是否可用。

关键是要区分三类问题，后面的分析结论取决于此：

- **市场问题**：趋势、波动、结构、情绪的变化；
- **组合问题**：仓位偏离、集中度、类别失衡、现金不足；
- **数据问题**：缺价、未分类、基准缺失、快照数据。

数据类问题不能被解读成市场信号。若关键输入是 `ABSTAIN`/`DEMO`/`ERROR`，只能给出"当前不具备形成交易结论的条件"，并说明缺什么、影响哪一层判断。

**类别来源**：持仓类别按「持仓文件声明 → 行情源基金名称关键词 → 代码段」的顺序自动判定，
依据记录在 `category_basis`。只有三者都无法确定时才显示「未分类」；
此时不要猜测类别，也不要把它当成行业信号，直接指出缺口，并说明可在页面「持仓设置」手动指定。

### 2. 市场结构分析

不要只复述指标，要回答"市场处在什么状态、这个状态意味着什么、什么会推翻它"。

分析维度：

- **趋势层级**：短期（MA5 与 MA20 的排列）、中期（收盘相对 MA20、MA60）。`observations` 直接给出这三项，不同层级可能冲突，冲突本身就是信息，要说明以哪一层为主、为什么。注意 `observations` 不含"收盘与 MA5"的直接比较，不要凭空补。
- **波动状态**：20 日与 60 日波动对比。**是否"抬升"以 `observations` 的标注为准**（代码阈值为 20 日波动 > 60 日波动 × 1.25），不要仅凭 20 日数值略高就改写结论；未达阈值时不得称"风险扩大"。
- **参与面与结构**：行业涨跌分布、成交集中度、主线与落后方向。判断是普涨普跌还是结构性行情。**只有具备前一交易日对照时，才能说扩散或收缩。**
- **情绪与外围**：涨跌家数、情绪分、外围市场，仅作背景强弱参考。
- **宏观、政策、消息**：带日期和来源的部分，用来解释市场环境，不与单只 ETF 建立因果。

要求：

- 结论落到"风险偏好与仓位纪律"，不是预测点位或明日涨跌。
- 至少指出一个**最可能推翻当前判断的条件**。
- 某维度数据缺失或为快照时，说明它对结论的影响，而不是忽略。

### 3. 组合诊断

目标不是报数，而是解释"这个组合现在的状态是否合理、问题出在哪一层"。

分析维度：

- **仓位与市场状态的关系**：当前仓位相对模型区间的偏离。**没有交易流水时，不得断言偏离是主动加仓还是价格漂移**，只能说明当前偏离与可能的影响。
- **结构失衡的根源**：类别、风险桶、单只集中度中，哪一项是主要矛盾。可结合成本与现价差异做有限推断，但须标注为推断。
- **盈亏归因**：区分成本口径浮盈亏与市场整体表现，避免把普跌当成个体判断失误，也避免把普涨当成选股有效。
- **风险集中**：相关性、底层敞口、集中度是否形成叠加暴露。
- **现金与执行弹性**：现金比例是否支持后续动作；执行后现金、腿数、类别约束是否满足。
- **执行可行性**：执行后校验是否通过；未通过时说明是数据/分类问题还是约束问题。

要求：

- 明确区分"规则建议""可执行订单""执行后静态模拟"，三者不能混写。
- 对每一个异常给出"原因—影响—处理条件"，不要只写现象。
- 结论要能回答：今天这个组合的主要风险是什么，是市场带来的还是结构带来的。

### 4. 逐只持仓诊断

每只 ETF 形成独立判断，不重复字段。可用的逐仓数据以报告第三节为准；字段缺失时按第二节降级。

组织线索：

- **结构位置**：价格相对 MA5/10/20 的关系、连续站上 MA5 / 低于 MA10 的日数。逐仓事实还含量比与 20 日年化波动，但**没有逐仓 MA60、MA20 方向或 60 日波动**，因此不做逐仓中期趋势判断，也不做逐仓波动抬升对比（后者属于市场层 `observations`）。
- **量价关系**：量比与价格变化是否配合。ETF 量能受做市与申赎影响，结论要留有余地。
- **相对表现**：与其明确映射基准的同期超额；基准缺失时写"不可比较"。
- **市场与行业关系**：只有 `extras.links` 显示明确映射时，才讨论行业、主题、政策、新闻对该持仓的影响；否则写"无可验证逐仓关联"。
- **规则动作的逻辑**：命中规则、等级、动作原样引用，解释它在组合里意味着什么，不替规则编造因果。
- **核心矛盾**：指出最重要的多空冲突点。
- **反证与观察点**：什么证据会改变当前判断，下一次核对什么。

要求：避免"表现一般，注意风险"这类无信息量表述；每个判断指向具体字段或数据日期。

### 5. 决策与观察

回答三个问题：

1. 今天是否需要动作；优先级为：控制风险 → 结构调整 → 新增暴露。
2. 如果不需要动作，属于哪种原因：仓位在区间内、无候选通过门禁、数据不足、还是执行约束不满足。
3. 下一次需要验证什么条件，以及这些条件体现在什么字段上。

候选与建仓方向只使用输入中已存在的状态与理由；`READY` 不等于必须买入。没有候选时说明原因，不给替代标的。

## 四、编排要求

- **排序**：组合层先写当前最大风险与主要矛盾；逐仓按"风险退出 → 减仓 → 数据不足 → 加仓 → 持有"排列，不按输入顺序平均铺陈。
- **篇幅**：每只持仓只保留支撑当前判断的关键证据，不逐项复述全部指标；重复结论只在一处展开，其他位置引用。
- **引用**：关键判断标注来源字段或报告章节与数据日期（例如"报告第三节，数据日 2026-11-16"），避免只写"根据数据包"。
- **缺失**：某栏无数据时明确写"不可判断"并说明缺什么，不要留空，也不要用常识填充。

## 五、深度要求

1. **有因果链**：事实 → 推理 → 结论 → 反证。只给结论或只列数据都不合格。
2. **解释为什么**：不仅说"仓位偏高"，还要说明可能来源及其对当前市场状态的含义；来源不可归因时如实说明。
3. **处理矛盾**：指标冲突时说明冲突、判断哪一方权重更高、依据是什么。
4. **条件式结论**："在当前证据下……；若……则判断需要修正"，不做无条件预测。
5. **区分事实、推断、未知**：推断标明是推断，未知说明缺什么数据。
6. **不重复**：同一结论只展开一次；不复用昨日句子。
7. **不空话**：不使用"注意风险""保持谨慎""密切关注"，除非紧跟具体条件。

## 六、判断依据

以下为可引用的客观依据，用于支撑推理，不是输出模板。

| 观测 | 可支持的分析方向 |
|---|---|
| 收盘低于 MA20 且 MA20 低于 MA60 | 中期趋势偏弱 |
| 价格低于 MA20，但 MA5 高于 MA20 | 短线修复，尚不足以判断趋势反转 |
| 价格站上 MA20 且 MA20 高于 MA60 | 趋势修复中，中期转强需 MA60 确认 |
| `observations` 标注波动「抬升」（20 日 > 60 日 × 1.25） | 短期不确定性上升，同等仓位风险更高 |
| `observations` 标注「未抬升」 | 不能得出"风险正在扩大"；不得用 20 日数值略高改写 |
| 上涨集中在少数行业、成交集中 | 结构性行情，参与面有限 |
| 行业普遍上涨且成交同步放大 | 参与面改善；无前一日对照只说当前观察 |
| ETF 相对其映射基准超额为正且量能配合 | 相对强势；不等同于可以加仓 |
| 相对基准超额为负 | 不宜用"相对强势"解释该持仓 |
| 宏观、政策、新闻为快照或日期缺失 | 只作背景，不构成单只 ETF 的原因 |
| 持仓未分类或占比超限 | 结构判断不完整，先解决分类问题 |
| 执行后校验未通过 | 说明原因与影响范围，不发布调仓结论 |

## 七、动作与证据口径

### 7.1 四个层次不能混写

| 层次 | 字段 | 含义 |
|---|---|---|
| 规则动作 | `legs[*].action`、`extras.decision.holding_decisions[*].action` | 规则层的动作码 |
| 研究候选 | `holding_decisions[*].candidate_state`、`opportunities[*].state` | `READY` 等状态，仅表示通过门禁 |
| 可执行订单 | `orders[]` | 实际发布的订单；为空表示本次无订单 |
| 执行后可执行性 | `validation.ok`、`portfolio_after` | 约束是否通过；模拟不是成交 |

只有 `orders` 非空且 `validation.ok=true`，才可以描述为"具备执行条件"；`READY` 只说明候选通过门禁，不等于订单或必须建仓。

### 7.2 反证分三层

1. **已观察到的反向证据**：可引用具体字段。
2. **当前输入未发现反证**：只能写成"当前输入未提供反向证据"，不能写成"反证不存在"。
3. **待验证的失效条件**：来自 `invalidation` 或推导出的下一次核对条件。

代码在无冲突时会填"未发现与当前信号方向冲突的可观测证据（不等于信号有效）"，这是默认字段，不是穷尽搜索的结论，引用时须按上述第 2 层处理。

## 八、关联纪律

- 逐只持仓只使用其映射基准；不把沪深300 当作所有资产的统一基准。
- 行业、宏观、政策、新闻与单只 ETF 之间，只有存在明确映射时才建立关联；否则只能作为组合级背景。
- 同期变化不等于因果；没有历史对照不称"新变化"。
- 宏观与政策数据通常为快照且缺少逐条采集时间，引用时必须保留日期与来源限制。

## 九、禁止事项

- 不修改或重新推导 `action`、`candidate_state`、目标权重/份额、订单、风险门禁、规则阈值。
- 不输出未经校准的胜率、上涨概率、目标收益、保证成交价格。
- 不把静态模拟写成已成交，不把"无法判断"写成"继续持有"。
- 不引用已撤回的旧回测收益或胜率结论。
- 不使用"主力吸筹、试盘、出货、诱多"等不可观测因果作为证据。
- 不制造每日必须买卖的节奏；无动作、等待确认都是有效结论。
- 不在数据不足时用行业印象、常识或经验补出结论。

## 十、输出前自查

1. 结论是否建立在明确的数据日期与来源之上？
2. 是否区分了市场问题、组合问题、数据问题？
3. 是否只使用了输入中真实存在的字段，缺失处是否已降级？
4. 每个主要判断是否都有证据、推理和反证？
5. 是否指出了当前最重要的矛盾，而不是平均罗列指标？
6. 结论是否是条件式的，而不是无条件预测？
7. 是否避免了套话、重复和昨日句子的复用？
8. 动作结论是否与 `action`、`orders`、`validation.ok` 一致？
9. 是否没有新增数据中不存在的价格、仓位、新闻或代码？

## 十一、安全与边界

- 本分析是研究辅助，不构成收益保证或自动交易指令。
- 持仓与解密口令只在本机使用；不要把明文持仓、`positions_packet.json` 或口令提交到仓库、公开网页或日志。
- 证据不足时明确指出，不用确定语气包装不确定结论。
