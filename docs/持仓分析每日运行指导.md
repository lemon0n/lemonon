# 持仓分析每日运行指导

## 目的

每个交易日运行一次，把当日市场数据与持仓数据整理成一份有分析深度的组合解读。

- 本文件规定**分析什么、依据什么判断、如何论证**，不提供可套用的固定句子，也不预设每天的结论、仓位或买卖动作。
- 输出**栏目固定**（便于每天在同一位置看到同类分析），但**内容必须由当日证据推导**，不允许复制昨日表述。
- 本文件供你个人的 LLM/MCP 工作流读取，不显示在 HTML 页面，应用不会自动调用 LLM。
- 规则动作、目标份额、订单、风险门禁只来自结构化数据；LLM 负责解释与推理，不得修改、重算或新增。

## 一、输入

按顺序读取，缺失的字段在对应分析中明确说明其影响：

1. 公开市场数据：`web/index.html` 内嵌 `window.DASHBOARD`
   - `market.regime`：状态、仓位区间、observations、as_of
   - `market.heat` / `market.flow`：行业涨跌、成交额、占比
   - `market.macro` / `glob` / `liquidity` / `valuation`：宏观与外围背景
   - `market.policy_heat` / `calendar` / `news` / `news_sentiment`
   - `market.indices` / `breadth` / `distribution`：指数、广度、涨跌分布
   - `packet.data_quality`：`market_snapshot`、`sector_snapshot` 等来源状态
   - `meta.data_date`
2. 本机持仓分析产物（本机解密生成）
   - `/tmp/持仓分析报告.md`、`/tmp/positions_packet.json`
   - `portfolio_before`、`s1`、`s2`、`legs[*].evidence`、`legs[*].links`、`risk`、`orders`、`portfolio_after`、`validation`
3. 规则口径：`config/methodology.yaml`

口令只用于本机解密，不写入报告、提示记录、提交内容或日志。

## 二、分析框架

输出保留以下栏目，但每栏要求做**推理**，不是填表。

### 1. 证据效力与判断边界

先判断今天的数据能支撑到什么程度的结论。需要说明：行情日与基准日是否一致、市场与行业数据是实时还是快照、持仓是否完整定价、分类是否完整、基准是否可用。

关键是要区分三类问题，后面的分析结论取决于此：

- **市场问题**：趋势、波动、结构、情绪的变化；
- **组合问题**：仓位偏离、集中度、类别失衡、现金不足；
- **数据问题**：缺价、未分类、基准缺失、快照数据。

数据类问题不能被解读成市场信号。若关键输入是 `ABSTAIN`/`DEMO`/`ERROR`，只能给出"当前不具备形成交易结论的条件"，并说明缺什么、影响哪一层判断。

### 2. 市场结构分析

不要只复述指标，要回答"市场处在什么状态、这个状态意味着什么、什么会推翻它"。

分析维度：

- **趋势层级**：短期（MA5 与价格、MA5 与 MA20）、中期（MA20 方向、MA20 与 MA60）、长期位置。不同层级可能冲突，冲突本身就是信息，要说明以哪一层为主、为什么。
- **波动状态**：20 日与 60 日波动对比，波动抬升通常意味着同样的仓位承担更大的不确定性，但不等同于方向。
- **参与面与结构**：行业涨跌分布、成交集中度、主线与落后方向。要判断是普涨普跌还是结构性行情，参与面是否扩散或收缩。
- **情绪与外围**：涨跌家数、情绪分、外围市场，仅作背景强弱参考。
- **宏观、政策、消息**：在当前数据中带日期和来源的部分，用来解释市场环境，不与单只 ETF 建立因果。

要求：

- 结论要落到"风险偏好与仓位纪律"，不是预测点位或明日涨跌。
- 至少指出一个**最可能推翻当前判断的条件**（例如收盘重新站上 MA20、波动回落、成交萎缩）。
- 若某维度数据缺失或为快照，说明它对结论的影响，而不是忽略。

### 3. 组合诊断

目标不是报数，而是解释"这个组合现在的状态是否合理、问题出在哪一层"。

分析维度：

- **仓位与市场状态的关系**：当前仓位相对模型区间的偏离，是主动选择还是结构性结果；偏离是否需要处理，取决于是否存在通过门禁的动作。
- **结构失衡的根源**：类别、风险桶、单只集中度中，哪一项是主要矛盾；是配置意图造成的，还是价格漂移造成的（例如某只涨幅过大被动超配）。
- **盈亏归因**：区分成本口径浮盈亏与市场整体表现，避免把普跌当成个体判断失误，也避免把普涨当成选股有效。
- **风险集中**：相关性、底层敞口、集中度是否形成叠加暴露。
- **现金与执行弹性**：现金比例是否支持后续动作；执行后现金、腿数、类别约束是否仍满足。
- **执行可行性**：执行后校验是否通过；未通过时说明是数据/分类问题还是约束问题，以及这如何影响今天的结论。

要求：

- 明确区分"规则建议""可执行订单""执行后静态模拟"，三者不能混写。
- 对每一个异常（超配、未分类、校验失败、缺价）给出"原因—影响—处理条件"，不要只写现象。
- 结论要能回答：今天这个组合的主要风险是什么，这个风险是市场带来的还是结构带来的。

### 4. 逐只持仓诊断

每只 ETF 要形成独立判断，而不是重复字段。建议围绕以下线索组织：

- **结构位置**：价格相对 MA5/10/20 的关系、均线排列、连续站上或跌破的持续性，判断处于趋势延续、震荡还是转折尝试阶段。
- **量价关系**：量比与价格变化是否配合，放量上涨、放量下跌、缩量回踩代表不同的确认程度；ETF 的量能受做市与申赎影响，结论要留有余地。
- **相对表现**：与其明确映射基准的同期强弱；基准缺失时明确"不可比较"，不用沪深300代替所有资产。
- **市场与行业关系**：只有存在明确映射时，才讨论行业、主题、政策、新闻对该持仓的影响；没有映射时写"无可验证逐仓关联"，不从名称推断。
- **规则动作的逻辑**：命中的规则、等级、动作原样引用，并解释它在组合里意味着什么（例如减仓是为了控制哪部分风险）。
- **核心矛盾**：指出该持仓当前最重要的多空冲突点，例如趋势偏弱但相对基准持续走强、技术面转弱但组合权重已低于目标。
- **反证与观察点**：什么证据会改变当前判断，下一次需要核对什么。

要求：避免"该 ETF 表现一般，注意风险"这类没有信息量的表述；每个判断都要能指向具体字段或数据日期。

### 5. 决策与观察

回答三个问题：

1. 今天是否需要动作；如果需要，优先级是什么（控制风险优先于结构调整，结构调整优先于新增暴露）；
2. 如果不需要动作，是哪种原因：仓位在区间内、无候选通过门禁、数据不足、还是执行约束不满足；
3. 下一次需要验证什么条件，以及这些条件在什么数据上体现。

候选与建仓方向只使用输入中已存在的状态与理由；`READY` 表示通过门禁的研究候选，不是必须买入。没有候选时明确说明原因，而不是给出替代标的。

## 三、深度要求

这是本指导的核心，输出质量按以下标准判断：

1. **有因果链**：事实 → 推理 → 结论 → 反证。只给结论或只列数据都不合格。
2. **解释为什么**：不仅说"仓位偏高"，还要说明偏高来自价格上涨漂移还是主动加仓，以及为什么这在当前市场状态下重要。
3. **处理矛盾**：不同指标冲突时，说明冲突、判断哪一方权重更高、依据是什么。
4. **条件式结论**：给出"在当前证据下……；若……则判断需要修正"的表述，不做无条件预测。
5. **区分事实、推断、未知**：推断要标明是推断，未知要说明缺什么数据。
6. **不重复**：同一结论只在一处展开，其他位置引用即可；不复用昨日句子。
7. **不空话**：不使用"注意风险""保持谨慎""密切关注"等无信息量表达，除非后面紧跟具体条件。

## 四、判断依据

以下是分析时可引用的客观依据，用于支撑推理，不是输出模板。

| 观测 | 可支持的分析方向 |
|---|---|
| 收盘低于 MA20 且 MA20 低于 MA60 | 中期趋势偏弱 |
| 价格低于 MA20，但 MA5 刚回到 MA20 上方 | 短线修复，尚不足以判断趋势反转 |
| 价格站上 MA20 且 MA20 上行 | 趋势修复中，中期转强仍需 MA60 确认 |
| 20 日波动高于 60 日 | 短期不确定性上升，同等仓位风险更高 |
| 20 日波动不高于 60 日 | 不能得出"风险正在扩大" |
| 上涨集中在少数行业、成交集中 | 结构性行情，参与面有限 |
| 行业普遍上涨且成交同步放大 | 参与面改善；无前一日对照只说当前观察 |
| ETF 相对其映射基准超额为正且量能配合 | 相对强势；仍不等同于可以加仓 |
| 相对基准超额为负 | 不宜用"相对强势"解释该持仓 |
| 宏观、政策、新闻为快照或日期缺失 | 只作背景，不构成单只 ETF 的原因 |
| 持仓未分类或占比超限 | 结构判断不完整，先解决分类问题 |
| 执行后校验未通过 | 说明原因与影响范围，不发布调仓结论 |

## 五、关联纪律

- 逐只持仓只使用其映射基准；不把沪深300当作所有资产的统一基准。
- 行业、宏观、政策、新闻与单只 ETF 之间，只有在输入中存在明确映射（成分、跟踪指数、主题匹配）时才建立关联；否则只能作为组合级背景。
- 同期变化不等于因果；没有历史对照不称"新变化"。
- 宏观与政策数据通常为快照且缺少逐条采集时间，引用时必须保留日期与来源限制。

## 六、禁止事项

- 不修改或重新推导 `action`、`candidate_state`、目标权重/份额、订单、风险门禁、规则阈值。
- 不输出未经校准的胜率、上涨概率、目标收益、保证成交价格。
- 不把静态模拟写成已成交，不把"无法判断"写成"继续持有"。
- 不引用已撤回的旧回测收益或胜率结论。
- 不使用"主力吸筹、试盘、出货、诱多"等不可观测因果作为证据。
- 不制造每日必须买卖的节奏；无动作、等待确认都是有效结论。

## 七、输出前自查

1. 今天的结论是否建立在明确的数据日期与来源之上？
2. 是否区分了市场问题、组合问题、数据问题？
3. 每个主要判断是否都有证据、推理和反证？
4. 是否指出了当前最重要的矛盾，而不是平均罗列指标？
5. 结论是否是条件式的，而不是无条件预测？
6. 是否避免了套话、重复和昨日句子的复用？
7. 动作结论是否与结构化规则和门禁一致？
8. 是否没有新增数据中不存在的价格、仓位、新闻或代码？

## 八、安全与边界

- 本分析是研究辅助，不构成收益保证或自动交易指令。
- 持仓与解密口令只在本机使用；不要把明文持仓、`positions_packet.json` 或口令提交到仓库、公开网页或日志。
- 证据不足时明确指出，不用确定语气包装不确定结论。
