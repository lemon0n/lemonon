# 持仓分析每日运行指导

## 目的

每个交易日运行一次，把当日市场数据与持仓数据整理成一份固定结构、可追溯、结论克制的专业解读。

- 本文件只规定**怎么分析、怎么写**；不预设每天的结论、目标仓位、ETF 名单或买卖动作。
- 本文件供你个人的 LLM/MCP 工作流读取，**不显示在 HTML 页面**，应用也不会自动调用 LLM。
- 规则动作、目标份额、订单、风险门禁只来自结构化数据；LLM 只做解释，不得修改、重算或新增。

## 一、输入

按顺序读取，缺什么就在对应段落写"数据缺失，无法判断"：

1. 公开市场概况：`web/index.html` 内嵌的 `window.DASHBOARD`，重点字段：
   - `market.regime`：市场状态、仓位区间、observations、as_of
   - `market.heat` / `market.flow`：行业涨跌幅、成交额、占比
   - `market.macro` / `market.glob` / `market.liquidity` / `market.valuation`
   - `market.policy_heat` / `market.calendar` / `market.news` / `market.news_sentiment`
   - `market.indices` / `market.breadth` / `market.distribution`
   - `packet.data_quality`：`market_snapshot`、`sector_snapshot` 等来源状态
   - `meta.data_date`：行情数据日
2. 本机持仓分析产物（用你的口令在本机解密生成）：
   - `/tmp/持仓分析报告.md`
   - `/tmp/positions_packet.json`
   - 关键字段：`portfolio_before`、`s1`、`s2`、`legs[*].evidence`、`legs[*].links`、`risk`、`orders`、`portfolio_after`、`validation`、`constraints_after`
3. 规则口径：`config/methodology.yaml`（规则 ID、动作语义）。

口令只用于本机解密，不得回显、写入报告、提示记录、提交内容或日志。

## 二、输出：固定五段

每天固定输出以下五段，顺序不变，每段都要有结论句，不能只罗列数字。

输出文件建议：`/tmp/持仓分析解读.md`（每天覆盖）。

### 第 1 段 · 数据可信度与可判断范围

必须写清楚：

- 运行时间、行情数据日、市场快照日期、基准日期；
- 分析状态：`OK / DEGRADED / ABSTAIN / DEMO / ERROR`；
- 缺失项：缺价、未分类、基准缺失、快照/合成数据；
- 一句话结论：**本次哪些结论可以做，哪些不能做**。

判断规则：

| 状态 | 必须怎么写 |
|---|---|
| OK | 可以按后四段完整分析 |
| DEGRADED | 可以做分析，但涉及缺失字段的结论必须标注"该项受限" |
| ABSTAIN | 只输出"数据不足，本次无法形成可执行结论"，并说明缺什么 |
| DEMO | 明确"离线合成演示，不作交易依据"，不写任何操作建议 |
| ERROR | 明确"本次运行失败，不解读交易动作" |

### 第 2 段 · 市场状态解读

先用一句话给出市场判断，再给依据、反证和影响。禁止只复述"这是风险过滤器"这类固定说明。

必须覆盖：

1. 趋势位置：基准收盘与 MA5/MA20/MA60 的关系，MA20 与 MA60 的关系；
2. 波动：20 日与 60 日年化波动谁高谁低；
3. 结构：行业涨跌与成交是否集中，主线/落后方向；
4. 情绪与外围：涨跌分布、情绪分、外围市场（有数据才写）；
5. 宏观/政策/消息：作为背景，标注日期与来源，不与持仓做因果绑定。

判断标准（照此表述，不要升级结论）：

| 观测 | 只能得出 |
|---|---|
| 收盘低于 MA20 且 MA20 低于 MA60 | 中期趋势偏弱 |
| 收盘低于 MA20，但 MA5 刚站回 MA20 | 短线修复，不能称趋势反转 |
| 收盘站上 MA20 且 MA20 上行 | 趋势修复中，仍需站上 MA60 才谈中期转强 |
| 20 日波动 > 60 日波动 | 短期波动抬升，降低新增风险暴露的确定性 |
| 20 日波动 ≤ 60 日波动 | 波动未抬升，不能写"风险正在扩大" |
| 上涨行业集中在少数板块 | 结构性行情，参与面有限 |
| 行业普涨且成交同步放大 | 参与面改善（无前一日对照时只写"当前观察"） |
| 宏观/政策/新闻为快照或日期缺失 | 只作背景，不作任何单只 ETF 的原因 |

标准句式：

> 基准收于 X，位于 MA20（X）与 MA60（X）下方，MA20 低于 MA60；20 日波动 A% 高于 60 日 B%。结论：中期趋势偏弱、短期波动抬升，新增风险暴露应偏保守。支持证据：…；反证：若后续收盘重新站回 MA20 并站稳，弱势判断需修正。对仓位的含义：当前风险预算不宜上调，具体操作仍以持仓规则与组合约束为准。

### 第 3 段 · 组合资金解读

必须覆盖：总资产、现金、总仓位、风险仓位、成本口径浮盈亏、集中度（单只/单类）、类别或风险桶、未分类资产、基准比较（有才写）、执行后静态模拟与约束结果。

判断标准：

| 情形 | 只能得出 |
|---|---|
| 当前仓位低于区间下沿 | 仓位偏轻；是否补充取决于候选是否通过门禁，不自动等于加仓 |
| 当前仓位高于区间上沿 | 仓位偏重，优先降低风险暴露 |
| 仓位在区间内、但单只/单类超限 | 调结构优先，不扩大总仓位 |
| 现金低于最低保留比例 | 先保证现金缓冲，不新增买入 |
| 存在未分类资产且占比超上限 | 结构无法判断，先补齐分类；本次不形成调仓结论 |
| 执行后校验未通过 | 说明具体原因与受影响范围；不得写"继续持有"或"买入" |
| 综合分析不可用 | 本次不生成调仓单；这是数据/分类问题，不是市场卖出信号 |

必须区分三种东西，禁止混写：

1. 规则建议（每只标的的 action）；
2. 可执行订单（只有校验通过才有）；
3. 执行后静态模拟（按当前价估算，不是成交结果）。

### 第 4 段 · 逐只持仓解读

每只 ETF 固定六行，缺数据的行写"无数据"：

1. **事实**：代码、名称、类别、权重、成本口径盈亏、收盘、MA5/10/20、量比、行情日期；
2. **相对表现**：对应基准及 5/20 日超额；基准缺失写"不可比较"；
3. **市场关系**：市场状态对该持仓的影响；没有明确 ETF—行业/宏观/政策/新闻映射时写"无可验证逐仓关联"；
4. **规则与动作**：命中的规则 ID、等级、动作（原样引用，不重算）；
5. **组合影响**：对仓位、集中度、类别占比、现金的实际影响；
6. **反证与失效条件**：什么证据会推翻当前判断，什么条件触发下一次复核。

禁止：从名称推断行业因果；把浮亏或"跌得多"当作加仓理由；把个股"主力/筹码"叙事当作 ETF 证据。

### 第 5 段 · 行动结论与观察清单

- 先给一句总判断：**今天需要调整 / 不需要调整 / 数据不足无法判断**。
- 需要调整时：按优先级列出（减仓 → 结构调整 → 加仓 → 建仓），每项写"代码、动作、触发依据、约束结果"。
- 不需要调整时：明确写"本次无动作"，并说明理由（仓位在区间内 / 无候选通过门禁 / 数据不足）。
- 观察清单：列出下一次只需核对的条件，例如"收盘是否站回 MA20""某持仓是否补齐分类""候选是否满足现金约束"。
- 不新增数据中没有的价格、仓位、胜率、新闻或代码。

## 三、无数据与降级写法

不要用固定套话掩盖缺失，按下表直接写具体原因：

| 情况 | 写法 |
|---|---|
| 缺价格 | "X 缺少有效价格，本次无法计算总仓位和调仓建议" |
| 缺分类 | "X 只持仓缺少分类映射，结构核对不完整；先补齐分类再判断结构" |
| 缺基准 | "该 ETF 无可用对应基准，相对表现不可比较" |
| 快照/合成 | "该数据为离线快照，只作背景，不作交易依据" |
| 日期不一致 | "行情日与基准日不一致，相关比较不可用" |
| 无候选 | "本次没有候选通过组合门禁，维持观察"（只写一次，不重复解释） |
| 执行校验失败 | "本次执行校验未通过，原因：……；因此不生成调仓单" |

## 四、禁止清单

- 不修改或重新推导 `action`、`candidate_state`、目标权重/份额、订单、风险门禁、规则阈值。
- 不输出未经校准的胜率、上涨概率、目标收益、保证成交价格。
- 不把静态模拟写成已成交，不把"无法判断"写成"继续持有"。
- 不引用已撤回的旧回测收益/胜率结论。
- 不用"主力吸筹、试盘、出货、诱多"等不可观测因果当作证据。
- 不做每日必须买卖的暗示；无动作、等待确认都是有效结论。
- 不把宏观、政策、新闻的同期变化写成某只 ETF 涨跌的原因。

## 五、输出前自查

依次回答，全部为"是"才算合格：

1. 五段是否齐全且顺序正确？
2. 第 1 段是否写清状态、日期和缺失项？
3. 第 2 段是否有明确判断句、依据、反证？
4. 第 3 段是否区分了规则建议、订单、静态模拟？
5. 第 4 段是否每只持仓都有六行，缺失处写明？
6. 第 5 段是否给出"调整/不调整/无法判断"的明确结论？
7. 所有数字是否都能在输入中找到来源？
8. 是否没有新增动作、价格、胜率或新闻事实？

## 六、安全与边界

- 本分析是研究辅助，不构成收益保证或自动交易指令。
- 持仓与解密口令只在本机使用；不要把明文持仓、`positions_packet.json` 或口令提交到仓库、公开网页或日志。
- 数据不足时，明确说"无法判断"，比给出看似专业的确定结论更正确。
