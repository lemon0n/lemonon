# 每日运行任务说明（运维手册）

> **已归档，不用于每日刷新。** 每日刷新只看仓库根目录的 `AGENTS.md`，执行 `bash scripts/daily.sh`；本文仅作历史参考。

> 读者：每天手动触发一次的低端 Agent、CI 定时任务、人工复核人。
> 核心原则：**Agent 只负责调用确定性流水线，不自己算指标、不自己决定买卖。**
> 即使是能力较弱的模型，只要按本文执行，就不会跑偏。

---

## 一、每天到底跑什么（一条命令）

```bash
# 1) 先跑测试（不触网，10 秒内，挡住逻辑回归）
python3 -m pytest tests/ -q

# 2) 生成当日结果（取真实行情；任一关键通道失败会自动降级并如实上报）
python3.11 scripts/run_update.py --json

# 3) 只做发布前校验（不重新取数）
python3 scripts/run_update.py --verify
```

产物只有三个：

| 文件 | 作用 |
|---|---|
| `web/analysis_packet.json` | **唯一权威结果**（网页、报告、审计都只读它） |
| `web/index.html` | 单文件页面（CSS/JS/数据全内联，双击可看） |
| `data/last_run.json` | 运行清单：状态、数据日、跳过项、校验结果 |

退出码含义：`0` 正常 · `1` strict 模式下状态非 OK · `2` 运行异常 · `3` 推送失败 · `4` 发布前校验失败。

## 二、每天必须先看的一个字段：`status`

```bash
python3 - <<'PY'
import json
d = json.load(open('data/last_run.json'))
print(d['status'], d['data_date'], d['validation'])
PY
```

| status | 含义 | Agent 应该做什么 |
|---|---|---|
| `OK` | 日线、实时价、基准指数全部真实且不陈旧 | 可以展示研究性组合方案 |
| `DEGRADED` | 非关键字段缺失（如无 IOPV、板块快照） | 可以展示，但必须同时展示限制说明 |
| `ABSTAIN` | 关键数据缺失 / 陈旧 / 冲突 | **只输出「无法判断」与缺失原因，禁止给买卖动作** |
| `DEMO` | 使用了离线合成快照 | 仅演示；禁止任何「可执行」表述 |
| `ERROR` | 运行或校验失败 | 保留上一份成功产物，不要伪装成今日结果 |

> `ABSTAIN` ≠ `HOLD`。数据不足所以无法判断，不能被翻译成「继续持有」。

时间口径必须分开写，不能只写运行时间：

- 行情最后交易日：`meta.data_date`
- 基准指数最后交易日：`meta.benchmark_date`
- 报告生成时间：`meta.as_of`（北京时间）

## 三、定时任务（自动化）

`.github/workflows/daily.yml`：

| 项 | 值 |
|---|---|
| 触发 | 每个交易日北京 06:50（UTC 22:50 前一天，`cron: '50 22 * * 0-4'`） |
| 手动 | GitHub Actions → Run workflow（可勾选 strict） |
| 流程 | 安装依赖 → `pytest` → `run_update.py`（失败重试 3 次）→ 原子提交产物 → 部署 Pages |
| 产物 | `web/index.html`、`web/analysis_packet.json`、`data/last_run.json` |

本地/家用 IP 跑的写法（云机房 IP 常被免费行情源限流）：

```bash
python3.11 scripts/run_update.py --push      # 取数 + 生成 + 提交 + 推送一次完成
```

盘中手动运行的要求：

- 日频信号只使用**最近一根已收盘 K 线**（`fetch_bars` 已剔除当日未收盘 K 线）；
- 实时价只能用于标注的估值，不得与旧均线混算成「新信号」；
- 同一天重复运行相同输入，必须得到相同动作（`run_id` 含输入哈希，可核对）；
- 数据时间倒退时不要发布。

## 四、低端 Agent 的硬性边界（防跑偏）

> **适用范围**：本节约束的是**公开市场摘要**（工作流 A）。
> 本机持仓的深度解读属于另一套工作流，见 [`持仓分析每日运行指导.md`](持仓分析每日运行指导.md)；
> 持仓解读允许用自然语言解释规则动作与候选状态，但同样不得修改任何交易字段。

Agent 只允许做这三件事：调用上面的命令、读产物、按模板写摘要。

**禁止**：

1. 自己推断买卖、自己给目标价、自己给胜率；
2. 修改 `web/index.html`（它由 `src/etfquant/webgen.py` 生成）；
3. 修改 `config/*.yaml` 的阈值来「让结果好看」；
4. 把 `ABSTAIN` 或 `DEMO` 的结果描述成可执行建议；
5. 引用 `docs/回测报告.md` 里已撤回的旧收益/胜率数字；
6. 在报告里写「主力出货 / 诱多 / 必到目标价 / 保证止损」这类不可观测或过度确定的表述。

公开市场摘要只允许输出这个结构（不得包含交易字段）：

```json
{
  "summary": "基于数据包的简短总结",
  "leg_notes": [
    {"code": "必须来自数据包", "fact_ids": ["必须存在"], "summary": "不得引入新数字",
     "caveats": ["限制与反证"]}
  ],
  "unknowns": ["无法判断的事项"]
}
```

该 JSON 摘要禁止出现：`action`、`entry/stop/take_profit`、`target_shares/quantity`、新证券代码、
新价格/日期/收益/胜率、没有输入来源的新闻事实。

注意：这条限制只针对「公开发布的市场摘要」。如果本次任务包含**本机持仓解读**，应按持仓指导书的规则允许解释 `action`、`candidate_state`、`orders` 与执行约束，但必须在开头标明含本机持仓内容、不与公开摘要混发、且不得改动字段值。

摘要校验失败的处理：

- 第一次失败：用**相同输入**重试一次，不允许让 Agent「修补数字」；
- 第二次失败：删除摘要，保留确定性模板结论；
- 不得因文字失败而重新计算或改变交易动作。

## 五、每日复核清单（人工，5 分钟）

1. `status` 是否为 `OK`；不是则读 `data_quality.blockers`；
2. `meta.data_date` 是否为上一个交易日；
3. `legs[*].data_status` 是否有 `ABSTAIN`；
4. `decisions[*].action` 是否有 `CLEAR`，其 `target_shares` 是否为 `0`；
5. `portfolio_after` 的 `position_pct + cash_pct` 是否约等于 100；
6. `validation.ok` 是否为 `true`；
7. 页面上是否只有一份动作（不存在网页与报告两套结论）。

## 六、持仓分析（需要口令时）

```bash
POSITIONS_PASSPHRASE='口令' python3 scripts/analyze_positions.py \
  --out /tmp/持仓分析报告.md \
  --packet /tmp/positions_packet.json
```

- 有任一持仓缺有效价格 → 组合快照 `complete=false` → 只展示单腿信息，不给总仓位与调仓建议；
- 每笔建议都带：当前份额 → 目标份额、预计费用、执行后仓位 / 现金 / 集中度、约束校验结果；
- 执行后约束不通过 → 退出码 3，且**不发布**目标份额。

口令、Token、券商信息一律只从环境变量读取，不写入仓库、报告、提示词或日志。

## 七、常见故障与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `status=ABSTAIN`，`blocking` 含「距…已 N 个自然日」 | 行情未更新 / 停牌 / 网络失败 | 先修数据源，不要手改数据 |
| `status=DEMO` | 走了离线快照 | 检查网络/接口限流；DEMO 结果不得实盘参考 |
| `status=ERROR`，`constraint_violations` 非空 | 执行后现金/集中度/腿数越界 | 缩小加仓步长或提高现金下限，不要绕过校验 |
| `run_update.py --verify` 返回 4 | 数据包不满足发布不变量 | 看 `errors` 字段逐条修，不要跳过 |
| 页面与报告动作不一致 | 有人手改了 `web/index.html` | 重新生成；网页只渲染数据包 |
| 免费行情源限流（东财 push2） | 触发封禁 | 立即放弃、不重试；自动退到腾讯/新浪 |

## 八、变更纪律

1. 一个工单一个变更集：数据修复、信号修改、页面美化不要混在一次提交；
2. P0 缺陷先写失败测试，再改实现；
3. 改模型前先修正确性，修完先跑旧规则建立新基线；
4. 每次实验冻结输入（`input_hash`）与配置（`config_hash`），保存全部结果而不只是最优结果；
5. 旧产物只读归档（`data/runs/`），新任务失败不得覆盖上一份成功结果。
