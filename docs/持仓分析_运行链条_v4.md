# 持仓分析运行链条 v4（设计稿）

> 目标：解决「上面一套规则、下面一套技术、结论互相打架」。
> 办法只有一条：**层与层之间只传递结论，不传递第二套判断**；
> 每一层只能收紧上一层给的额度，不能自行放大。

## 0. 四份输入

| 输入 | 来源 | 用途 |
|---|---|---|
| 行情 | 日线（1200 根）+ 实时价 | 月/周/日结构、概率、执行位 |
| 规则卡 | `config/methodology.yaml` | 唯一动作谓词（R-D1/D2/D4/C2 等） |
| 组合契约 | `config/risk.yaml` | 仓位区间、单只/类别/腿数/现金约束 |
| 背景 | 国家队宽基份额、舆情环境 | 只调「额度倾向」，不产生买卖 |

## 1. 链条（固定顺序，禁止跳层）

```
L0 数据闸门
   → L1 环境层：市场状态 + 总量仓位上限
   → L2 结构层：月线定方向、周线定节奏、日线定点位（逐标的）
   → L3 组合层：评分档 × 波动 → 单只目标权重
   → L4 执行层：目标 − 当前 = 差额 → 条件确认 → 约束复核
   → L5 解释层：一句话结论 → 3 条理由 → 怎么做 → 什么条件改判
```

### L0 数据闸门
- 价格缺失 → 该腿 ABSTAIN，不参与目标权重
- 技术面不足（<70 根）→ 不给动作，只给持仓事实
- 分类缺失 → 组合结构提示，不阻断单腿

### L1 环境层（决定总仓位，不决定个股）
- 市场状态：基准收盘 vs MA20/MA60、MA5/MA20 排列、20 日波动是否抬升
- 总仓位上限 = `regime_fit` 区间中枢：上行 85 / 震荡 65 / 下行 35 / 下行+波动 25
- 舆情、国家队只做 ±5pct 的倾向修正，且**不得突破区间上下沿**
- 输出：`cap_total`、`env_note`（一句定性）

### L2 结构层（逐标的，三层嵌套）
| 周期 | 看什么 | 输出 |
|---|---|---|
| 月线 | 收盘 vs 20 月线、月 MACD 背离 | 牛 / 熊 / 转换 |
| 周线 | 5/10/20/30 周排列、MACD | 向上 / 走平 / 向下 |
| 日线 | MA5/10/20/30/60、量能、假突破 | 强 / 弱 / 转折 |

- 评分卡（0–100，可明确归零）：
  - 月线底背离 35（双背离 35 / 单 25 / 未确认 15 / 无 5 / 顶背离 0）
  - 站上 20 月线 25
  - 周线多头 25（多头 25 / 金叉 18 / 粘合 10 / 空头 4 / 死叉 0）
  - 日线确认 15（站上 MA10 + 量能不背离 + 相对强度）
- 估值、宏观景气、资金三日流入未接入时，权重要在页面标注「缺失，按可得项归一」
- 评分档 → 单只上限：S≥85→25%、A 75–84→20%、B 60–74→12%、C 50–59→8%、D<50→5%（观察仓，不清零）
- 目标合计低于 `cap_total` 时，差额留在现金；不用「把额度用满」倒推动作

### L3 组合层（目标权重，不是动作）
```
单只目标 = min(评分档上限, cap_total × 评分系数 × 波动系数 / 归一)
```
- 评分系数 = 0.6 + 0.4 × 评分/100
- 波动系数 = min(1, 15% / 20 日年化波动)
- 单只上限再受 `max_single_weight_pct` 约束
- 输出：`target_w` 合计不超过 `cap_total`

### L4 执行层（差额 + 确认 + 约束）
- `gap = target_w − current_w`；`|gap| < 3pct` → 不动
- 加仓：周线不得向下，且「站上 MA10 / MACD 多头 / 连续 2 日资金流入」满足 ≥2
- 减仓：跌破 MA10 回到目标；跌破 MA20 两日卖差额一半；跌破 MA30 两日卖全部差额；跌破 MA60 或硬止损立即执行
- 约束复核：单只 ≤25%、类别 ≤60%、现金 ≥5%、腿数 ≤8；不通过 → 不发布
- 规则卡（R-D1/D2…）只作为**减仓触发的最早时点**，不覆盖目标仓位算法

### L5 解释层（每只持仓固定四段）
1. 一句话：今天做什么（与 L4 的 gap 一致）
2. 三条理由：环境 / 结构 / 相对强弱，各一条
3. 怎么做：目标、差额、触发确认、执行价口径
4. 什么条件改判：失效线、回补条件、下次复核时点

## 2. 页面分工

**持仓概况（一览，不看技术细节）**
- 4 个数字：总资产、持仓市值、浮动盈亏、当日盈亏
- 1 个仓位条：当前 vs `cap_total`
- 1 句话：今天整体做什么（补 / 减 / 不动）
- 1 张 5 列表：代码、当前权重、目标权重、差额、动作（一句话）
- 3 条风险：最集中的板块、最弱的一腿、现金是否够

**持仓分析（深入，逐层展开）**
- 第 1 层 环境：状态、上限、舆情/国家队背景
- 第 2 层 组合：结构、集中度、类别、现金
- 第 3 层 板块：行业评分（技术/资金/政策/情绪）+ 宏观
- 第 4 层 个股：月/周/日状态 → 评分与档位 → 缠论（笔、中枢、背驰、买卖点）→ 执行位 → 5/20/60 日概率（含样本量）
- 第 5 层 改判：每腿的失效与回补条件

**市场洞察及方向（不变）**

## 2.5 主干道与冲突裁决

五层只是分工，**裁决只走一条主干道**：

```
L1 环境 → 定总仓位上限
L2 结构 → 定单只档位上限
L3 组合 → 定目标权重
L4 执行 → 定差额方向与时点
L5 解释 → 只解释，不改结论
```

后一层只能收紧前一层，不能推翻。跨层分歧按下表裁决，且必须在页面写出「冲突 + 裁决」：

| 冲突 | 裁决 | 理由 |
|---|---|---|
| 日线强 vs 周线空头 | 方向以周线为准，日线只定执行节奏 | 周线是方向，日线是点位 |
| 月线转换 vs 周线空头 | 按周线处理，不提前加仓 | 转换不等于确认 |
| 差额为正 vs 周线向下 | 不买，动作降级为等待 | 额度不允许逆势加仓 |
| 评分档上限 vs 环境额度 | 取小 | 额度由环境给，结构只能收 |
| 缠论买点 vs 差额为负 | 不做多，缠论只用于卖出时点 | 买点不改变目标权重 |
| 概率偏低 vs 评分较高 | 概率只做参考，不改档位 | 概率是解释项，不是决策项 |
| 舆情/国家队 vs 仓位区间 | 只做 ±5pct 倾向，不得破上下限 | 背景不改规则 |

每层解读必须是「数据 + 判断 + 反证/改判」三件套，由当次数据生成，禁止固定模板。

## 3. 一致性规则（验收项）

1. 概况里的动作必须等于 `gap` 判定的结果，不得另写
2. 个股页展示的技术信号只能解释动作，不能出现与动作相反的买卖建议
3. 任何「加仓」必须同时满足 L1 额度与 L4 确认；额度不足时显示「环境不允许」，不是「技术看多」
4. 概率必须附样本量与窗口；样本 <30 显示「样本不足」
5. 每个数字标注来源与数据日；缺数据明说缺，不补脑
