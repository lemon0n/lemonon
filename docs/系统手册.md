# 系统手册：架构、分析口径、每日刷新 SOP

> 这份文档是给「下次直接开工」用的：先按第 7 章的 SOP 跑，出问题按第 8 章对账、第 9 章排查。
> 所有阈值都以仓库里的 `config/*.yaml` 与代码为准；本文只是把散落的口径集中写清楚，不引入新规则。

---

## 1. 这套系统是什么

个人自用的**中国 ETF 研究台**：

- **不做**自动交易，不接券商；只产出「目标权重 → 订单草案」。
- 模型只做**研究与解释**；能不能落地由**确定性风控**判定，风控不通过就退回。
- GitHub 只当托管 + Pages；数据由本机刷新后推上去。
- 默认 `research.scope = holdings`：**只研究自己持有的标的**，不生成新方向候选。

产出三样东西：

| 产物 | 路径 | 用途 |
|---|---|---|
| 网页 | `web/index.html` | 手机/桌面看：市场概况 / 持仓分析 / 持仓设置 |
| 每日报告 | `data/runs/<日期>/<run>/report.md` | 今天该不该动、风控改了什么 |
| 持仓深度报告 | `docs/持仓分析报告.md` | 逐只：角色/因果链/证据/反证/失效条件 |

## 2. 架构总览

```
┌──────────────────────────── 数据层 ────────────────────────────┐
│ scripts/fetch.py → src/etfquant/datasource/fetch/{market,news,national,sector}.py │
│   market   : 全市场广度/涨跌分布/外盘/ETF 折溢价（东财→新浪双源） │
│   national : 宽基 ETF 份额（国家队背景，只在 p1 展示）            │

                                │  loader / features / indicators

│ webgen.py      单文件 HTML（内联 CSS/JS + 数据 JSON）              │
│ web_assets/app.js    全部渲染逻辑（市场/组合/个股/缠论/图表）      │
│ web_assets/style.css 版式与响应式                                 │
```

## 3. 数据层

### 3.1 数据源（每次运行重建，没有离线兜底）

| 任务 | 命令 | 产物 | 失败时 |
|---|---|---|---|
| market | `python scripts/fetch.py --market` | `data/live/market.json` | 全部重建、字段写 `null`，不读旧文件 |
| news | `python scripts/fetch.py --news` | `data/live/news.json` | `items=[]` + 原因，页面显示「快讯抓取失败」 |
| national | `python scripts/fetch.py --national` | `data/national_team.json` | 份额序列来自官方披露，仅作背景 |
| sector | `python scripts/fetch.py --sector [--dry-run]` | `data/live/index_sector_weights.json` | 失败指数**不沿用旧权重**，页面显示「未覆盖」 |

**每条数据链都有主通道 + 副通道，并区分「分析输入」与「背景展示」**（2026-11 起，离线快照全部删除）：

| 数据链 | 用途/节奏 | 主通道 | 副通道 | 失败语义 |
|---|---|---|---|---|
| ETF 日线 | 分析输入·按行情日收盘 | 东财（akshare） | 腾讯 → 新浪 | 三通道都失败 → 该腿缺席并降级 |
| 指数日线 | 分析输入·按行情日收盘 | 腾讯 | 新浪 → 新浪备用域名 | 全失败 → 市场状态 ABSTAIN |
| ETF 实时价 | 分析输入·最新价单独标注 | 东财（akshare） | 腾讯 → 新浪 | 全失败 → 现价空，折溢价不可用 |
| 指数点位 | 背景展示·可盘中刷新 | 新浪 | 腾讯 | 全失败 → 点位空，不显示旧值 |
| 板块资金流 | 背景展示·可盘中刷新 | 东财 | 腾讯（31 个申万一级） | 全失败 → 板块块显示抓取失败 |
| 市场广度 | 背景展示·可盘中刷新 | 东财（分页） | 新浪（分页） | 全失败 → 广度 null |
| 财经快讯 | 背景展示·可盘中刷新 | 东财 | 新浪 → 同花顺 | 全失败 → 快讯空 + 原因；只有数据日当天快讯进研究证据 |
| 行业权重 | 分析输入·只接受当天抓取 | 东财/国证官方 | 自由流通市值近似（腾讯行情 + 东财行业） | 失败 → 该指数不映射 |
| 宽基份额 | 背景展示·周频披露 | 上交所 curl | 上交所 requests（同源不同传输） | 全失败 → 保留本地历史序列（仅背景） |
| 外盘指数 | 背景展示·可盘中刷新 | 新浪 | 腾讯 | 全失败 → 外盘块空 |
| ETF 折溢价 | 背景展示·可盘中刷新 | 东财 IOPV | 新浪估值（`fu_` 估算净值） | 全失败 → 明确「折溢价不可用」 |

体检命令：`python scripts/check_feeds.py`（结果落 `data/live/feeds_health.json`，
`daily.sh` 每次抓数后自动跑）。状态含义：

- `OK`：主通道与副通道都通；
- `PARTIAL`：主通道可用但部分副通道/官方源不可用；
- `FALLBACK`：主通道不可用，当前靠副通道取数（页面仍有数据，但要知道主通道挂了）；
- `FAIL`：所有通道都拿不到，该链无数据。

**刷新节奏**：分析输入按行情日（收盘）口径；背景数据可以盘中刷新，但页面必须在顶部标明
「分析基准：X 收盘」与「背景数据抓取于 Y（阶段）」，且研究/点评不得引用非基准日的背景数据。
页面「数据来源与通道」面板列出 11 条链的状态、当前通道与主/副通道。

`data/live/market.json` 与 `news.json` 带 `fetched_at`；loader 拒绝超过 30 分钟的旧文件。`webgen` 只接受**今天抓取**的行业权重。`data/live/` 已 gitignore：仓库里不允许出现任何行情快照。

### 3.2 数据日与降级语义（重要）

- `meta.data_date`：**行情数据日**（基准指数最后一根 K 线），页面所有价格/均线/涨跌都以此为准。
- `market.fetched_at`：市场数据的抓取时间；`market.phase`：盘前/集合竞价/盘中/盘后/休市。
- 页面顶部显示「市场数据抓取于 X（阶段）；快讯抓取于 Y（来源）」；某通道失败就显示「抓取失败」，不显示旧值。
- 运行状态 `status`：`OK` / `DEGRADED` / `ABSTAIN` / `LLM_FAILED` / `REJECTED`，写在 `data/last_run.json`。
- **不允许**用过期/降级数据生成可执行订单（`risk_policy.quality.allow_stale_for_execution=false`）。
- **来源 live ≠ 当日数据**：每条日线/报价都记录真实日期，与运行日按保守预期交易日比对；早于预期日即 `STALE`，页面标「非实时」，`degraded=true`、`source.live=false`，研究风控拒绝可执行动作。
- `expected_session`：工作日 15:15 后算当日，之前/周末算上一交易日（不依赖另一个可能过期的节假日表）。
- 快讯只来自本次实时抓取（`data/live/news.json`），旧快讯不会进入当日证据；行业权重按逐指数 `weights_date/stale/errors` 披露，失败指数不映射。
- 板块主线/落后由实时板块涨跌幅排序，不再人工维护。
- `--finish` 只收尾最新 `.pending_run`；brief 与研究载荷必须绑定当前 `run_id`。

## 4. 研究决策层

### 4.1 五层决策链（只有一个出口）

```
L0 数据闸门  行情/持有/行业权重/舆情是否可用 → 不可用只写事实
L1 环境层    大盘状态 → 总仓位上限（85 / 65 / 35，波动抬升再 −10）
L2 板块层    板块四维评分 → 评级 → 板块上限、覆盖度
L3 个股层    三周期 + 双评分卡 + 结构 → 单只上限（25/20/10/5/0）
L4 组合层    目标权重 = min(总上限分摊, 单只上限, 板块上限) → 差额 → 动作 → 订单
L5 解释层    点评、逐只解读、情景（只能引用 L1–L4，不得改数字）
```

四条铁律：额度只能收紧；下层不许翻案；解释层不许自创；**动作必须等于目标权重表**。

### 4.2 契约与证据

- 权重一律为「占含现金总资产」的比例（0–1），`sum(target_weight) + cash_target_weight = 1`。
- 方向与权重必须一致：BUY/ADD 抬权重、SELL/REDUCE 降、EXIT 归零、HOLD 不动。
- 每条研究结论必须引用 `context.evidence_catalog` 里的 `evidence_id`（含 snapshot sha256），一条都不引 = 失败；
  例外：没有任何可交易标的（未加载持仓）时允许零引用，计划为「空仓 + 现金 100%」，
  成交后的状态是 `APPROVED`（`trades=[]`、`orders=[]`），不是失败。
- 金额/份额不进入页面载荷：`publish.page_payload` 只放百分比，`no_absolute_fields()` 有测试兜底。

### 4.3 风控硬约束（risk_policy.yaml）

| 约束 | 值 | 违规码 |
|---|---|---|
| 总风险资产 | ≤ 95% | `GROSS_EXPOSURE` |
| 现金下限 | ≥ 5% | `CASH_FLOOR` |
| 单只 | ≤ 25% | `SINGLE_WEIGHT` |
| 单一类别 | ≤ 60% | `CATEGORY_WEIGHT` |
| 腿数 | ≤ 8 | `MAX_LEGS` |
| 单日换手 | ≤ 30%（单边/2） | `TURNOVER` |
| 最小交易金额 | ≥ ¥200（7k 级账户校准） | `TRADE_BELOW_BAND` |
| 不换仓带 | 目标与现仓差 < 1pp 不动 | `TRADE_BELOW_BAND` |
| 权重和 | = 100% | `WEIGHT_SUM` |
| 标的是否持有 | 必须在持仓里 | `UNKNOWN_SYMBOL` / `MISSING_HELD` |
| 执行规则 | 无盘口必须给条件式执行规则 | `MISSING_EXECUTION_RULE` |
| 数据可用性 | 过期/降级不出可执行订单 | `DATA_NOT_EXECUTABLE` |

退回后：写 `<run_dir>/agent_repair.json`（RevisedProposal）再 `--finish`；不允许放宽阈值来通过。

### 4.4 订单草案规则

- 目标份额 = `floor(总资产 × 目标权重 ÷ 价格 ÷ 100) × 100`；买入现金不足按可用现金下调。
- 费用（服务端）= `max(成交额 × 0.5bp, ¥5)`；页面估算在此基础上**多计 1bp 滑点**，两者口径在页面上分别标注。
- 挂单价（页面估算）：买入 `现价 × 1.0001` 进位、卖出 `现价 × 0.9999` 截断，到 0.001；不保证成交。
- 单笔不超过近 20 日成交额的 5%；`allow_market_orders=false`。

### 4.5 运行产物（`data/runs/<日期>/<run>/`）

```
context.json         冻结事实（模型看到的全部输入）
AGENT_TASK.md        本次要写的字段清单（由 pydantic 自动生成）
agent_output.json    agent 模式：你写的四段 JSON（research/proposal/redteam/revision + 可选 brief）
01_research.json 02_proposal.json 03_redteam.json 04_revised.json 05_risk.json 06_final_plan.json 07_memory.json
report.md            每日报告
page_data.json       页面数据（prepare 时生成）
```

## 5. 页面结构与每块口径

### 5.1 三个标签

| 标签 | 内容 |
|---|---|
| **市场概况** p1 | 指数/广度/情绪/板块/资金/估值/隔夜/消息；国家队只在这里作背景 |
| **持仓分析** p5 | 下面三段 |
| **持仓设置** p7 | 编辑持仓与现金、加密保存到云端（`web/positions.enc.json`） |

### 5.2 一、持仓概况

1. **四个数字**：总资产（其中现金）、持仓市值（几只）、浮动盈亏（% + 金额，分母=持仓成本）、当日盈亏（% + 金额，分母=昨日持仓市值）。
2. **今日点评**：八块（今天是什么日子 / 我们现在站在哪 / 组合的真实问题 / 哪只该动为什么是它 / 如果我错了 / 今天做什么 / 什么情况下改主意 / 没解决的事）。来源 `agent_output.brief` → `data/brief.json`；校验：日期一致、≥6 块、无禁词（`config/brief_banned.txt`）。
3. **持仓明细表**（12 列）：名称（代码）、板块、仓位现→目标、数量现→建议、本次操作（分批带首批）、挂单价、费用、成本→现价、盈亏、5/20 日上涨（近 N 日上涨天数占比）、全市场位置（5 日超额）、动作。
   - 每行下面一行小字：研究给的 **理由 / 触发 / 失效 / 执行**。
   - 排序：按本次操作金额降序；HOLD 行给「（目标 X 份）」便于核对是否不足一手。

### 5.3 二、持仓分析

**1. 市场环境**

| 子块 | 口径 |
|---|---|
| 1.1 大盘位置 | 指数点位 / 均线排列（5/10/20/30/60/120）/ 五均线开关（连几日站上 MA5）/ 量能（成交额+环比）/ 缺口（近 20 日未回补跳空）/ 空间（距 120 日高低、赔率）/ 波动（20、60 日年化） |
| 状态判据 | 收盘 > MA60 且 MA5 > MA20 → 上行 85%；收盘 < MA60 且 MA5 < MA20 → 下行 35%；其余 震荡 65%；`vol20 > vol60×1.25` → 追加「波动抬升」，再降 10 |
| 1.3 热度与情绪 | 涨跌家数/上涨占比（>55% 赚钱面广，<45% 偏窄）、涨停跌停与连板、成交额环比、恐慌形态（只有放量急杀才算）、连续普跌天数、情绪温度 0–100（情绪 40% + 涨跌家数 35% + 成交额 15% + 趋势 10%） |
| 1.4 资金动向 | 两融余额、北向成交、新成立基金、ETF 份额周变化、逆回购、DR007；北向净流入 2024-08 起不披露；板块成交占比前 5，>15% 记过热 |
| 估值分位 | 沪深300 / 创业板指 / 中证500 / 科创50 的 PE 与近 5 年分位 |

**2. 组合情况**

- 2.1 组合板块结构：ETF 权重 × 指数行业权重聚合；单板块 ≥25% 超配、≤5% 低配。
- 2.2 集中度：最大板块、前三合计、持有/有效只数（1/HHI，按持仓内部相对权重）、现金比例、TMT 合并（电子+计算机+通信）。
- 2.3 板块健康度：见 6.2。
- 纪律闸门（5 项，实时判）：总仓位 ≤95%、现金 ≥5%、单一类别 ≤60%、单只 ≤25%、腿数 ≤8。

**3. 个股分析（单卡三选项卡）**

| 选项卡 | 内容 |
|---|---|
| 概览 | 进场检查三步 + 执行与改判 |
| 结构与图 | K 线主图（铺满）+ 三周期表 + 缠论结构（两列键值） |
| 评分与概率 | 底部评分 / 顶部风险（两栏等高）+ 概率 |

### 5.4 三、市场洞察及方向

1. 今日定性（时段感知：盘前/盘中/盘后）；
2. 位置与赔率（距高/距低/上下空间/赔率；赔率 >10 标注「贴近前低，失真」）；
3. 情绪与主线（情绪温度条 + 领涨/落后板块）；
4. 情景与触发（4 列表格：情景 / 触发 / 当前距离 / 对应动作）；
5. 复盘对照（上次计划 vs 今天）；
6. 新方向候选（`scope=holdings` 时不生成，页面明说）。

## 6. 分析细节规格

### 6.1 三周期与均线

| 周期 | 看什么 | 结论口径 |
|---|---|---|
| 月线 | 收盘 vs 20 月线 | 上方「可重仓区」，下方「上涨当反弹」 |
| 周线 | MA5/10/20/30 | 全部多头排列=多头；金叉初期；粘合；空头 |
| 日线 | MA5/10/20/60/120 + 量比 | 量比 ≥1 放量；均线状态字符串 |

规则：**日线服从周线**。周线向上，日线回踩是买点；周线向下，日线反弹是卖点。

### 6.2 板块四维评分

```
评分 = 技术 40 + 资金 25 + 政策 20 + 情绪 15   （缺项按剩余权重折算，缺失不补 0）
技术：该板块持仓 ETF 的周线排列（基准 50）：MA5>MA10 +12、MA10>MA20 +12、收盘>MA20 +12、MA20>MA60 +14
资金：50 + (板块成交占比 ÷ 31 行业均值 − 1) × 20，clamp 0–100
政策：政策热度同名/同义主题匹配（电子↔半导体/光模块、计算机↔算力/AI…），匹配不到记缺失
情绪：50 + 当日涨跌幅 × 8
```

评级：S≥85、A≥75、B≥60、C≥50、D；板块上限：**S25 / A20 / B10 / C5 / D0**（D 只限制新增，不强制清仓）。
缺项会写明缺哪几项（例：`缺技术`、`缺政策`），不写「缺 N 项」这种模糊话。

### 6.3 双评分卡

**底部评分**（权重合计 60，缺项折算）：

- 月线底背离 25：创 13 月新低且 DIF 抬高 → 25，否则 15；未创新低但 DIF<0 → 8。
- 月线倍量站上 20 月线 20：站上且量为 5 月均量 1.5 倍 → 20，站上 → 10。
- 周线多头排列 15：MA5>10>20>30 → 15；MA5>MA10 且价>MA30 → 10；MA5/MA20 差 <2% → 5。

= 0–100；≥85 S、≥75 A、≥60 B、≥50 C，否则 D；单只上限 25/20/10/5/3。

**顶部风险**（权重合计 75）：

- 月线顶背离 30；跌破 10 月线 20；周线死叉 15；情绪过热 10（板块成交占比 ≥15% 记 10、≥10% 记 5）。
- 总分 ≥80 → 单只上限归 0；≥60 → 压到 5%；≥40 → 上限减半。

### 6.4 缠论（简化实现，页面如实标注）

| 构件 | 规则 |
|---|---|
| 分型 | 左右各 2 根 K 线确认的顶/底 |
| 笔 | 顶底交替；间隔 ≥4 根；幅度 ≥1.5% |
| 中枢 | 最近 4 笔取 3 段重叠：ZG = min(各段高)、ZD = max(各段低) |
| 中枢类型 | 与上一个中枢比：中心抬高=上涨中枢、降低=下跌中枢；宽度扩张=扩张、收窄=奔走 |
| 背驰（结构） | 最后两个同向笔：价格新极值但 DIF 反向 → 底/顶背驰 |
| 面积背驰 | 最后两段同向笔的 MACD 柱面积缩小到 <80% 且价格创新极值 |
| 三类买卖点 | 一买=下跌背驰后新低；二买=回踩不破 ZD；三买=站上 ZG 后回踩不破；三卖=跌破 ZD 未收回 |
| 图上标识 | 灰折线=笔、虚线框=中枢（标 ZG/ZD）、▲/▼=买卖点、三角+文字=背驰、MA5/10/20 三色线 |
| 图下说明 | 自动写「笔 N 段 / 中枢 ZG…ZD（未形成也写）/ 买卖点（无也写）/ 量价 / 形态」，并注明与上方表格同源 |

**不做**：线段、多级别递归。缠论只解释位置与节奏，**不改目标与订单**。

### 6.5 量价 / K 线形态 / 多维共振

- 量价状态：放量滞涨（量比≥1.3 且 3 日涨幅≤0.5%）、放量下跌、缩量回踩（量比≤0.8、3 日跌幅<3%、价在 MA20 上）、量价背离（**今日自己创 20 日新高**且量 <前次高点日 80%）、缩量下行。
- K 线形态：早晨之星 / 黄昏之星 / 看涨吞没 / 看跌吞没 / 锤子线 / 射击之星 / 十字星（最近三根）。
- 多维共振：结构 / 量价 / 形态 / 趋势 四维投票 → 四维偏多 / 四维偏空 / 多维冲突 / 中性。

### 6.6 进场检查（选股三步）

1. 底部震荡：近 20 日未创新低；
2. 放量突破：均线多头（5>10>20）+ 实体阳线无长上影 + 站上 120 日线；
3. 回踩确认：回踩不破关键位 + 缩量。

三条缺一条写「突破不成立」；突破当天只标关注，回踩才是确认。

### 6.7 执行位与改判

- 止损：交易仓（C/B）破 10 日线 2 日出局；核心仓（A/S）破 20 日线 2 日减半、破 30 日线 2 日清差额、破 60 日线立即。
- 改判：站上 20 日线且周线转多 → 评级重估；连续两日跌破 30 日线 → 卖出剩余差额。
- 显式给出「触发条件 / 执行条件」（来自研究层 trade），不再用本地「需 ≥2 条确认」那套。

### 6.8 概率（历史相似条件）

用近 20 日动量 + 波动做特征，在历史窗口里找相似条件，统计 5/20/60 日上涨占比与中位涨幅。
样本 <30 不显示；**只作参考，不改评级、不改动作**。

### 6.9 估值分位

只有能映射到宽基指数的标的才显示（科创50 / 创业板指 / 沪深300 / 中证500）；行业 ETF 明确写「未覆盖」，不硬套。

## 8. 数字对账口径（排查「图与表打架」）

1. **总资产** = Σ(份额 × 最新价) + 现金；**浮动盈亏%** 分母是持仓成本；**当日盈亏%** 分母是昨日持仓市值。
2. **权重** = 个股市值 ÷ 总资产；持仓权重合计 = 持仓市值 ÷ 总资产（不等于 100%，差额是现金）。
3. **目标权重**来自研究层 `proposal.trades[].target_weight`（百分比），页面不再本地补算；目标合计 + 现金目标 = 100%。
4. **份额** = floor(总资产 × 目标权重 ÷ 价格 ÷ 100) × 100；差 <1pp 视为不动。
5. **挂单价**：买 ×1.0001 进位、卖 ×0.9999 截断到 0.001；点评里的价格必须与表格一致。
6. **费用**：页面 = max(5, 成交额×0.5bp) + 成交额×1bp；服务端 = max(成交额×0.5bp, 5)。
7. **K 线与现价同源**：demo/页面使用的日线必须截断到 `data_date`，否则图是今天、表是昨天。
8. **新鲜度**：`quote_date < expected_session` 即过期；live 来源也不能豁免，证据 ID 使用资产自己的行情日期。

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 广度数据不是今天 | 东财 push2 被限流/不可达 | 自动切新浪（盘中有效）；两源都失败则广度 null，不显示旧值。先跑 `check_feeds.py` 看通道状态 |
| 某条链一直显示「抓取失败」 | 所有通道都不可达 | 先跑 `python scripts/check_feeds.py` 定位是哪条链/哪个通道；`data/live/feeds_health.json` 有逐通道耗时与原因 |
| 月线/20 月线显示「数据不足」 | 新 ETF 历史太短（如 158041 仅 40+ 交易日） | 正常，不做假数据 |
| 图上没有中枢/买卖点 | 结构确实没形成（三笔无重叠） | 正常；图下说明会写「中枢（当前未形成）/ 卖点（当前无）」 |
| 页面图表空白 | 切到「结构与图」后才会绘制；若是 JS 报错 | 用 Chrome dump-dom + `window.onerror` 探针查；历史上出现过 `nm is not defined` |

| 口令没生效 | 未设 `POSITIONS_PASSPHRASE` 或 `positions/.passphrase` | 只跑市场层，不生成持仓报告 |
| 风控退回 | 见 `05_risk.json` 的 violations | 改建议，别改阈值 |

## 10. 已知限制（写清楚，免得误判）

1. 板块评分的「技术」用的是**持仓 ETF 周线代理**，不是行业指数；「政策/情绪」依赖 `policy_heat` 与当日涨跌，匹配不到就记缺失。
2. 缠论是**简化实现**：分型→笔→中枢→背驰→三类买卖点，不含线段与多级别递归，也未做 A/B 回测验证，因此只解释不改目标。
3. 概率是**历史相似条件统计**，不是胜率；样本 <30 不显示。
4. 估值只有宽基指数；行业 ETF 无估值口径。
5. 国家队份额只在「市场概况」作背景，不参与定仓。
6. 广度/新闻/板块等每条链都配了主副通道，但都是公开免费源：被限流时靠副通道，连续被限流就只能显示「抓取失败」（不会显示旧值）。
7. `research.scope=holdings` 时没有新方向候选、也不配置货币 ETF（现金等待期收益为 0 是已知取舍）。

|---|---|
