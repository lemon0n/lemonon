# 页面实现说明（逐块：内容 + 实现）

> 口径（阈值、判据、验收）以 [系统手册](系统手册.md) 为准；本文只做「每块由哪个函数生成」的开发索引。

> 这份文件替代原来的「页面区块对照」，是**页面唯一的结构说明**：每一块显示什么、数据从哪来、
> 由哪个函数生成、阈值是多少、缺数据时怎么降级。
>
> 每日刷新入口仍只看仓库根目录 `AGENTS.md`；本文只用于开发和排查，不参与每日流程。
> 代码位置：页面逻辑在 `src/etfquant/web_assets/app.js`，数据组装在 `src/etfquant/webgen.py`。

## 0. 一页看懂

### 0.1 四个视图

| 视图 | id | 内容 | 是否需要口令 |
|---|---|---|---|
| 锁屏 | `#lock` | 输入/创建口令、选择加密文件、跳过 | — |
| 市场概况 | `#p1` | 公开行情、板块、宏观、消息 | 否 |
| 持仓分析 | `#p5` | 概况 + 分析 + 洞察 | 是（解密 `web/positions.enc.json`） |
| 持仓设置 | `#p7` | 编辑持仓、现金、云端保存 | 是 |

导航：`nav('p1'|'p5'|'p7')`；未解锁时持仓相关导航隐藏，点「跳过」进公开模式。

### 0.2 数据流

```
scripts/daily.sh
  → src/etfquant/pipeline.run()         取数 → 质量检查 → 指标 → 市场状态 → 目标仓位 → 数据包
  → webgen.build_data()                 组装 window.DASHBOARD（meta / market / legs / plan / packet…）
  → webgen.render()                     内联 CSS+JS+数据，输出单文件 web/index.html
  → 浏览器 render()                     先画 p1，解锁后算 p5，p7 可编辑
```

浏览器侧不重新取历史行情（除池外持仓的日线/周线和「刷新行情」按钮），
它只做三件事：**解密持仓、按现价算盈亏与差额、把同一份目标仓位表渲染成各块**。

### 0.3 三个日期，别混

| 字段 | 含义 | 来源 | 页面位置 |
|---|---|---|---|
| `meta.data_date` | 行情日：最后一根**已收盘**日线 | `pipeline` 汇总各腿 `last_date` | 顶部、个股卡 |
| `meta.market_fetched_at` / `meta.news_fetched_at` | 本次市场与快讯的抓取时间 | `data/live/market.json` / `news.json` 的 `fetched_at` | p1 顶部提示 |
| `meta.as_of` / `run_date` | 本次运行时刻 | 运行当天 | 顶部「最新更新」 |

`snapshot_date ≠ data_date` 时，p1 顶部强制提示，避免把旧情绪/旧快讯当成今天。

### 0.4 状态与来源

| 徽标 | 字段 | 语义 |
|---|---|---|
| 来源 | `meta.source.live` | 实时 / 降级；降级时 title 写哪些通道抓取失败 |
| 状态 | `meta.status` | `OK` / `DEGRADED` / `ABSTAIN` / `DEMO` / `ERROR`；`DEMO` 的 title 明确「仅演示、不输出交易动作」 |

`ABSTAIN` ≠ 持有；`DEMO` 只演示，页面不输出可执行交易动作。

## 2. 锁屏与解密

| 功能 | 实现 |
|---|---|
| 读取密文 | `fetchEnc()` 取 `web/positions.enc.json`，带 `cache:no-store` |
| 解密 | `decBlob()`：PBKDF2-SHA256（210000 次）派生 AES-GCM-256 密钥，全程在浏览器 |
| 解锁 | `unlock(pass)` → `applyHold()` → `closeLock()` → `render()` → `ensureHoldQuotes()` 补价格 |
| 创建 | `initCloud()` 生成空持仓密文，页面给出提交说明 |
| 跳过 | `skipLock()`：进公开模式，只显示 p1 |
| 会话记忆 | 口令只放 `sessionStorage`，关闭标签页即失效 |
| 换口令 | p7「改口令」→ `changePass()` |

仓库里永远只有密文；服务端与构建产物拿不到持仓。

## 3. p1 市场概况

生成函数：`page1()`。区块顺序即下表顺序。

### 3.1 快照日提示

`meta.snapshot_date !== meta.data_date` 时显示：
「市场数据抓取于 X（阶段）；快讯抓取于 Y（来源）」，失败的通道显示「抓取失败」而不是旧值。

### 3.2 市场总览（四卡）

| 卡 | 显示 | 数据 | 实现 |
|---|---|---|---|
| 两市成交额 | 金额 + 环比 | `market.breadth.amount_yi / amount_chg_pct` | `page1()` |
| 市场情绪（快照） | 分 + 标签 | `market.sentiment.score / label` | 同上 |
| 仓位区间 | `fit_lo~fit_hi%` + 状态 + 基准日 | `market.regime` | `market_regime.compute()` |
| 市场状态依据 | 条目数 | `regime.observations.length` | 同上 |

### 3.3 指数与均线状态

`market.indices[]`（6 项）：指数、最新、涨跌、均线状态（站上/缠绕/跌破）。
来源：`loader.indices()`（新浪实时，失败保留快照）。

### 3.4 市场状态与情绪（条目表）

`market.sentiment.items[]`（约 12 条：涨跌家数比、涨停/跌停、连板高度、恐慌判定、连续普跌、情绪节点、首次分歧等）。
来源：`data/live/market.json` + `data/live/news.json`（本次运行实时抓取）。

### 3.5 阶段 → 仓位 → 我的持仓

- `linkStrip()`：一行联动条，显示当前状态、仓位区间、当前仓位（解锁后），并给「持仓分析 →」。
- `planSection(true)`：四卡「目标总仓位 / 当前仓位 / 差额 / 今日结论」。
  差额 < `gap_threshold`（默认 3pct）→ 不动；正 → 分批补；负 → 分级减。

### 3.6 板块概况（可展开）+ 热力图

- 标题：申万一级 31 行业，面积 = 流通市值，颜色 = 涨跌幅。
- 数据：`market.heat[]`（`name / cap / chg / v`）来自 `sector_flow.csv`。
- 实现：`secDetails()` 折叠 + `heatMap()` 的 squarified treemap（`squarify()`，Bruls 1999），
  `heatColor()` 按 ±0.5/1.5/3/5% 分档，A 股红涨绿跌。

### 3.7 国家队动向（最新一期）

只显示截止最新一期，不铺历史行：

| 元素 | 内容 |
|---|---|
| 最新一期 | `series[-1].date` |
| 合计份额 | `全宽基合计`，单位亿份 |
| 较上次 / 近四周 | 对 `series[-2]`、按日期回溯 25 天的基线算涨跌 |
| 六类最新 | 一行文字列出六类份额 |
| 提示 | 单期跳动 >15% 的类别合并成一句「口径跳变，不据此判断增减持」 |

实现：`nationalTeamSection()` / `ntWindow()`；数据 `data/national_team.json`。
只作背景，不参与目标仓位；持仓分析页不重复展示。

### 3.8 行业成交额与占比

表：行业、成交额（亿）、占比、涨跌幅、流通市值。
数据：`market.flow[]`；按成交额降序。

### 3.9 轮动与主线 + 涨跌分布

- 轮动与主线：`regime.regime / leaders / laggards`。
- 涨跌分布：`market.distribution` 六档（`<-3%` 到 `>3%`），条长按家数归一（纯视觉）。

### 3.10 宏观环境（四块）

估值（`valuation.items`）、外围（`glob.items`）、资金面（`liquidity.items`）、宏观数据（`macro.items`）。
`secInfo()` 固定提示：人工维护快照，统计期与采集时间可能缺失，只作背景。

### 3.11 政策与消息面

| 块 | 数据 | 说明 |
|---|---|---|
| 快讯 | `news[]`（时间 + 文本 + 链接） | 链接多为来源入口，未核验原文 |
| 财经日历 | `calendar[]`（日期/事件/级别） | 年份常缺，页面标注 |
| 消息面情绪 | `news_sentiment`：综合分、正面/中性/负面占比、`note` | `note` 来自 `data/news_note.json`，日期必须等于快照日 |
| 政策主题净热度 | `policy_heat[]`（主题/热度/变化） | 只作背景 |

消息解读模板见文末第 10 节。

## 4. p5 持仓分析

入口 `page5()`：`calcPort()` → `s1Position()` → `buildPdec()` → `rsPageHTML()`；
随后 `setTimeout(rsInit,0)` 异步取池外日线，取完 `rsAfterBars()` 刷新各块。

### 4.1 一、持仓概况

#### 4.1.1 四个数字

| 卡 | 算法 | 缺数据 |
|---|---|---|
| 总资产 | Σ 市值 + 现金 | 任一只缺价 → 「—」并写缺哪只 |
| 持仓市值 | Σ 最新价 × 份额 | 同上 |
| 浮动盈亏 | （现价 − 成本）× 份额；% 分母 = Σ 成本×份额 | 缺成本 → 「—」 |
| 当日盈亏 | （现价 − 昨收）× 份额；% 分母 = Σ 昨收×份额 | 缺昨收 → 「—」 |

实现：`calcPort()` + `kpi()`。现金不参与百分比分母。

#### 4.1.2 今日点评（5 段分析）

容器 `#rsBrief`，`rsRenderBrief()`：
优先用 `data/brief.json`（`webgen._brief()` 校验日期、结构、禁词）；不存在或不合格时用 `rsBriefSections()` 现场生成：

| 段 | 写什么 |
|---|---|
| 今日基调 | 时段 + 定性 + 仓位 vs 上限的结论（高出多少 / 还差多少） |
| 大盘与量能 | 状态、收盘、MA5/MA20、成交额环比；再判性质（缩量阴跌 / 放量出货 / 放量待确认） |
| 结构 | 主线与过热、落后、组合最大暴露、最大仓位是否压在最低评级 |
| 今天动什么 | 具体标的、份数、挂单价、首批；没单就说清为什么不动 |
| 什么情况下改判 | 转好（收复 MA20 且 MA5 上穿）与恶化（连续两日破 MA30）两条阈值 |

禁止「综合来看 / 注意风险 / 胜率」等词（`config/brief_banned.txt`）。

#### 4.1.3 持仓明细表（12 列）

容器 `tbody#rsPlanBody`，`rsPlanRows()` → `rsSortPlanRows()` → `rsPlanRowsHTML()`。

| 列 | 算法 | 缺失 |
|---|---|---|
| 名称 / 代码 | 持仓 + 行情名称 | — |
| 板块 | `rsSectorLabel()`：指数权重 → 名称关键词 → 宽基近似 → 未覆盖 | 「未覆盖（数据日 X）」 |
| 仓位（现→目标） | 现值 = 市值/总资产；目标见下 | 无目标 → 「—」 |
| 数量（现→建议） | 目标金额 ÷ 挂单价，向下取整到 100 份 | 只显示现有 |
| 本次操作 | 建议 − 现有；卖出括号内给首批 | 「—」 |
| 挂单价 | 买 ×1.0001 进位、卖 ×0.9999 截断，到 0.001 | 「不挂单（原因）」 |
| 费用 | max(5, 成交额×0.5bp) + 成交额×1bp | 「—」 |
| 成本 → 现价 | 直接取 | 「—」 |
| 盈亏 | （现价−成本）/成本；金额另起一行 | 「—」 |
| 5/20 日上涨占比 | `rsForecast()` 历史相似条件 | 「样本不足」 |
| 全市场位置 | 近 5 日相对基准超额 + 所属板块成交占比 | 「—」 |
| 动作 | `planActionOf()` 的唯一结果 | — |

**目标从哪来（三条，按优先级）**：

1. 观察池内：`D.plan.items[].target_weight`（`plan_v3.build()`）。
2. 观察池外、能取到日线：浏览器按同一公式补算，行内标「池外补算 · X 分 Y 级」。
3. 连 30 根日线都没有：按类别结构目标折算（宽基 50 / 行业 25 / 债券 15 / 黄金 5 / 海外 5，
   乘总上限后同类均分），标「结构参考目标」，动作固定为「日线未到，暂不动」且**不生成订单**。

排序：按 |本次操作金额| 降序，不动的靠后。

### 4.2 二、持仓分析

#### 4.2.1 1. 市场环境

| 小块 | 内容 | 数据 / 实现 |
|---|---|---|
| 大盘位置（七项） | 点位、均线排列、五均线开关、量能、缺口、空间、波动 | `market.regime`；`maRegime()`；判据只看「收盘 vs MA60」「MA5 vs MA20」，波动 >60 日×1.25 再降 10pct |
| 均线各自管什么（折叠） | 5/10/20/30/60/120 日与 20 月线用法 | 静态文案 |
| 热度与情绪 | 涨跌平、涨停跌停、成交额、恐慌、连续普跌、情绪温度 | `market.breadth` + `sentiment.items` |
| 资金动向 | 主力、两融、北向说明、过热板块（占比 ≥15%） | `market.liquidity.items` + `market.flow[]` |
| 隔夜与消息 | 外围指数、前 3 条快讯 | `market.glob.items` + `market.news` |

国家队已按需求移出 p5，只在 p1 保留最新一期。

#### 4.2.2 2. 组合情况

| 块 | 内容 | 实现 |
|---|---|---|
| 组合板块结构 | 各行业暴露条（**占持仓市值**），≥25% 超配、≤5% 低配，未映射占比单列 | `rsSectorExposure()` + `rsSectorMap()` |
| 集中度与结构 | 最大板块、前三合计、持有/有效只数、现金比例、TMT 合并 | HHI = Σ(占比²)，有效只数 = 1/HHI；TMT = 电子+计算机+通信 |
| 组合与市场是否一致 | 先给结论，再给：最大暴露是否主线、超低配清单、走弱但仍有暴露、覆盖度、轮动信号、未映射说明 | `rsRenderSector()`、`coverageText()`、`rotationSignals()` |
| 申万板块健康度 | 评分、评级、板块上限、涨跌、成交占比、组合暴露、关系、状态 | `sectorScore()`、`rsSectorHealth()` |

板块四维评分（0–100）：技术 40% / 资金 25% / 政策 20% / 情绪 15%。
技术项需要行业代表 ETF 周线，**未接入**，按剩余权重归一，标题标「缺 1 项」。
评级与上限：S≥85→25%、A≥75→20%、B≥60→10%、C≥50→5%、D<50→0%（只限新增）。

#### 4.2.3 3. 个股分析

选择器：每只持仓一个按钮（`rsSelect()`），下方 `#rsDetail` 渲染当前标的。

**正常情况（有日线）——八块 + 一块展示层：**

| 顺序 | 块 | 内容 | 实现 |
|---|---|---|---|
| 1 | 结论 | 减/持/加 + 现→目标、差额、挂单价、费用 | `RS_PLAN`（同一出口） |
| 2 | 进场检查 | 环境 + 三步 ✓/✗：不创新低、均线多头/实体阳线/站上 120 日线、回踩不破/缩量/假突破 | `calcBars()` + `legs[]` |
| 3 | 三周期 | 月线（20 月线）、周线 5/10/20/30、日线 5/10/20/60/120 + 量比 | `rsMonthly()` + `RS_WEEK` |
| 4 | 双评分卡 | 底部：月线底背离 25 + 倍量站上 20 月线 20 + 周线排列 15；顶部：月线顶背离 30 + 破 10 月线 20 + 周线死叉 15 + 板块过热 10；缺项按已有项归一，标未接入项数 | `legScore()` |
| 5 | 结构图 | K 线 + MA5/10/20 + 笔 + 中枢 + 成交量 + MACD；只画最近 220 根 | `rsChanOf()` + Canvas |
| 6 | 缠论结构（展示层） | 中枢 ZG/ZD、现价在中枢上/中/下、最近一笔方向与幅度、底/顶背驰/三买；**与目标的关系**（减仓遇买点 → 仍减但分批更细；加仓遇顶背驰 → 等回踩）；冲突裁决；持仓上下文（评级、现仓→目标、板块占比、大盘） | `rsChanText()` |
| 7 | 概率 | 5/20/60 日上涨占比、样本数、20 日中位 | `rsForecast()` |
| 8 | 怎么做 | 现→目标、差额、确认条数、挂单价、首批、分批 | `RS_PLAN` + `orderTicket()` |
| 9 | 改判 | 转好：站上 20 日线且周线转多；恶化：连续两日破 30 日线 → 卖出剩余差额；另附交易仓/核心仓两套止损 | 静态阈值 + 真实价位 |

**降级情况（没有日线）：** `rsDetailFallback()` 显示仓位、目标、评级/上限、现价、动作原因，
并给「重新取行情」按钮（`rsRetryBars()` 清缓存 → 重取腾讯/东财 → 重算计划并重绘）。不臆造均线与结构图。

池外日线来源：腾讯 JSONP（900 根）→ 东财 JSONP（900 根）→ 失败降级。
周线接口失败时用日线聚合（`rsWeeklyFromDaily()`），月线由此最多只有约 41 个月。

### 4.3 三、市场洞察及方向

| 块 | 内容 | 实现 |
|---|---|---|
| 1 今日定性 | 时段（盘前/盘中/午盘/盘后/周末）+ 偏多/偏空/震荡 + 三条依据 | `marketOutlook()` + `bjSession()`；打分：状态 ±2、MA5/MA20 ±1、涨跌占比 ±1、情绪分 ±1，≥2 偏多、≤−2 偏空 |
| 2 位置与赔率 | 近 120 日高低、距高/低、上下空间、赔率 | `regime.position`；赔率 = 向上空间 ÷ 向下空间，仅描述位置 |
| 3 情绪与主线 | 涨停跌停、成交额、恐慌、连续普跌、情绪节点、主线三判据 | `sentiment.items` + `regime.leaders`；温度 = 情绪×40% + 涨跌家数×35% + 成交额×15% + 趋势×10% |
| 4 情景与触发 | 偏弱延续 / 震荡修复 / 转强确认，真实价位 + 当前距离 | `position.low120`、`ma20`、`close` |
| 5 复盘对照 | 上次计划 vs 今天的目标与评级变化 | `rsStoreSnapshot()` / `rsRenderReview()`，本机 localStorage，不是成交回报 |
| 6 新方向候选 | 板块 B 级以上、非持仓、近 5 日不弱于大盘、同类别一只、不含不碰名单；额度 <3pct 只写观察 | `buildIdeas()` + `rsRenderIdeas()` |

候选不碰名单：军工、传媒、游戏、次新。

## 5. p7 持仓设置

生成函数：`page7()`。

## 6. 公式与阈值总表

| 名称 | 公式 / 阈值 | 位置 |
|---|---|---|
| 总仓位上限 | 状态区间中枢：上行 85 / 震荡 65 / 下行 35；20 日波动 >60 日×1.25 再降 10 | `market_regime` |
| 结构评分 | 50 ±15（收盘 vs MA20）±10（均线排列）+5（站上 MA60）−10（20 日新低），clamp 0–100 | `plan_v3._indicators` |
| 目标权重 | `min(25%, 评级上限, 总上限 × 系数 ÷ 归一)`；系数 =（0.6+0.4×评分/100）× min(1, 15/20日波动) | `plan_v3.build` |
| 评级上限 | S25 / A20 / B10 / C5 / D3 | `PLAN_CAP` |
| 差额→动作 | 目标−现仓；\|差额\|<3pct 持有；差额>3 且周线向下或确认<2 → 等待；差额<−3 → 减仓（跌破 MA10 或周线向下直接减，否则先减一半） | `planActionOf()` |
| 挂单价 | 买 ×1.0001 向上进位；卖 ×0.9999 向下截断；到 0.001 | `orderTicket()` |
| 数量 | `floor(总资产 × 目标% ÷ 挂单价 ÷ 100) × 100`；买入不低于现有份额，受现金限制 | `orderTicket()` |
| 首批 | 卖出 \|差额\| × 50%，向下取整到 100 份（其余 30/20） | `orderTicket()` |
| 费用 | `max(5, 成交额×0.5bp) + 成交额×1bp` | `orderTicket()` |
| 盈亏分母 | 浮盈 ÷ Σ成本；当日 ÷ Σ昨收市值 | `calcPort()` |
| 板块四维 | 资金 `50+(占比/行业均值−1)×20`；情绪 `50+涨跌×8`；政策取同名热度；技术未接入；权重 25/20/15 归一 | `sectorScore()` |
| 板块评级 | S≥85 / A≥75 / B≥60 / C≥50 / D<50；上限 25/20/10/5/0 | `sectorScore()` |
| 个股双评分 | 底部 25+20+15；顶部 30+20+15+10；按已有项归一；顶部≥80 上限 0、≥60 上限 5、≥40 折半 | `legScore()` |
| 情绪温度 | 情绪 40% + 涨跌家数 35% + 成交额分 15% + 趋势分 10% | `marketOutlook()` |
| 缠论结构 | 分型左右各 2 根；笔间隔≥4 根、幅度≥1.5%；中枢取最近 4 笔 3 段重叠（ZG=min 高，ZD=max 低）；底/顶背驰用 DIF；价格>ZG 记三买 | `rsChanOf()` |
| 概率 | 20 日涨幅 + 20 日波动找相似样本，按距离加权；输出 5/20 日上涨占比与中位 | `rsForecast()` |

## 10. 消息面解读模板（给模型用）

页面只显示「综合分 + 正/中/负占比」，四个数本身说明不了什么；解读由模型写，**不规定句式**。

**材料**（`data/live/{market,news}.json`）

- `news_sentiment`：`score`、`label`、`positive`、`neutral`、`negative`
- `news`：前 3 条快讯
- 可选：`global`、`policy_heat`

**要求**

- 100 字以内，一段话；不列点、不用固定套话（禁词见 `config/brief_banned.txt`）。
- 至少说清两件事：正面和负面各主要来自哪条消息；这个分数对今天意味着什么（只作背景，不改仓位）。
- 拿不到材料就留空，不猜政策力度，不预测点位。

**落盘**

```json
{"data_date": "2026-11-23", "note": "100 字以内的解读"}
```

写到 `data/news_note.json`；日期必须等于当日快照日，否则页面不采用。
