# 页面区块对照

一眼看清：页面上每一块是谁算的、数据从哪来、出问题该改哪个文件。
页面只有三页加一个锁屏，全部内嵌在 `web/index.html` 里。

**一条总规则**：后端（Python）只负责取数、算指标、给目标仓位；
凡是和"你持有多少"有关的（仓位、盈亏、差额、订单、行业暴露、评分卡），都在浏览器里算，
因为持仓只在浏览器解密。

## 2 持仓分析（p5，需解锁）

### 一、持仓概况

| 区块 | 显示内容 | 怎么算 | 代码 |
|---|---|---|---|
| 四个数字 | 总资产、持仓市值、浮动盈亏、当日盈亏 | 持仓 × 最新价；盈亏分母=成本，当日分母=昨市值 | `calcPort()` |
| 今日点评 | 八段：今天什么日子 → 大盘阶段 → 主要矛盾 → 行业 → 资金 → 自身偏差 → 今天动什么 → 改判 | 取环境、板块、国家队、目标仓位、订单；每句带数字 | `rsBriefSections()`；若 `data/brief.json` 存在且通过校验则优先用它 |
| 持仓明细表（13 列） | 名称/代码、板块、仓位现→目标、数量、本次操作、挂单价、费用、成本→现价、盈亏、5/20 占比、全市场位置、国家队、动作 | 目标来自 `plan.items`，差额→动作→订单同一出口 | `rsPlanRows()`、`orderTicket()`、`rsSectorLabel()`、`nationalTeamText()`、`rsForecast()` |

### 二、持仓分析

| 区块 | 内容 | 数据来源 | 代码 |
|---|---|---|---|
| 大盘位置（七项表） | 点位、均线排列、五均线开关、量能、缺口、空间、波动 | `market.regime`（close/ma5/10/20/30/60/120、ma_spread_pct、days_above_ma5、gaps、position、vol20/60）、`market.breadth` | `market_regime.classify()` + `maRegime()` |
| 均线各自管什么（折叠） | 5/10/20/30/60/120 日与 20 月线用法 | 静态文案 | `rsPageHTML()` |
| 热度与情绪 | 涨跌平、涨停跌停、连板、成交额、恐慌形态、连续普跌、情绪温度 | `market.breadth` + `sentiment.items` | `rsPageHTML()` + `sentiment` |
| 资金动向 | 主力、两融、北向说明、过热板块 | `market.liquidity.items`、`market.flow[]` | `rsPageHTML()` |
| 隔夜与消息 | 外围指数、前三条快讯 | `market.glob.items`、`market.news` | `rsPageHTML()` |
| 国家队 | 宽基份额表，按日期回溯 25 天，>15% 标"仅展示" | `data/national_team.json` | `nationalTeamTable()`、`ntWindow()` |
| 组合板块结构 | 各行业暴露条 | 持仓权重 × `sector_weights`，**占持仓市值** | `rsSectorExposure()`、`rsSectorMap()` |
| 集中度与结构 | 最大板块、前三合计、有效只数、现金、TMT 合并 | 同上 + HHI | `rsRenderSector()` |
| 组合与市场是否一致 | 最大暴露是否主线、超配/低配、走弱但有暴露、覆盖度、轮动信号 | `sector_weights` + `regime.leaders` + `flow` | `rsRenderSector()`、`coverageText()`、`rotationSignals()` |
| 板块健康度表 | 评分、评级、板块上限、涨跌、成交占比、组合暴露、关系、状态 | 资金=成交占比/31 行业均值；情绪=当日涨跌；政策=政策热度；技术未接入 | `sectorScore()`、`rsSectorHealth()` |
| 宏观经济背景 | 宏观与资金条目 | `market.macro`、`market.liquidity` | `rsMacroRows()` |
| 个股分析（八块） | 结论、进场检查、三周期、双评分卡、结构图、概率、怎么做、改判 | 见下一节 | `rsRenderDetail()` |

个股八块的产出：

| 块 | 数据 |
|---|---|
| 结论 | `RS_PLAN`（同一出口），含现→目标、差额、挂单价、费用 |
| 进场检查 | 日线 K 线（腾讯）+ `legs[].stand_back/shrink/false_breakout` |
| 三周期 | 周线 260 根 → 月线聚合 + 月 MACD；周线 5/10/20/30；日线 5/10/20/60/120 + 量比 |
| 双评分卡 | `legScore()`：月线底背离、20 月线、周线排列、顶背离、破 10 月线、周线死叉、板块过热；未接入项计数 |
| 结构图 | `rsChanOf()` 简化缠论（分型→笔→中枢），Canvas 绘制 |
| 概率 | `rsForecast()` 历史相似条件，样本 <30 写"样本不足" |
| 怎么做 | `RS_PLAN` + 确认条数 + 分批节奏 |
| 改判 | 20 日线 / 30 日线真实价位，两条阈值 |

### 三、市场洞察及方向

| 区块 | 内容 | 数据 | 代码 |
|---|---|---|---|
| 今日定性 | 时段、偏多/偏空/震荡、三条依据 | 状态 ±2、MA5/20 ±1、涨跌占比 ±1、情绪 ±1 | `marketOutlook()`、`bjSession()` |
| 位置与赔率 | 近 120 日高低、距高/低、空间比 | `regime.position` | `marketOutlook()` |
| 情绪与主线 | 涨停跌停、成交额、恐慌、主线三判据 | `sentiment.items`、`regime.leaders/laggards` | `marketOutlook()` |
| 情景与触发 | 偏弱延续 / 震荡修复 / 转强确认，真实价位 + 当前距离 | `position.low120`、`ma20`、`close` | `marketOutlook().scenarios` |
| 复盘对照 | 上次计划 vs 今天的目标与评级 | 本机 localStorage 快照 | `rsRenderReview()`、`rsStoreSnapshot()` |
| 新方向候选 | 板块 B 级以上、非持仓、近 5 日不弱于大盘、不碰名单、额度闸门 | 观察池 `legs[]` + `sectorScore()` + `plan.total_target` | `buildIdeas()` |

## 5 每日工作流

```
bash scripts/daily.sh
  → git 同步 main
  → loader：实时源 → 失败降级快照（data/snapshot、data/cache）
  → features / market_regime / plan_v3：指标、状态、目标仓位
  → webgen：把结果内嵌成 window.DASHBOARD，输出 web/index.html
  → run_update：发布前校验 → 提交推送产物
  → GitHub Actions：只发布 Pages
```

浏览器打开后：
1. 先渲染 p1（纯公开数据）；
2. p5 需要口令解密 `positions.enc.json`；
3. 解密后 `calcPort()` → `rsPlanRows()` → 各块渲染，行情不足时按"数据不足/未覆盖/样本不足"降级。
