# 持仓分析 · 展示与实现指导书 v5

> 读者：维护页面的工程师、每天触发刷新的 Agent、复核人。
> 适用范围：`web/index.html` 的「持仓分析」页（含持仓概况、持仓分析、市场洞察及方向三部分）。
> 本文件规定**呈现什么、每个数字从哪来、文案怎么生成、哪些事必须交给 skill 而不是写死在页面里**。
> 不含投资建议，不预测点位。

## 0. 这一版要解决的三个具体问题

| 症状 | 现在的表现 | 根因 | 本文件的对策 |
|---|---|---|---|
| 文案空洞 | 「先降风险，再调结构；不追高，不抄底」「热度只做环境定性」这类句子没有当日数据支撑 | 文案是页面里写死的字符串，不是由数据生成 | 第 3.3 节「点评规范」+ 第 8 节「skill 输出 claims」：每句必须带数字与出处，校验不过就不显示 |
| 行业分类对不上 | 概况表「主要板块」写死 4 只 ETF 的编造权重；市场侧是 31 个申万一级，两边板块名与占比互相核不上 | `RS_SECTOR_MAP` 硬编码 + 名称关键字兜底 | 第 6 节「行业映射唯一数据源」，页面只读，缺失就标缺失，禁止猜 |
| 逻辑写死 | 阈值、候选清单、判断分支都在 `app.js` 里 | 展示层承担了分析层职责 | 第 1 节三层架构 + 第 8 节 skills：分析在后台产出结构化结论，页面只渲染 |

**三条硬约束（后文所有设计都服从这三条）**

- **R1 页面不得内置业务常数**：行业权重、候选清单、评级阈值、结论文案，一律从 `data/dashboard.json` 读。
- **R2 每个数字可回溯**：页面上出现的每个数字，必须能在 dashboard 里找到字段路径。
- **R3 文案与数据一致**：文案里的数字必须出现在该段 `claims.refs` 中；对不上就不渲染该段，降级为「结论生成失败，仅显示事实」。

## 1. 总体架构

```
                  ┌─────────────────────────────────────────────┐
   数据层          │ datasource（行情/指数/板块/舆情/国家队）      │
                  │   ↓ 落盘 data/snapshot/*、data/cache/*       │
                  ├─────────────────────────────────────────────┤
   计算层          │ features → methodology.decide（唯一动作）    │
   （确定性）      │ → plan_v3（仓位账本）→ execution（约束复核） │
                  ├─────────────────────────────────────────────┤
   分析层          │ skills（结构化结论 + 文案 + claims）          │
   （可刷新）      │   market-brief / portfolio-review /          │
                  │   leg-review / sector-map / national-team    │
                  ├─────────────────────────────────────────────┤
   契约层          │ data/dashboard.json（唯一契约，带版本号）     │
                  ├─────────────────────────────────────────────┤
   展示层          │ webgen → web/index.html（纯渲染 + 校验）      │
                  └─────────────────────────────────────────────┘
```

### 1.1 职责边界

| 层 | 可以做 | 不可以做 |
|---|---|---|
| 数据层 | 抓取、落盘、记录失败与数据日 | 判断方向 |
| 计算层 | 指标、评分、档位、目标权重、动作、约束 | 写解释性长文 |
| 分析层（skill） | 组织事实、写解读、给冲突裁决、给改判条件 | 改动作、改目标权重、改阈值、编造数字 |
| 契约层 | 版本、字段、类型、缺失语义 | 承载业务逻辑 |
| 展示层 | 格式化、排序、折叠、校验 claims | 计算评级、拼行业权重、内置候选 |

### 1.2 当前实现的落点（迁移前）

| 能力 | 现在在哪 | 迁移目标 |

| 页面骨架 | `app.js` `page5()`（839）、`rsPageHTML()`（2214） | 保留骨架，内容改读 dashboard |

## 2. 数据契约 `data/dashboard.json`

版本号 `dashboard_version: "5.0"`；任何字段变更必须升版本，展示层按版本兼容。

### 2.1 顶层结构

| 字段 | 生产者 | 消费者 | 缺失时页面表现 |
|---|---|---|---|
| `meta` | pipeline | 全部 | 顶部「数据不可用」 |
| `market` | datasource + `market_regime.classify` | 二、三部分 | 相关块显示「基准数据不足」 |
| `market.regime.position` | `market_regime` | 位置与赔率 | 显示「缺少高低点」 |
| `plan`（仓位账本） | `plan_v3.build` | 一、二、三部分 | 目标列显示 `—`，候选全部「观察」 |
| `legs[]` | features + methodology | 一、二部分 | 该腿 ABSTAIN |
| `sector_weights` | `sector-map` skill | 一、二部分 | 「行业权重未覆盖」 |
| `national_team` | `fetch_national_team` | 一、二部分 | 显示「未纳入」 |
| `analysis` | skills | 一、二、三部分 | 降级为事实展示 |

### 2.2 `plan`（仓位账本，唯一动作来源）

```json
{
  "total_target": 35.0,
  "fit_lo": 30, "fit_hi": 40,
  "max_single": 25,
  "items": [
    {"code": "510300", "target_weight": 8.9, "score": 40, "grade": "D",
     "cap": 5, "trend_factor": 0.35, "own_target": 1.8}
  ]
}
```

派生规则（不得在页面里重算）：

| 字段 | 公式 |
|---|---|
| `own_target` | `cap × trend_factor` |
| `target_weight` | 经 L2 集中度折减、L3 环境锚±带校准后的采纳值 |
| `gap` | `target_weight − weight` |
| `action` | 由 `gap` 与确认条件派生（见 9.1） |
| `pace` | 减仓单周 `min(|gap|, max(5, |gap|/3))`；加仓一次到位；`|gap|<3` 不动 |

### 2.3 `analysis`（skill 产出的解释层）

```json
{
  "version": "5.0",
  "generated_at": "2026-11-20 09:10:00",
  "degraded": false,
  "overview": {"brief": [{"stage": "环境|结构|执行|改判",
                          "text": "…", "refs": [{"path": "market.regime.regime", "value": "下行趋势"}]}]},
  "env": {"verdict": "偏空", "score": -3, "reasons": [...], "mood": [...], "mainline": "…", "claims": [...]},
  "portfolio": {"focus": "…", "alignment": "…", "risks": [...]},
  "legs": {"510300": {"one_liner": "…", "reasons": [...], "change_condition": "…", "claims": [...]}},
  "outlook": {"session": "盘后", "scenarios": [...], "candidates": [...]}
}
```

**claims 规则**

- `refs.path` 必须是 dashboard 内真实路径；`value` 与路径取值一致（校验见 7.3）。
- 一段文案至少 1 条 refs；数字型句子至少 1 条数值 refs。
- 校验失败：该段不渲染，页面显示「解释生成失败（引用不一致）」，其余事实照常显示。

## 3. 第一部分：持仓概况

定位：**一屏看完、不看技术**。回答四个问题：有多少钱、赚亏多少、偏离目标多少、今天做什么。

### 3.1 版面

```
[总资产] [持仓市值] [浮动盈亏] [当日盈亏]        ← 4 个 KPI
───────────────────────────────────────────
今日点评（四段，见 3.3）
───────────────────────────────────────────
明细表（11 列，见 3.2）
───────────────────────────────────────────
脚注：数据日 / 统计口径 / 样本说明
```

已删除的内容（不要加回来）：仓位条、独立「持仓类别」卡、执行后估算卡、今日建议卡。仓位与目标的对比已并入 KPI 的说明行与点评。

### 3.2 明细表字段

| 列 | 字段路径 | 计算 | 缺失显示 |
|---|---|---|---|
| 代码 | `legs[].code` | — | — |
| 名称 | `legs[].name` | — | 代码 |
| 主要板块 | `sector_weights.names[code][0]` | 指数行业权重最大项 | 行业权重未覆盖 |
| 权重（现→目标） | `legs[].weight` → `plan.items[].target_weight` | 市值 / 总资产 | `—` |
| 数量（现→建议后） | `legs[].shares` → `floor(total × target% / last / 100) × 100` | 100 份取整 | 只显示当前 |
| 成本 → 现价 | `legs[].cost` → `legs[].last` | — | `—` |
| 盈亏 | `legs[].pnl_pct` / `legs[].pnl` | (last/cost−1) | `—` |
| 5/20 日占比 | `legs[].forecast.d5.p` / `d20.p` | 见 4.3.4 | 样本不足 |
| 全市场位置 | `legs[].rs.excess5` + `market.sector_flow[track].share_pct` | 相对基准 5 日超额 | `—` |
| 国家队 | `national_team.series` 近 4 期 | 该宽基份额变化 | 未纳入 |
| 动作 | `plan.items[].action` + `action_text` | 由 gap 派生 | `—` |

> 全市场位置与「主要板块」必须来自同一套行业枚举（见第 6 节），否则两列会自相矛盾。

### 3.3 今日点评规范（反空洞的核心）

结构固定为四段，每段一句话，全文 ≤ 160 字，**不得出现无数据的形容词**。

| 段 | 必须包含 | 句式 | 反例（禁止） |
|---|---|---|---|
| 环境 | 时段、大盘状态、定性、1 条依据、仓位与锚的偏离、温度 | 「盘后：大盘X，定性Y；依据Z。仓位 a%，锚 b%（高/低 n pct）；温度 t/100。」 | 「市场情绪偏暖，注意风险」 |
| 结构 | 触发退出/减仓/可加仓只数、最弱一腿及其动作 | 「结构上 x 只退出、y 只减仓、z 只可加仓；最弱 CODE（动作）。」 | 「持仓结构整体合理」 |
| 执行 | 今日订单笔数与代码、未动原因 | 「今日 n 笔：A、B；其余差额不足 3pct。」 | 「按计划执行即可」 |
| 改判 | 两个可验证条件及其后果 | 「改判：基准收复 MA20 x 且 MA5 上穿 → 锚上调；某腿跌破 MA30 两日 → 卖出该腿差额。」 | 「密切关注市场变化」 |

补充规则：

1. 四段全部由 `analysis.overview.brief` 提供，页面不拼句子。
2. 每段必须带 `refs`；含数字的句子必须为数值 refs。
3. 数据不足时写「缺失」并说明缺哪个字段，不写推测。
4. 禁用词表见附录 C。

## 4. 第二部分：持仓分析

定位：**逐层深入**，顺序固定为「市场环境 → 组合情况 → 个股分析」。三层不得倒置，因为上层给额度、下层只能收紧。

### 4.1 市场环境（先看天）

| 块 | 字段 | 规则 |
|---|---|---|
| 大盘走势 | `market.regime.regime` / `fit_lo` `fit_hi` / `as_of` / `ma5` `ma20` `ma60` / `close` | 状态由 `market_regime.classify` 判定：收盘 > MA60 且 MA5 > MA20 → 上行；收盘 < MA60 且 MA5 < MA20 → 下行；否则震荡；`vol20 > vol60×1.25` 追加「波动抬升」 |
| 热度与舆情 | `breadth.advance/decline/amount_yi/amount_chg_pct`、`sentiment.score/label`、`news_sentiment.score/label` | 只描述，不生成动作 |
| 国家队 | `national_team.series[].groups` | 近 4 期变化；只调倾向 ≤ ±5pct，不得破 `fit_lo/fit_hi` |

解读要求：每个块一句「数据 → 判断 → 改判」，由 `analysis.env` 产出；页面不写死。

### 4.2 组合情况（再看结构）

#### 4.2.1 板块暴露

```
exposure[s] = Σ_i weight_i × sector_weights[track(i)][s] / 100
```

- `sector_weights` 见第 6 节；`track(i)` 来自 `universe.yaml` 的 `track` 字段。
- 板块枚举必须等于 `market.sector_flow[].sector` 的集合（申万一级 31 个）。
- 任一 ETF 缺映射 → 该腿计入「未覆盖」，在表下方单独一行，不并入其他板块。

#### 4.2.2 集中度与结构

| 指标 | 公式 | 阈值来源 |
|---|---|---|
| 最大板块 | `max(exposure)` | 提示线 25% |
| 前三板块 | `sum(top3)` | — |
| HHI | `Σ (weight_i/100)²` | 提示线 0.25 |
| 有效只数 | `1 / HHI` | — |
| 浮亏腿数 | `count(pnl_pct < 0)` | — |
| 现金比例 | `cash / total` | 下限 `min_cash_pct: 5` |

只列事实 + 与阈值的比较，不合成单一「健康分」。

#### 4.2.3 板块健康度（四维，替换现有单日公式）

现有实现 `50 + 涨跌×8 + (占比−4)×1.2` 只反映当日，噪声大。改为拐点体系的四维加权：

| 维度 | 权重 | 指标 | 缺失处理 |
|---|---|---|---|
| 技术面 | 40% | 周线 MACD 方向 + 均线排列 + 是否处 20 周线上方 | 缺 → 不计入，按可得项归一 |
| 资金面 | 25% | 板块成交占比变化（近 5 日 vs 前 5 日） | 缺 → 归一 |
| 政策面 | 20% | `policy_heat` 该主题热度与变化 | 缺 → 归一 |
| 情绪面 | 15% | 板块当日涨跌 + 涨跌家数占比 | 缺 → 归一 |

输出四维原始值 + 加权分 + 「维度缺失」标记；页面必须同时显示四维，不能只给总分。

#### 4.2.4 组合与市场是否一致

判定三条，全部落文字：

1. 最大暴露板块是否属于 `market.rotation.leaders`（主线）→ 是/否 + 差额。
2. 超配（≥25%）与低配（≤5%）清单。
3. 「走弱但仍有暴露」清单：`板块健康度状态=走弱 且 exposure ≥ 10%`，逐条给收紧方向。

结论必须与第一部分动作不冲突：若判定某板块走弱但该板块对应持仓动作为「加仓」，必须在此处标红冲突并降级为「观察」。

### 4.3 个股分析（最后看腿）

#### 4.3.1 结论卡

- 结论标签只有三种：**减 / 持 / 加**，且必须等于账本 `action`。技术面不得给出与账本相反的建议。
- 信心分改为可解释项：`依据条数 × 一致性`，不再用 `a.level` 映射固定值。

#### 4.3.2 三周期状态（月 / 周 / 日）

| 周期 | 判定 | 输出 |
|---|---|---|
| 月线 | 收盘 vs 20 月线 + 月 MACD 背离（双/单/无） | 牛 / 转换 / 熊 |
| 周线 | 5/10/20/30 周排列 + MACD | 多头 / 金叉初期 / 走平 / 空头 |
| 日线 | 收盘 vs MA10/MA20 + MACD + 量比 | 强 / 转折 / 弱 |

评分卡（0–100）：月线底背离 35 + 站上 20 月线 25 + 周线多头 25 + 日线确认 15。
档位 → 单只上限：S≥85→25%、A 75–84→20%、B 60–74→12%、C 50–59→8%、D<50→5%（观察仓，不清零）。
估值、景气、资金三项未接入时，页面必须标注「按可得项归一」。

#### 4.3.3 缠论（明确边界）

实现顺序：分型 → 笔 → 中枢 → 背驰 → 买卖点。

| 步骤 | 规则（当前实现） |
|---|---|
| 分型 | 左右各 2 根的最高/最低确认 |
| 笔 | 顶底交替、间隔 ≥4 根、幅度 ≥1.5% |
| 中枢 | 最近 3 段笔的重叠区间：ZG = min(各段高)，ZD = max(各段低)，ZG > ZD 有效 |
| 底背驰 | 价格创新低而 MACD DIF 抬高 |
| 三类买卖点 | 仅标注「底背驰（1 买候选）」「站上中枢上沿（3 买）」 |

**不得**做的事：不做线段、不做多级别递归时，必须在图注写明「简化实现」；不得使用固定序号（如第 18/44/68 根）当买卖点；不得用分位数假装中枢。

#### 4.3.4 概率

- 特征：20 日动量 + 20 日波动；距离加权取最近 k 个样本（k ≈ 4√n）。
- 输出 5/20/60 日：上涨占比、中位涨幅、样本数、样本区间。
- 样本 < 30 → 显示「样本不足」，不显示百分比。
- 概率只做参考，不改变档位与动作（冲突表第 6 条）。

#### 4.3.5 执行与改判

| 项 | 内容 |
|---|---|
| 当前 → 目标 | `weight → target_weight`，差额 |
| 确认条件 | 周线是否向上 + 日线确认 0–3（站上 MA10 / MACD 多头 / 量比 >1.1） |
| 节奏 | 减仓单周 ≤ 差额 1/3 且 ≥5pct；加仓需确认 ≥2；`|gap|<3` 不动 |
| 执行位 | 买点参考 MA10；失效为收盘跌破 MA20 |
| 改判 | 周线转多头且站上 MA20 → 目标回到 `own_target`；跌破 MA30 两日 → 卖出全部差额 |

## 5. 第三部分：市场洞察及方向

定位：**给位置、给情绪、给情景**，不给「明天涨跌」。与第一部分共用同一环境源，禁止另算一套。

### 5.1 今日定性

- 时段感知：盘前 05:00–09:25 / 盘中 09:30–11:30 与 13:00–15:00 / 午盘 11:30–13:00 / 盘后 / 周末。
- 打分：下行趋势 −2、MA5<MA20 −1、涨跌家数 <45% −1、情绪分 ≤35 −1（正向同理），`|score| ≥ 2` 定偏多/偏空，否则震荡。
- 输出：定性 + 3 条依据（每条含数字）。
- 时段只影响「关注重点」，不改结论口径。

### 5.2 位置与赔率

- 输入：`market.regime.position`（近 120 日高/低、上下空间、赔率、振幅）。
- 输出：距高点 %、距低点 %、向上空间 %、向下空间 %、赔率。
- 必须注明：赔率 = 向上空间 ÷ 向下空间，只描述位置，不代表发生可能性；贴近前低时赔率会放大。

### 5.3 情绪与主线

| 项 | 数据 | 说明 |
|---|---|---|
| 涨跌停 / 连板 | `sentiment.items` | 情绪强度 |
| 成交额环比 | `breadth.amount_chg_pct` | 缩量下跌不计恐慌；放量下跌才算 |
| 恐慌判定 | `sentiment.items['恐慌判定']` + 连续普跌天数 | 二者缺一不下「恐慌」结论 |
| 主线确认 | `rotation.leaders` + `情绪节点` + `首次分歧` | 只有「分歧转一致 + 首次分歧已过」才写具备「扛过分歧再反包」条件，且需次日不破 MA5 确认 |
| 落后方向 | `rotation.laggards` | 「未跌够的不追反弹」 |

### 5.4 情景与触发

三个情景，触发值取真实价位，不用写死系数（如 `MA20×0.96`）：

| 情景 | 触发 | 对应动作 |
|---|---|---|
| 偏弱延续 | 收盘跌破近 120 日低点 | 按差额分批减，不抄底 |
| 震荡修复 | 在前低 ~ MA20 之间震荡 | 只调结构，不加总仓 |
| 转强确认 | 站上 MA20 且 MA5 上穿 MA20 | 差额可执行 |

每行同时显示「当前距触发的百分比」，让读者知道离哪边近。

### 5.5 新方向候选

过滤顺序：观察池 → 排除已持仓 → 仅 A/B 级 → 相对基准 5 日不弱 → 同类别只留一只 → 额度闸门。

额度闸门：`room = total_target − 当前仓位`；

- `room < 3pct` 或账本缺失 → 全部「观察」，并写明原因；
- `room ≥ 3pct` 且 A 级 → 可分批；B 级 → 观察。

禁止：内置固定候选清单；在额度不足时仍推荐买入。

## 7. 每日运行链条

### 7.1 命令与顺序

```bash
python3 -m pytest tests/ -q                 # 1. 不触网，先挡回归
python3 scripts/run_update.py --json        # 2. 取数 → 计算 → skill → dashboard → 页面
python3 scripts/run_update.py --verify      # 3. 只校验，不取数
```

### 7.2 时序

```
fetch（行情/指数/板块/舆情/国家队/行业权重）
  → features（均线、MACD、量比、相对强度）
  → methodology.decide（唯一动作）
  → plan_v3（账本：own_target → target → gap → action → pace）
  → execution（目标份额、费用、约束复核；不通过则 published=false）
  → skills（overview / env / portfolio / legs / outlook，产出文本 + claims）
  → dashboard.json（版本 + 数据日 + degraded）
  → webgen（渲染；claims 校验失败则降级）
  → 发布（提交 + Pages）
```

### 7.3 三道闸门

| 闸门 | 检查 | 失败处理 |
|---|---|---|
| 契约校验 | dashboard 字段齐全、类型正确、版本匹配 | 不发布，报错 |
| 引用校验 | 文案内数字 ⊆ claims.refs；refs 路径存在且值一致 | 该段不渲染，页面标注「解释生成失败」 |
| 一致性校验 | 三个部分的动作、方向、额度互相不矛盾（第 9 节） | 标红冲突并降级为「观察」 |

### 7.4 降级语义

| 状态 | 含义 | 页面表现 |
|---|---|---|
| OK | 全链路成功 | 正常 |
| DEGRADED | 非关键字段缺失 | 顶部提示 + 缺失处标「缺失」 |
| ABSTAIN | 关键数据不足 | 不显示动作，只显示事实 |
| DEMO | 离线快照 | 顶部横幅，禁止当作真实数据 |

## 8. Skills 规范（把「写死的文案」换成可刷新的分析）

### 8.1 为什么要 skill

页面里的长句、判断、候选清单，本质是**每天变化的分析结论**。写在 `app.js` 里，只能靠改代码更新，而且容易写成空话。改成 skill 后：

- 输入固定（dashboard 子集），输出固定（JSON schema），可校验；
- 换模型、换提示、换口径都不用改页面；
- 失败可回退到规则生成的兜底文案，并在页面标注。

### 8.2 skill 清单

| skill | 输入 | 输出 | 禁止 |
|---|---|---|---|
| `market-brief` | `market.regime/breadth/sentiment/rotation/policy_heat` | `analysis.env`：定性、3 条依据、情绪条目、主线判断 | 给个股动作；预测点位 |
| `portfolio-review` | `plan`、`exposure`、`market.sector_flow`、`regime` | `analysis.portfolio`：一致性、超低配、走弱暴露、3 条风险 | 改权重；推荐具体标的 |
| `leg-review` | 单腿 `legs[i]` + `plan.items[i]` + 缠论/概率 | `analysis.legs[code]`：一句话、3 条理由、改判条件 | 改动作；给目标价；编造价位 |
| `sector-map` | `universe.yaml`、指数权重源 | `index_sector_weights.json` | 用名称猜行业 |
| `national-team` | 上交所份额 | `national_team`（既有） | 推断政策意图 |

### 8.3 输出 schema（以 leg-review 为例）

```json
{
  "code": "510300",
  "one_liner": "周线空头、日线转折，按差额分 4 周减，不一次清仓。",
  "reasons": [
    {"kind": "结构", "text": "月线转换、周线空头，方向以周线为准"},
    {"kind": "执行", "text": "差额 -18.4pct，单周上限 6.1pct"},
    {"kind": "相对", "text": "5 日相对基准 -0.8pct，弱于大盘"}
  ],
  "change_condition": "周线转多头且站上 MA20 → 目标回到 1.8%；跌破 MA30 两日 → 卖出全部差额。",
  "claims": [
    {"path": "legs.510300.week.state", "value": "空头/死叉"},
    {"path": "plan.items.510300.gap", "value": -18.4}
  ]
}
```

### 8.4 提示约束（写进 skill 的 system prompt）

1. 只使用输入 JSON 中的字段，不得引入外部记忆或常识数字。
2. 每个数字必须来自 `claims`；找不到字段就写「缺失」，不估算。
3. 不写「注意风险」「保持谨慎」「综合来看」这类无信息句。
4. 不预测点位、不给目标价、不承诺收益。
5. 一句话结论必须能被执行（含动作、幅度或条件）。
6. 中文，短句，每段 ≤ 3 行。

### 8.5 回退

skill 输出未通过 schema 或 claims 校验 → 使用规则兜底文案（现有 `rsRenderBrief` 的生成逻辑即为兜底实现），并在 `analysis.degraded=true`，页面在点评标题旁标注「兜底文案」。

## 9. 一致性与冲突裁决

### 9.1 唯一动作来源

动作只由账本派生，页面与 skill 都不得另写：

```
gap = target_weight − weight
|gap| < 3                      → 持有
gap > 0 且 周线向下            → 等待（不买）
gap > 0 且 确认 < 2            → 等待确认
gap > 0 且 确认 ≥ 2            → 加仓 gap
gap < 0 且 周线空头/日线弱     → 减仓（按 pace）
gap < 0 其他                   → 减半差额
```

规则卡 `methodology.decide` 只用于**数据闸门**与**减仓最早触发时点**，不覆盖目标权重。

### 9.2 冲突裁决表（页面需显示「冲突 + 裁决」）

| 冲突 | 裁决 |
|---|---|
| 日线强 / 周线空头 | 方向以周线为准，日线只定执行节奏 |
| 月线转换 / 周线空头 | 按周线处理，不提前加仓 |
| 差额为正 / 周线向下 | 不买，动作降级为等待 |
| 评分档上限 / 环境额度 | 取小 |
| 缠论买点 / 差额为负 | 不做多，缠论只用于卖出时点 |
| 概率偏低 / 评分较高 | 概率只做参考，不改档位 |
| 舆情·国家队 / 仓位区间 | 只 ±5pct 倾向，不得破上下限 |
| 组合判定走弱 / 该腿动作加仓 | 冲突标红，动作降级为观察 |

### 9.3 校验实现位置

- 计算层：`portfolio/execution.py` 与 `web_assets/decision.js`（同构）
- 展示层：渲染前比对三处（概况动作、组合一致性、环境定性），不一致则加 `conflict` 标记
- 测试：`tests/test_audit.py` 已有「单一订单来源」等约束，新增「板块枚举一致」「文案 claims 完整」两条

### B. 术语

| 词 | 含义 |
|---|---|

### C. 禁用词与空洞句（出现即判不合格）

- 没有具体数字的「情绪偏暖」「资金活跃」
