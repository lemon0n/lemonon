# 持仓分析页 · 施工指南

给第一次接手这个页面的人：每一块显示什么、判断从哪来、没有数据怎么显示、写在哪、怎么验收。

适用范围：`web/index.html` 第 5 页「持仓分析」（持仓概况 / 持仓分析 / 市场洞察及方向）。
不构成投资建议，不预测点位。

**三条底线**

- 页面不写死业务数字：行业权重、候选名单、评级分数线、点评句子，全部由数据与规则算出来。
- 每个数字都能说出出处：哪个文件、哪个字段、哪次运行。
- 一句结论里的数字，必须能在同一页找到那个数；找不到就不写这句话。

**一句话验收**：把页面上任意一句结论单独拿出来，读者都能在同一页找到支撑它的数字；找不到，就是不合格。

## 2. 页面是什么

### 2.1 三个部分，各回答一个问题

| 部分 | 回答 | 读者动作 | 篇幅 |
|---|---|---|---|
| 一、持仓概况 | 我有多少钱、赚亏多少、今天买卖什么、多少份什么价 | 直接照着下单 | 一屏，不滚动也能看完四卡+点评 |
| 二、持仓分析 | 市场什么环境、组合跟不跟得上、每只为什么留或减 | 判断要不要改计划 | 可长，越往下越细 |
| 三、市场洞察及方向 | 大盘在什么位置、情绪冷热、三种走法怎么办、还能看什么 | 做下周打算 | 中等 |

顺序不可倒：**先给结论（概况），再讲理由（分析），最后讲远景（洞察）**。理由只能收紧结论，不能推翻结论。

### 2.2 一屏原则

概况只放三类东西：四个数字、一段点评、一张能下单的表。
不放：仓位条、持仓类别饼图、执行后估算卡、今日建议卡、表下小字说明、收益曲线。这些内容已经在表里或点评里，重复即噪音。

### 2.3 命名（页面上一律用名字）

| 写法 | 例子 |
|---|---|
| 名字（代码） | 沪深300ETF（510300）、科创50ETF（588000） |
| 只写代码 | 只允许出现在表格的「代码」列和函数参数里 |
| 行业名 | 用市场板块表里的名字：电子、银行、电力设备… |

第一条出现全名，后文可只写名字。禁止只写一串数字让读者自己查。

## 3. 决策链：五层，每层只做一件事

### 3.1 先说以前为什么割裂

旧页面的问题不是数据不够，而是**四套判断同时在跑**：

| 位置 | 它在说什么 | 谁听谁的 |
|---|---|---|
| 规则卡（methodology） | 这只触发减仓 | 不知道有没有人执行 |
| 目标仓位表（plan_v3） | 这只该占 8.9% | 与规则卡的动作不保证一致 |
| 执行后估算 | 执行完还剩多少仓 | 自己算一遍，与表里的数量对不上 |
| 持仓分析（技术） | 日线转强、缠论买点 | 与上面的减仓完全相反 |

四个地方各有一套数字，读者自然觉得割裂。修复办法只有一条：**把动作收敛到一个出口，其他层只能收紧，不能另起一套。**

### 3.2 五层与唯一出口

```
L0 数据闸门     行情/持仓/行业权重/舆情是否可用；不可用就只说事实
   ↓
L1 环境层       大盘状态 → 总仓位上限（35 / 65 / 85，可 ±5）
   ↓
L2 板块层       板块强弱评分 → 板块评级（S/A/B/C/D）→ 单板块上限、覆盖度
   ↓
L3 个股层       三周期 + 双评分卡 + 结构 → 单只上限（25/20/10/5/0）
   ↓
L4 组合层       目标仓位 = min(总上限分摊, 单只上限, 单板块上限) → 差额 → 动作
   ↓               ↓
   ↓          唯一出口：目标仓位表 → 订单（数量、挂单价、费用）
   ↓
L5 解释层       点评、逐只解读、洞察；只能引用 L1–L4 的结论
```

三条传导规则：

1. **额度只能收紧**：L2 拿到的总仓位上限，只能往下压，不能加。
2. **下层不许翻案**：L3 技术再强，若 L2 判定该板块 D 级（上限 0），就不得加仓。
3. **解释层不许自创**：L5 里出现的动作必须等于 L4 的动作；想说的不同，先改 L4。

### 3.3 每层做什么、不许做什么

| 层 | 输入 | 输出（结构化） | 不许做 |
|---|---|---|---|
| L0 | 行情、持仓、行业权重、舆情、国家队 | 可用/降级/放弃 + 缺失项清单 | 用估算值填空 |
| L1 | 指数日线、涨跌家数、成交额、隔夜、资金、国家队 | 大盘状态、总仓位上限、环境定性（偏多/偏空/震荡） | 指定买哪只 |
| L2 | 行业指数/代表 ETF 的周线、板块成交占比、政策热度、当日涨跌 | 板块四维分、板块评级、覆盖度、过热标记 | 直接给个股数量 |
| L3 | 个股月/周/日线、MACD、量比、相对强度、缠论 | 三周期状态、评分、评级、执行位 | 决定目标仓位 |
| L4 | 上限、评分、当前仓位、现金、约束 | 目标仓位、差额、动作、订单 | 写解释长文 |
| L5 | 以上全部 | 点评、逐只解读、情景 | 改任何数字 |

### 3.4 冲突裁决表（页面必须显示「冲突 + 裁决」）

| 冲突 | 裁决 |
|---|---|
| 日线转强 / 周线空头 | 以周线定方向，日线只定节奏，不加仓 |
| 月线转换 / 周线空头 | 按周线，不提前埋伏 |
| 目标仓位高于现在 / 周线向下 | 不买，改为等待，写明等什么 |
| 单只上限 / 板块上限 / 总上限 | 三者取小 |
| 缠论买点 / 目标是减 | 不做多，缠论只用于卖出时点 |
| 概率偏低 / 评分较高 | 概率只作参考，不改评级 |
| 舆情或国家队 / 仓位区间 | 最多 ±5 个百分点，不破上下限 |
| 板块判定走弱 / 该只动作是加仓 | 标橙，动作降级为「观察」，不新增 |
| 规则卡触发减仓 / 目标仓位仍高 | 以目标仓位为准，规则卡只用于最早减仓时点与数据闸门 |

## 4. 第一部分 持仓概况

版面自上而下：

```
① 四个数字
② 今日点评
③ 持仓明细表
```

### 4.1 四个数字

| 卡 | 大字 | 小字 | 怎么算 | 缺数据 |
|---|---|---|---|---|
| 总资产 | 金额 | 其中现金多少 | 所有持仓市值 + 现金 | 显示「—」，小字写缺哪只的价格 |
| 持仓市值 | 金额 | 持有几只 | Σ 最新价 × 份额 | 同上 |
| 浮动盈亏 | 百分比 | 金额 | Σ（最新价 − 成本价）× 份额 | 缺成本只显示「—」 |
| 当日盈亏 | 百分比 | 金额 | Σ（最新价 − 昨收）× 份额 | 缺昨收显示「—」 |

赚红亏绿、零值灰；金额取整到元加千分位；比例两位小数。
无持仓：只显示总资产与现金，后两卡写「暂无持仓」。

实现：`calcPort()` 计算、`kpi()` 渲染。

### 4.2 今日点评

**它不是数据罗列，是一次综合判断。** 写法照沉关河的复盘：一句结论先行，一句定性，2–3 点编号理由，然后怎么做，最后一句风险收口；每段不超过 3 行，短句，不用「综上所述」。

#### 生成方式（两层）

1. 主来源：`skills/portfolio-brief` 每日运行时读取当次全部结论，写 `data/brief.json`，页面直接读。
2. 兜底：文件缺失或数据日期与页面不一致，页面用 `rsBriefSections()` 现场生成，标题标注「（本机引擎）」。

**点评只能引用 L1–L4 的结论，不能自己再判断一次。** 这是"不再割裂"的关键：点评里说减仓，表里的动作就必须是减仓。

#### 结构（不强制分几段，讲清为止）

| 环节 | 必须写到 | 不许写 |
|---|---|---|
| 结论 | 基调 + 今天最该做的一件事 | 「注意风险」「保持谨慎」 |
| 环境 | 大盘状态、总仓位上限、当前仓位与偏离、量能、情绪温度 | 无数字的形容词 |
| 结构 | 主要矛盾是哪只、哪个板块，为什么 | 平均用力地列四只 |
| 动作 | 方向、数量、挂单价、分几批；不动的写原因 | 只说「减仓」不给量 |
| 改判 | 阈值 + 后果（站上什么就怎样，跌破什么就怎样） | 「密切关注」 |
| 收口 | 「价格是执行价，不保证成交。」 | 收益承诺 |

#### 示例（下行趋势中的减仓日，实际内容每天不同）

> **今日基调：先降后看。**
>
> 大盘还在 60 日线下方，5 日线压在 20 日线下，近 5 日量能比前 5 日缩了两成，没有放量急杀，所以这是阴跌不是恐慌。总仓位上限 35%，我们现在 40.6%，高出 5.6 个百分点，这一口先还回去。
>
> 1. 结构上四只里三只周线仍是空头排列，只有科创50ETF（588000）日线先转强，但周线没跟上，按纪律不加。
> 2. 真正拖累的是沪深300ETF（510300）：月线在转换期、周线死叉，底部评分 38，评级 D。
> 3. 电子板块成交占比 16.1%，已经过热，而我们的电子暴露 17.5%，是唯一超配的方向。
>
> 今天动两笔：沪深300ETF（510300）减 2400 份，挂 4.051；中证500ETF（510500）减 800 份，挂 6.312。科创50ETF（588000）不动，等回踩 10 日线再谈。剩余差额按 50/30/20 分三批减完，不一次清仓。
>
> 改判：基准收复 20 日线 4069.52 且 5 日线上穿 20 日线，总仓位上限从 35% 上调到 45%；任一只收盘连续两日跌破 30 日线，卖出该只全部剩余差额。
>
> 价格是执行价，不保证成交。

骨架：**定方向 → 找主要矛盾 → 给动作（量+价+分批）→ 写改判 → 收口**。

#### 禁词与硬规则

- 禁：注意风险、保持谨慎、密切关注、综合来看、整体合理、酌情处理、有望、可能上涨、保证、必涨、胜率。
- 每句带数字；没有的数写「缺失」并说明缺哪个字段。
- 不给目标价，不预测点位，不写「概率很大」这类无样本量判断。
- 给动作时同时给失效条件。

实现：`rsBriefSections()`（兜底）、`rsRenderBrief()`（渲染）、`webgen._brief()`（读取与校验）、`skills/portfolio-brief/SKILL.md`（契约）。

### 4.3 持仓明细表

一行一只，能照着下单。

| 列 | 显示 | 怎么算 | 缺数据 |
|---|---|---|---|
| 名称 / 代码 | 沪深300ETF（510300） | 直接取 | 名称缺只显示代码 |
| 板块 | 主要投向 | 指数行业权重最大项 | 「行业未覆盖（数据日 X）」 |
| 仓位（现→目标） | 20.3% → 8.9% | 现：市值÷总资产；目标：目标仓位表 | 「目标缺失」 |
| 数量（现→建议） | 30,000 → 21,900 | 向下取整（总资产×目标仓位%÷挂单价÷100）×100 | 只显示当前 |
| 本次操作 | −8,100 | 建议数量 − 现在数量 | 「—」 |
| 挂单价 | 4.051 | 买：现价×1.0001；卖：现价×0.9999 | 「不挂单」+原因 |
| 费用 | ¥4.1 | max(5, 成交额×0.5bp) + 成交额×1bp | 「—」 |
| 成本 → 现价 | 4.120 → 4.052 | 直接取 | 「—」 |
| 盈亏 | −1.7% / −¥2,040 | （现价−成本）÷成本；金额=差价×份额 | 「—」 |
| 5/20 日上涨占比 | 46% / 43% | 历史相似条件统计 | 样本<30 整列隐藏 |
| 全市场位置 | 弱于基准 0.8pct | 近 5 日涨幅 − 大盘 5 日涨幅 | 「—」 |
| 国家队 | 沪深300 减持 0.3% | 该宽基近 25 天份额变化 | 「未纳入」 |
| 动作 | 减仓 −11.4pct | 目标仓位表 | 「—」 |

约定：

- 排序：按本次操作金额降序，不动的靠后。
- 格式：份额千分位；价格三位小数；费用到分。
- 动作必须等于订单方向；不一致整行标橙并写「以订单为准」。
- 每行 `title` 带规则编号，便于回查。

下单信息六条边界：

| 情况 | 处理 |
|---|---|
| 目标仓位缺失 | 数量、价格全「—」，备注「目标缺失」 |
| 价格缺失 | 同上，备注「价格缺失」 |
| 不足 100 份 | 视为不动，备注「不足一手」 |
| 买入现金不足 | 按可用现金下调手数，备注「受现金限制」 |
| 当日成交额 < 1000 万 | 不挂单，备注「流动性不足」 |
| 停牌 / 涨跌停封死 | 不挂单，备注原因 |

实现：`orderTicket()`（算量价费）、`rsPageHTML()`（拼表）、`rsSectorMap()`（板块）、`nationalTeamText()`（国家队）。

## 5. 第二部分 持仓分析

顺序固定：**市场环境 → 组合情况 → 个股分析**。上层给额度，下层只能收紧。

### 5.1 市场环境

按沉关河的四层取数（大盘 → 板块 → 个股 → 情绪）取前两层与情绪，叠上拐点体系的宏观层与 topnews 的时段判断。页面上分五个小块。

#### 5.1.1 大盘位置（沉关河第 1 层）

必须逐项显示，不许只给一句状态：

| 项 | 显示 | 判据 |
|---|---|---|
| 指数点位 | 基准收盘 | 直接取 |
| 均线排列 | 5/10/20/120 日线的顺序与方向 | 多头排列 / 空头排列 / 缠绕 |
| 五均线开关 | 收盘是否站回 5 日线，站了几天 | 站回 = 短线回暖确认；站不上只是反弹 |
| 均线缠绕 | 5/10/20 三线最大间距百分比 | 间距 < 1.5% 记「缠绕，等变盘」 |
| 量能 | 今日成交额、近 5 日 vs 前 5 日 | 缩量 / 平量 / 放量（±10% 为平） |
| 缺口 | 近 20 日未回补的跳空位置 | 上方缺口未补 → 多头没信心 |
| 空间 | 距前高、距前低、上下空间比 | 赔率 = 向上空间 ÷ 向下空间，只描述位置 |
| 波动 | 20 日 vs 60 日实现波动 | 抬升 → 总仓位下调 10 个百分点 |

输出一句结论，格式：「空头排列 + 缩量 + 距前低 0.8%，没放量急杀，是阴跌不是恐慌」。
判定表（走这一条，不另立标准）：

| 收盘 vs 60 日线 | 5 日线 vs 20 日线 | 状态 | 总仓位上限 |
|---|---|---|---|
| 上方 | 上方 | 上行趋势 | 85% |
| 下方 | 下方 | 下行趋势 | 35% |
| 其余 | — | 震荡区间 | 65% |
| 20 日波动 > 60 日波动×1.25 | — | 追加「波动抬升」 | 再降 10 个百分点 |

#### 5.1.2 市场热度与情绪（沉关河第 4 层）

| 项 | 显示 | 判读 |
|---|---|---|
| 涨跌家数 | 上涨 / 下跌 / 平盘，上涨占比 | 占比 >55% 赚钱面广，<45% 偏窄 |
| 涨停 / 跌停 / 连板高度 | 家数与最高连板 | 跌停家数上升 = 情绪恶化 |
| 成交额与环比 | 金额与环比百分比 | 环比 −5% 以下记「缩量」 |
| 恐慌形态 | 是否放量急杀 | **只有放量急杀才算恐慌；缩量阴跌不算**（沉关河 #10） |
| 连续普跌天数 | 天数 | 连续 2–3 天普跌 = 短线试错窗口，不是加仓信号 |
| 地天板 / 天地板 | 有无及次数 | 情绪极端摇摆的标尺 |
| 情绪温度 | 0–100 与四项分项 | 情绪 40% + 涨跌家数 35% + 成交额 15% + 趋势 10% |

#### 5.1.3 资金动向（topnews 口径）

| 项 | 显示 | 说明 |
|---|---|---|
| 两市主力资金 | 净流入 / 净流出金额 | 日频，来自公开数据 |
| 两融 | 融资余额、融资净买入 | 日频 |
| 北向 | 不显示 | 2024-08 起不再盘中披露净流入，页面上要写明这一点，不要留空 |
| 板块成交占比 | 各行业占全市场成交额 | 占比 >15% 记「过热」 |

#### 5.1.4 隔夜与消息（topnews）

- 隔夜：美股三大指数、A50 期指、原油黄金铜。**只算开盘扰动，不改 A 股自身周期**（沉关河：外围暴跌只影响开局，是踏空者补票机会）。
- 消息：政策 / 财联社快讯，给情感分（−1 ~ +1）与重要性（1–10），只列重要性前 3。
- 宏观事件窗口：议息、CPI、重要会议前 48 小时标记「静默期，仓位不增不减」。

#### 5.1.5 国家队

六类宽基最新份额、较上次增减、近四周方向。**近四周按日期回溯 25 天**，不按条数取（日频数据取 4 条只有 4 天）。
只当背景：影响总仓位 ±5 个百分点以内，不破上下限；单期变化 >15% 标「仅展示，不作判断」。

实现：`signals/market_regime.py`（状态、上限、位置赔率）、`rsRenderMarket()`（渲染）、`nationalTeamTable()`、`marketOutlook()`（情绪与定性，三部分共用同一份）。

### 5.2 组合情况

四块：板块强弱与评级、组合覆盖度、集中度、与市场是否一致。

#### 5.2.1 板块强弱评分（拐点体系四维）

板块强度 = 技术面 40% + 资金面 25% + 政策面 20% + 情绪面 15%，每项 0–100。

| 维度 | 取什么 | 缺失处理 |
|---|---|---|
| 技术面 40% | 该行业代表 ETF 的周线 MACD 方向 + 5/10/20/30 周均线排列 + 是否站上 20 周线 | 缺 → 权重按已有项折算 |
| 资金面 25% | 板块成交占比变化（近 5 日 vs 前 5 日）+ 主力净流入天数 | 同上 |
| 政策面 20% | 政策热度表里该主题的热度与变化 | 无对应主题记缺失 |
| 情绪面 15% | 当日涨跌幅 + 涨跌家数占比 | 同上 |

缺项不直接不算，按比例分给已有项（例缺政策面：技术 40→50、资金 25→31、情绪 15→19），标题旁标「缺 1 项」。

板块评级与上限（与个股同一套分档，便于比较）：

| 综合分 | 评级 | 单板块上限 |
|---|---|---|
| ≥85 | S | 25% |
| 75–84 | A | 20% |
| 60–74 | B | 10% |
| 50–59 | C | 5% |
| <50 | D | 0%（已有持仓只保留观察，不加） |

#### 5.2.2 组合覆盖度（解决"组合跟不跟得上"）

| 判断 | 做法 |
|---|---|
| 主线是谁 | 取 `rotation.leaders` + 政策热度前 2，记前三个方向 |
| 组合覆盖了没有 | 把组合按行业暴露与主线对照 → 覆盖 / 低配（<5%）/ 未覆盖 |
| 主线是否过热 | 板块成交占比 >15% → 标「过热」，即便覆盖也不加 |
| 有没有反包证据 | 该板块是否「扛过分歧后再次反包」；没有证据就写「未确认」 |

输出三句：「覆盖了 X（占比 a%）；缺 Y（占比 0%），受额度限制只观察；Z 已过热，不加」。

#### 5.2.3 集中度

| 指标 | 公式 | 提示线 |
|---|---|---|
| 最大板块 | max(暴露) | ≥25% 记超配，≤5% 记低配 |
| 前三大合计 | top3 之和 | >60% 记集中 |
| 持有只数 / 有效只数 | 只数 / 1÷HHI | — |
| 现金比例 | 现金 ÷ 总资产 | 下限 5% |
| 同一主题合并 | 半导体+科创+存储 这类合并计算 | 合计 ≤35% |

#### 5.2.4 与市场是否一致 ⓘ

三条判断，逐条给结论，标题右侧 ⓘ 可展开计算思路：

1. 最大暴露板块是否属于当前主线（跳过「未覆盖」「其他」）。
2. 超配（≥25%）与低配（≤5%）清单。
3. 走弱（板块评级 C/D）但仍有暴露（≥10%）的清单 → 逐条给收紧方向。

ⓘ 展开内容：写清输入字段、三条判断的阈值、缺项怎么处理、以及「这条判断怎么约束下一层」（走弱板块的个股不得加仓）。

冲突处理：判定走弱但该只动作为加仓 → 标橙，写「裁决：不新增，降级为观察」。

#### 5.2.5 纪律闸门（拐点体系，可直接执行）

| 闸门 | 规则 | 页面表现 |
|---|---|---|
| 单板块止损 | 板块层面亏 −5% | 无条件减该板块全部差额 |
| 单只硬止损（延5切10） | 跌破 10 日线：观察；跌破 20 日线且 2 日不收回：减半；跌破 30 日线且 2 日不收回：清差额；跌破 60 日线：立即 | 落在个股「执行位」 |

实现：`rsSectorExposure()`、`rsRenderSector()`、`portfolioRead()`、`sector_weights`（行业权重唯一来源）。

## 6. 第三部分 市场洞察及方向

定位：给位置、给冷热、给三种走法，不给「明天涨跌」。

### 6.1 今日定性（时段感知）

时段：盘前 05:00–09:25 / 盘中 09:30–11:30、13:00–15:00 / 午盘 11:30–13:00 / 盘后 / 周末 / 假日。
时段只决定「看什么」：盘前看隔夜与开盘预判，盘中看量能承接，盘后看次日与结构确认。

定性打分：大盘状态 ±2、5 日线与 20 日线关系 ±1、上涨家数占比 ±1、情绪分 ±1；|合计| ≥2 才给偏多/偏空，否则震荡。
下面必须列三条依据，每条带数字。三条依据要覆盖不同维度（位置、量能、情绪），不许三条都讲均线。

### 6.2 情绪与主线

- 涨停/跌停/连板高度、成交额与环比、恐慌形态、连续普跌天数（与 5.1.2 同一份数据，不另算）。
- 主线：写出名字，附三条判据——分歧节点、首次分歧是否已过、次日是否不破 5 日线；三条齐了才写「反包确认」。
- 落后方向：注明「没跌够的不追反弹」。
- 先跌先稳：列先跌板块与是否先企稳。

### 6.3 情景与触发

三行表：情景 / 触发条件 / 当前距离 / 对应动作。

| 情景 | 触发 | 动作 |
|---|---|---|
| 偏弱延续 | 收盘跌破近 120 日最低 | 按差额分批减，不抄底 |
| 震荡修复 | 在前低与 20 日线之间 | 只调结构，不加总仓 |
| 转强确认 | 站上 20 日线且 5 日线上穿 20 日线 | 差额可执行 |

触发值必须是真实价位，不许写「20 日线 ×0.96」。
每行写「当前距离」：还差几个百分点、几个价位。

### 6.4 新方向候选

筛选：观察池 → 去掉已持有 → 只留板块评级 B 及以上 → 近 5 日不弱于大盘 → 同类只留一只 → 看剩余额度。
额度闸门：剩余额度 <3 个百分点或目标仓位表缺失 → 建议一律「观察」并说明原因。
候选不得内置固定名单；不得在没额度时写「可分批」；不得推荐不碰名单里的方向。

## 7. 一致性与关联度（你问的四件事）

### 7.1 决策唯一入口

**唯一出口是目标仓位表**。差额 = 目标仓位 − 现在仓位；动作由差额与确认条件派生；订单由动作派生。
页面上任何地方出现动作（表格、个股卡、点评、洞察），都必须与它一致；不一致以它为准，并把不一致标出来。

### 7.2 规则卡的位置

规则卡（`config/methodology.yaml` 与 `methodology.decide`）只做两件事：

1. 数据闸门：数据不足就 ABSTAIN，不给动作。
2. 最早减仓时点：跌破关键位后允许提前减，但不改变目标仓位的大小。

规则卡**不覆盖目标仓位**。这样"上下两套结论"从源头消失：规则只决定「什么时候可以动」，目标仓位决定「动到多少」。

### 7.3 组合覆盖

组合层输出三件事，供个股与点评引用：

- 主线的覆盖情况（覆盖 / 低配 / 未覆盖）
- 板块评级与单板块上限
- 超配、走弱仍有暴露的清单

个股加仓需要同时满足：该板块评级 ≥B、组合未超单板块上限、个股确认条件 ≥2 条。缺一条就不加，并在卡片写明缺哪条。

### 7.4 执行后估算

执行后仓位、现金、费用**只能由订单派生**（同一函数、同一份数量），不做第二遍估算。
页面显示为一行的说明，不单独做卡片；数值与明细表逐行相加必须相等。

### 7.5 持仓分析的位置

分析层是解释层：**只引用，不判断**。

- 个股卡片的一句话结论 = 表格里的动作。
- 点评里的每一句 = 某一层的结论摘要。
- 洞察里的定性 = 与 5.1 用同一份数据算出的同一个值。

### 7.6 一处数字，一处算法

| 数字 | 唯一算法 | 出现在 |
|---|---|---|
| 总仓位上限 | 5.1.1 判定表 | 环境、点评、组合 |
| 板块评级 | 5.2.1 四维加权 | 组合、个股、候选 |
| 单只评级 | 5.3.1 + 5.3.2 | 个股、明细表 |
| 目标仓位 | 8.4 | 明细表、个股、点评 |
| 差额与动作 | 8.5 | 明细表、个股、点评 |
| 数量 / 挂单价 / 费用 | 8.6，`orderTicket` | 明细表、个股 |

### 8.3 降级语义

| 状态 | 含义 | 页面 |
|---|---|---|
| OK | 全链路成功 | 正常 |
| 降级 | 非关键字段缺失 | 顶部提示 + 缺失处写「缺失」 |
| 放弃 | 关键数据不足 | 只显示事实，不给动作 |
| 演示 | 离线快照 | 顶部横幅，不得当真实数据 |

### 8.4 目标仓位

```
单只基础 = 单只上限 × 趋势系数（周线多头 1.0 / 金叉 0.9 / 粘合 0.7 / 空头 0.35）
目标仓位 = min(单只上限, 单板块上限, 总仓位上限 × 单只基础 ÷ Σ单只基础)
目标合计 < 总仓位上限时，差额留现金；不为用满额度倒推动作
```

### 8.5 差额与动作

```
差额 = 目标仓位 − 现在仓位
|差额| < 3 个百分点               → 持有
差额 > 3 且 周线向下              → 等待（写明等什么信号）
差额 > 3 且 加仓确认不足 2 条      → 等待确认
差额 > 3 且 确认 ≥ 2 条           → 加仓
差额 < −3 且 周线空头或日线弱      → 减仓，按 50/30/20 分批
差额 < −3 其余                   → 先减一半差额
```

### 8.6 下单数量、挂单价、费用

```
挂单价  = 买入：现价 × 1.0001；卖出：现价 × 0.9999
建议数量 = 向下取整（总资产 × 目标仓位% ÷ 挂单价 ÷ 100）× 100
本次操作 = 建议数量 − 现在数量
首批     = 减仓时 min(|本次操作|, max(5% 总资产折份, |本次操作|/3))
费用    = max(5 元, 成交额 × 0.5bp) + 成交额 × 1bp     （ETF 免印花税）
```

## 9. 四个 skills 的运行逻辑与取用清单

这一章回答「方法从哪来」。每条都注明：它怎么做、我们怎么用、哪条不照搬、为什么。

### 9.1 沉关河（交易思维）

**运行逻辑**：先看大盘定仓位 → 看板块定方向 → 看个股定动作 → 看均线定出局。
取数是四层：大盘（指数点位、5/10/20/120 日均线排列与斜率、近 5 日量能对比、跳空缺口、离前高前低空间）→ 板块（谁先跌谁先稳、近半月量能、是否扛过分歧后反包）→ 个股（底部震荡 1–3 个月、放量突破震荡区上沿、缩量回踩不破）→ 情绪（涨跌家数、连板高度、跌停家数、成交额、看空比例）。
输出固定：一句结论 → 一句定性 → 编号 2–3 点理由 → 怎么做（仓位/买点/止损）→ 一句收口；每段 ≤3 行。

**我们取用的**

| 取用 | 落在哪 |
|---|---|
| 四层顺序（大盘→板块→个股→均线） | 第 3 章五层链、5.1→5.2→5.3 顺序 |
| 大盘七项取数（含 120 日线、缺口、空间比、缠绕） | 5.1.1 大盘位置 |
| 五均线开关 | 5.1.1「站回 5 日线才算回暖」 |
| 缩量下跌不算恐慌，放量急杀才算 | 5.1.2 恐慌形态 |
| 连续普跌 2–3 天是试错窗口 | 5.1.2，写明「不是加仓信号」 |
| 主线要扛过分歧后反包 | 5.2.2、6.2 三条判据 |
| 先跌先稳 | 5.2.2、6.2 |
| 均线纪律（10/20/30 日出局） | 5.3.6 执行位 |
| 3 日 10% 先保护利润 | 5.3.6 兑现 |
| 单票试错 ≤10% | 目标权重与单只上限取小 |
| 结论先行、短句、风险收口 | 4.2 点评写法 |
| 不编数字，取不到就说缺 | 全站缺失语义 |

**不照搬的**

- 「主力/筹码/吸筹」这类主体推断：ETF 没有单一大股东等价物，页面上只描述量价形态，不写"主力在吸"。
- 他自相矛盾的两套止损口径（10 日线无条件 vs 20 日线才算放弃）：我们只取一套——收盘连续 2 日跌破才算，写进 5.3.6，不并列。
- 「看空比例」投票数据：没有稳定来源，不显示。

### 9.2 拐点体系（A 股 ETF 大波段）

**运行逻辑**：三层嵌套——宏观层定总仓位上限，中观层定板块方向，微观层定进出时点。
选品用「铁三角」：月线底部结构 40 + 周线趋势确认 30 + 基本面/资金面共振 30，总分 ≥75 才重仓，<60 只做观察仓，<50 不持有。
月线 20 月线是楚河汉界：站上进入可重仓区，站下只做反弹。
输出规范四条：不幻想（标数据来源与时间）、不讨好（该清就说）、不摇摆（结论与评分一致）、可校验（每个结论附指标）。

**我们取用的**

| 取用 | 落在哪 |
|---|---|
| 三层嵌套 | 第 3 章 L1/L2/L3 |
| 20 月线分界 | 5.3 三周期、5.3.1 月线项 |
| 底部/顶部双评分卡 | 5.3.1、5.3.2 |
| 评级与仓位上限 S25/A20/B10/C5/D0 | 5.2.1、5.3.3 |
| 板块强度 = 技术40/资金25/政策20/情绪15 | 5.2.1 |
| 成交占比 >15% 记过热 | 5.1.3、5.2.2 |
| 延 5 切 10 止损 | 5.3.6 |
| 加仓需 ≥2 条件 | 5.3.6、8.5 |
| 减仓三批 50/30/20 | 5.2.5、明细表首批 |
| 单板块止损 −5% | 5.2.5 |
| 阶梯止盈 25/40/50 | 5.3.6 |
| 不碰名单（军工/传媒/游戏/次新） | 6.4 候选过滤 |
| 宏观事件前 48 小时静默 | 5.1.4、顶部提示 |
| 结论与评分一致、可校验 | 第 7 章一致性 |

**改动的**

- D 级上限 0% → 我们留 ≤3% 观察仓：A 股跳空多，一次清零常卖在最低点；写明「只保留观察，不加」。
- 评分卡里估值、领先股、景气、资金四项暂无数据源 → 标「未接入，按已有项折算」，不编分。
- 「不碰名单」保留为候选过滤，不清仓已有持仓（避免一刀切卖出）。

### 9.3 topnews（舆情与资金）

**运行逻辑**：按交易时段采集（盘前/盘中/午盘/盘后/周末/假日），采美股、期货、财联社快讯、宏观、主力资金与两融；对每条新闻算情感分（−1~+1）与重要性（1–10），做板块关联；最后给出「市场定性 + 情感分 + 影响等级」一行结论，并给保守/稳健/激进三档建议。

**我们取用的**

| 取用 | 落在哪 |
|---|---|
| 时段感知（六档） | 6.1 |
| 情感分与重要性分级 | 5.1.4 消息 Top3 |
| 主力资金 + 两融口径 | 5.1.3 |
| 北向已停披露要写明 | 5.1.3 |
| 隔夜美股/A50/商品 | 5.1.4 |
| 定性一行结论的写法 | 6.1 |

**不照搬的**：三档风格建议（保守/稳健/激进）——我们的额度由环境层统一给，不给三套并存建议，避免读者按最激进的一套执行。

### 9.4 量化平台（回测与执行口径）

`orderTicket` 参考实现：

```javascript
function orderTicket(r, targetW, total){
  if(targetW==null || r.last==null) return {note:'目标或价格缺失'};
  var side = targetW > r.weight ? 'buy' : 'sell';
  var limit = r.last * (side==='buy' ? 1.0001 : 0.9999);
  var shares = Math.floor(total*targetW/100/limit/100)*100;   // 向下取整，100 份为一手
  var delta = shares - r.shares;
  if(Math.abs(delta) < 100) return {delta:0, note:'不足一手'};
  var amt = Math.abs(delta*limit);
  var fee = Math.max(5, amt*0.00005) + amt*0.0001;
  return {shares:shares, delta:delta, limit:limit, fee:fee, side:side};
}
```

## 13. 边界

- 缠论为分型→笔→中枢的简化实现，不含线段与多级别递归，图注必须写明。
- 概率是历史相似条件的统计，不是预测；样本少不显示，不参与决策。
- 行业权重来自公开披露，拿不到就写「未覆盖」，不猜。
- 挂单价是限价保护，不保证成交；所有数字都是执行参考，不是承诺。
- 沉关河、拐点等方法的阈值是**他们的经验值**，搬到 ETF 上只作规则来源，不当作已验证收益；回测结论必须带「历史不代表未来」。
- 持仓只在本机解密，任何情况下不写入仓库。
