# 持仓分析页 · 施工指南

> **设计文档，不用于每日刷新。** 每日刷新只看仓库根目录的 `AGENTS.md`，执行 `bash scripts/daily.sh`。

从零搭建 `web/index.html` 第 5 页「持仓分析」的完整说明：每一块显示什么、判断怎么来、没有数据怎么显示、写在哪、怎么验。
不构成投资建议，不预测点位。

**三条底线**

- 页面不写死业务数字：行业权重、候选名单、评级分数线、点评句子，全部由数据与规则算出来。
- 每个数字都有出处：哪个文件、哪个字段、哪次运行。
- 一句结论里的数字，必须能在同一页找到那个数；找不到就不写这句话。

**验收口径**：任意一句结论单独拿出来，读者都能在同一页找到支撑它的数字；找不到就是不合格。

## 1. 页面结构

### 1.1 三部分，各回答一个问题

| 部分 | 回答 | 读者动作 | 篇幅 |
|---|---|---|---|
| 一、持仓概况 | 我有多少钱、赚亏多少、今天买卖什么、多少份什么价 | 直接照着下单 | 一屏内能看完 |
| 二、持仓分析 | 市场什么环境、组合跟不跟得上、每只为什么留或减 | 判断要不要改计划 | 可以长，越往下越细 |
| 三、市场洞察及方向 | 大盘在什么位置、情绪冷热、三种走法怎么办、还能看什么 | 做下周打算 | 中等 |

顺序不可倒：先给结论，再讲理由，最后讲远景。理由只能收紧结论，不能推翻结论。

### 1.2 一屏原则

概况只放三类东西：四个数字、一段点评、一张能下单的表。
不放：仓位条、持仓类别饼图、执行后估算卡、今日建议卡、表下小字说明、收益曲线。这些内容已经在表里或点评里，重复即噪音。

### 1.3 命名

| 写法 | 例子 |
|---|---|
| 名字（代码） | 沪深300ETF（510300）、科创50ETF（588000） |
| 只写代码 | 仅限表格「代码」列与函数参数 |
| 行业名 | 用板块快照里的名字：电子、银行、电力设备… |

首次出现写全，后文可只写名字。禁止只给一串数字让读者自己查。

### 1.4 视觉重心

- 概况：数字大、留白多，表格行高足够点得准。
- 分析：分层小标题明显（1. 市场环境 / 2. 组合情况 / 3. 个股分析），每层开头一句话结论，再展开证据。
- 洞察：表格化（情景三行、候选一表），少用长段。

## 2. 决策链：五层，一个出口

### 2.1 旧版为什么割裂

旧页面不是数据不够，而是四套判断同时在跑：

| 位置 | 它在说什么 | 谁听谁的 |
|---|---|---|
| 规则卡（methodology） | 这只触发减仓 | 不知道有没有人执行 |
| 目标仓位表（plan_v3） | 这只该占 8.9% | 与规则卡的动作不保证一致 |
| 执行后估算 | 执行完还剩多少仓 | 自己算一遍，与表里数量对不上 |
| 持仓分析（技术） | 日线转强、缠论买点 | 与上面的减仓正好相反 |

修复只有一条：把动作收敛到一个出口，其他层只能收紧，不能另起一套。

### 2.2 五层与唯一出口

```
L0 数据闸门   行情/持有/行业权重/舆情是否可用；不可用就只说事实
   ↓
L1 环境层     大盘状态 → 总仓位上限（35 / 65 / 85，可 ±5）
   ↓
L2 板块层     板块评分 → 板块评级 → 单板块上限、主线覆盖度
   ↓
L3 个股层     三周期 + 双评分卡 + 结构 → 单只上限（25/20/10/5/0）
   ↓
L4 组合层     目标仓位 = min(总上限分摊, 单只上限, 单板块上限) → 差额 → 动作
   ↓                ↓
   ↓          唯一出口：目标仓位表 → 订单（数量、挂单价、费用）
   ↓
L5 解释层     点评、逐只解读、洞察；只能引用 L1–L4 的结论
```

三条传导规则：

1. 额度只能收紧：L2 拿到的总上限，只能往下压，不能加。
2. 下层不许翻案：L3 技术再强，若 L2 判该板块 D 级（上限 0），不得加仓。
3. 解释层不许自创：L5 的动作必须等于 L4；想说的不同，先改 L4。

### 2.3 每层做什么

| 层 | 输入 | 输出 | 不许做 |
|---|---|---|---|
| L0 | 行情、持有、行业权重、舆情、国家队 | 可用 / 降级 / 放弃 + 缺失清单 | 用估算值填空 |
| L1 | 指数日线、涨跌家数、成交额、隔夜、资金、国家队 | 大盘状态、总上限、环境定性 | 指定买哪只 |
| L2 | 行业代表 ETF 周线、板块成交占比、政策热度、当日涨跌 | 板块四维分、评级、覆盖度、过热标记 | 直接给个股数量 |
| L3 | 个股月/周/日线、MACD、量比、相对强度、结构 | 三周期状态、评分、评级、执行位 | 决定目标仓位 |
| L4 | 上限、评分、当前仓位、现金、约束 | 目标仓位、差额、动作、订单 | 写解释长文 |
| L5 | 以上全部 | 点评、逐只解读、情景 | 改任何数字 |

### 2.4 冲突裁决表（页面显示「冲突 + 裁决」）

| 冲突 | 裁决 |
|---|---|
| 日线转强 / 周线空头 | 以周线定方向，日线只定节奏，不加仓 |
| 月线转换 / 周线空头 | 按周线，不提前埋伏 |
| 目标仓位高于现在 / 周线向下 | 不买，改为等待，写明等什么 |
| 单只上限 / 板块上限 / 总上限 | 三者取小 |
| 结构上出现买点 / 目标是减 | 不做多，结构只用于卖出时点 |
| 概率偏低 / 评分较高 | 概率只作参考，不改评级 |
| 舆情或国家队 / 仓位区间 | 最多 ±5 个百分点，不破上下限 |
| 板块走弱 / 该只动作是加仓 | 标橙，降级为「观察」，不新增 |
| 规则卡触发减仓 / 目标仓位仍高 | 以目标仓位为准；规则卡只管最早减仓时点与数据闸门 |

## 3. 第一部分 持仓概况

```
① 四个数字
② 今日点评
③ 持仓明细表
```

### 3.1 四个数字

| 卡 | 大字 | 小字 | 怎么算 | 缺数据 |
|---|---|---|---|---|
| 总资产 | 金额 | 其中现金多少 | 所有持仓市值 + 现金 | 「—」，小字写缺哪只价格 |
| 持仓市值 | 金额 | 持有几只 | Σ 最新价 × 份额 | 同上 |
| 浮动盈亏 | 百分比 | 金额 | Σ（最新价 − 成本价）× 份额 | 缺成本只显示「—」 |
| 当日盈亏 | 百分比 | 金额 | Σ（最新价 − 昨收）× 份额 | 缺昨收显示「—」 |

赚红亏绿、零值灰；金额取整到元加千分位；比例两位小数。
百分比分母：浮动盈亏% = 浮动盈亏 ÷ 持仓成本（Σ 成本价×份额）；当日盈亏% = 当日盈亏 ÷ 昨日持仓市值（Σ 昨收×份额）。不用总资产做分母，现金会稀释数字。
无持仓：只显示总资产与现金，后两卡写「暂无持仓」。

实现：`calcPort()` 计算，`kpi()` 渲染。

### 3.2 今日点评

点评是整个页面的判断汇总，不是数据罗列，也不是把下面三块各抄一句。它要把**大盘、行业、资金、国家队、宏观、组合结构、个股结构**放在一起权衡，说清今天到底发生了什么、我们该做什么、什么情况下改主意。

**不设字数、不设段数、不设句式模板。** 写得长没关系，但每一句都要有依据；宁可多写两句把因果讲透，也不要凑一个漂亮的排比。要像人话——像一个人看完盘之后跟你说的话，不是公告。

#### 3.2.1 必须综合的七类信息

| 类别 | 取什么 | 它在判断里起什么作用 |
|---|---|---|
| 大盘位置 | 收盘与 5/10/20/60/120 日线关系、均线排列与斜率、站回 5 日线几天、均线缠绕间距、近 20 日缺口 | 定总仓位上限，决定「能不能进攻」 |
| 量能 | 今日成交额、近 5 日 vs 前 5 日、放量还是缩量、有没有放量急杀 | 区分「恐慌」与「阴跌」，决定敢不敢试错 |
| 空间与赔率 | 距前高、距前低、上下空间比 | 决定「这个位置值不值得扛」 |
| 行业与主线 | 主线是谁、有没有扛过分歧后反包、落后方向、板块成交占比是否过热、先跌的有没有先稳 | 决定「方向对不对」，决定组合该往哪偏 |
| 资金 | 两市主力净流入、两融 | 决定「背景是帮忙还是拆台」，只调倾向 ±5 |
| 宏观与隔夜 | 隔夜美股/A50/商品、政策与会议窗口、事件静默期 | 决定「今天是不是特殊日子」，多数情况只算开盘扰动 |
| 自身 | 当前仓位 vs 上限、最大暴露板块、评级分布、最弱一只、现金比例、今日订单 | 决定「动作落在哪只、多少量、什么价」 |

缺哪一类就写「缺」，不许用别的数据顶替，也不许因为缺就跳过——缺本身就是信息（说明结论要保守一档）。

#### 3.2.2 推理顺序

```
1) 今天是什么日子     → 时段、隔夜、事件窗口（有没有静默期）
2) 大盘处在什么阶段   → 状态、上限、量能性质、位置赔率
3) 今天的主要矛盾在哪 → 是环境压着不能动，还是结构错了要换，还是执行没跟上
4) 行业给了什么信号   → 主线是否成立、有没有过热、落后是否补跌
5) 资金背景帮不帮忙   → 主力、两融、国家队（只调倾向）
6) 我们自身偏差多少   → 仓位 vs 上限、板块暴露 vs 主线、最弱一只
7) 今天动什么         → 哪只、多少份、什么价、分几批
8) 什么情况下改判     → 阈值 + 后果，两条以上
```

顺序不能跳。跳过 2 直接说 7，就是旧版那种「上面一套规则、下面一套技术」的割裂。

#### 3.2.3 综合判断怎么下（几种常见组合）

深度不是靠形容词，是靠把几类信息放在一起对照。以下是页面上最常遇到的情形，写点评时按对应方式下结论：

| 组合 | 现象 | 结论怎么写 |
|---|---|---|
| 指数跌 + 缩量 + 距前低近 | 阴跌，没有放量急杀 | 「这是阴跌不是恐慌」→ 不加，按差额分批减，等放量急杀或站回 5 日线再谈 |
| 指数跌 + 放量急杀 + 跌停增加 | 恐慌形态成立 | 「恐慌成立，但恐慌是短线试错窗口不是加仓信号」→ 只允许小仓试错（≤5%），且要写明失效位 |
| 指数弱 + 主线板块放量领涨 | 结构强于指数 | 「指数不给力，但主线在自证」→ 只做结构切换，不加总仓；主线已过热则不追 |
| 国家队增持 + 技术破位 | 背景与价格相反 | 「以价格为准，国家队只调倾向」→ 上限最多 +5 个百分点，不改变破位减仓 |
| 宏观利好 + 量能萎缩 | 利好没有被资金接住 | 「只算开盘扰动，不改周期」→ 不加，等量能回来 |
| 情绪分偏暖 + 涨停家数下降 + 跌停增加 | 情绪与价格背离 | 「情绪先于价格转弱」→ 提前减一档，不等破位 |
| 组合超配方向正是过热板块 | 结构风险 | 「超配且过热，先减这一块」→ 按差额减，写明减到多少 |
| 最弱一只评分 D 但仓位最大 | 结构错配 | 「最大的仓位压在最低的分上」→ 优先减它，不是减评分高的 |
| 只剩现金没方向 | 空仓或轻仓 | 「没方向就不动，等主线自证」→ 写清等什么信号，不硬找标的 |

#### 3.2.4 示例（下行趋势中的减仓日，实际每天不同，长度不固定）

> **今日基调：先降后看。**
>
> 大盘收在 4016.29，5 日线 4050.23 压在 20 日线 4069.52 下面，60 日线 4352.11 还在头顶上，均线是标准的空头排列。20 日年化波动 16.97%，60 日是 15.16%，波动没抬升，说明这不是崩，是磨。

>

>

> 价格是执行价，不保证成交。

这段示例里用到的每类信息都能在本页找到：大盘数值在环境块、板块过热在组合块、国家队在环境块、仓位与差额在明细表、评分与周线状态在个股卡。这就是「综合」的样子——不是把六个数并列念一遍，而是让它们互相解释。

#### 3.2.5 不写什么

- 不写「注意风险」「保持谨慎」「密切关注」「综合来看」「整体合理」「酌情处理」「有望」「可能上涨」「保证」「必涨」「稳赚」「胜率」。
- 不写没有数字支撑的形容词（「情绪偏暖」要给出分数，「资金活跃」要给出金额）。
- 不给目标价，不预测点位，不写「概率很大」这类没有样本量的判断。
- 不写操作建议之外的心理按摩。要写心态就写可诊断的那种：这次是信号变了，还是只是自己看着难受。
- 结尾固定一句：「价格是执行价，不保证成交。」

#### 3.2.6 生成方式与实现

| 项 | 位置 |
|---|---|
| skill 契约 | `skills/portfolio-brief/SKILL.md` |
| 产出文件 | `data/brief.json`（`data_date` + `conclusion` + `blocks[]`，每块 `k`/`v`/`refs`） |
| 读取与校验 | `webgen._brief()`：日期一致、结构合法、不含禁词 |
| 页面兜底 | `rsBriefSections()` 现场生成，`rsRenderBrief()` 渲染 |
| 来源标注 | 不标来源标签；点评每句的数字都能在同页核对 |
| 校验失败 | 该块不渲染，其余事实照常显示 |

主来源是 skill，兜底是引擎。两者都必须遵守 3.2.1–3.2.5；不同只在于 skill 可以写得更像人话，引擎只能按模板拼数字。

### 3.3 持仓明细表

## 4. 第二部分 持仓分析

读法：三层递进，每层开头一句话结论，然后给证据，最后一行写「这一层约束了下面什么」。

```
1. 市场环境  → 得出：总仓位上限、能不能进攻
2. 组合情况  → 得出：方向对不对、额度怎么分、哪块要收
3. 个股分析  → 得出：这一只怎么下手（量、价、止损）
```

### 4.1 市场环境

四个小块：大盘位置、热度与情绪、资金动向、隔夜与消息；末尾附位置与赔率。
（国家队动向已按你的要求移出持仓分析，只在 p1 市场概况保留最新一期作背景。）

#### 4.1.1 大盘位置

必须逐项显示，不许只给一句状态：

近 120 日最高最低、距高点、距低点、向上空间、向下空间、赔率。

#### 4.1.8 七项怎么读成一句话

数据摆完不算完，要给综合判读。判读方式固定为「现象 → 性质 → 该怎么办」：

| 现象 | 性质 | 该怎么办 |
|---|---|---|
| 指数在 60 日线下方 + 5 日在 20 日下方 + 缩量 | 空头趋势里的阴跌 | 上限压到 35%（波动抬升再降 10），只减不加 |
| 同上但出现放量急杀、跌停增加 | 恐慌形态 | 恐慌是短线试错窗口，不是加仓信号；试错 ≤5%，写失效位 |
| 均线三线缠绕、间距 <1.5% | 变盘前 | 不压方向，等站回 5 日线 3 日再定 |
| 距前低 <1%、距前高 >15% | 位置便宜但没确认 | 只做差额调整，不因为「便宜」加仓 |
| 上方缺口未补 + 缩量 | 多头没信心 | 反弹只做减法 |
| 涨跌家数 >55% 但指数不涨 | 结构性行情 | 只做结构，不加总仓 |

→ 约束下一层：这一块产出总上限与环境定性，组合层的总仓位、候选的额度都由它派生。

实现：`signals/market_regime.py`（状态、上限、均线、位置）、`rsRenderMarket()`、`nationalTeamTable()`、`marketOutlook()`。

### 4.2 组合情况

四块：板块评分与评级、覆盖度、集中度、与市场一致性；末尾纪律闸门。

#### 4.2.1 板块评分（四维，0–100）

板块强度 = 技术 40% + 资金 25% + 政策 20% + 情绪 15%。

| 维度 | 取什么 | 缺失 |
|---|---|---|
| 技术 40% | 该行业代表 ETF 的周线 MACD 方向、5/10/20/30 周排列、是否站上 20 周线 | 权重按已有项折算 |
| 资金 25% | 板块成交占比变化（近 5 日 vs 前 5 日）+ 主力净流入天数 | 同上 |
| 政策 20% | 政策热度表里该主题的热度与变化 | 无对应主题记缺失 |
| 情绪 15% | 当日涨跌幅 + 涨跌家数占比 | 同上 |

缺项不直接不算，按比例分给已有项（例缺政策面：技术 40→50、资金 25→31、情绪 15→19），标题旁标「缺 1 项」。

评级与单板块上限（与个股同一套分档，便于比较）：

| 分 | 评级 | 单板块上限 | 处理 |
|---|---|---|---|
| ≥85 | S | 25% | 核心，回踩加 |
| 75–84 | A | 20% | 持有 |
| 60–74 | B | 10% | 中等，等升级 |
| 50–59 | C | 5% | 观察，不加 |
| <50 | D | 0% | 不加；已持有的按个股规则清到观察仓 |

#### 4.2.2 覆盖度（组合跟不跟得上）

| 判断 | 做法 |
|---|---|
| 主线是谁 | `rotation.leaders` + 政策热度前 2，取前三个方向 |
| 覆盖了没有 | 组合行业暴露 vs 主线 → 覆盖 / 低配（<5%）/ 未覆盖 |
| 主线过热没有 | 板块成交占比 >15% → 过热，即便覆盖也不加 |
| 企稳没有 | 板块指数是否收盘站回 5 日线；站不上只是反弹 |
| 有没有反包证据 | 是否「扛过分歧后再次反包」；没有证据写「未确认」 |
| 没跌够的 | 与同期跌幅最小者比较；没跌够的方向往往补跌，不追 |

输出三句：「覆盖了 X（占比 a%）；缺 Y（0%），受额度限制只观察；Z 已过热，不加」。

轮动信号（判断「要不要换方向」）：

| 信号 | 含义 | 动作 |
|---|---|---|
| 领涨板块滞涨 + 低位板块放量 | 轮动将至 | 减高位、配低位（受额度约束） |
| 领涨板块成交占比 >15% | 情绪过热 | 不加，考虑减 |
| 低位板块持续缩量 | 轮动条件不具备 | 不切换 |
| 高位板块龙头破位 | 主线可能切换 | 减高位 |

#### 4.2.3 集中度

| 指标 | 公式 | 提示线 |
|---|---|---|
| 最大板块 | max(暴露) | ≥25% 超配，≤5% 低配 |
| 前三大合计 | top3 之和 | >60% 记集中 |
| 持有只数 / 有效只数 | 只数 / 1÷HHI | — |
| 现金比例 | 现金 ÷ 总资产 | 下限 5% |
| 同主题合并 | 半导体+科创+存储合并算 | 合计 ≤35% |

#### 4.2.4 与市场是否一致 ⓘ

三条判断，逐条给结论，标题右侧 ⓘ 展开计算思路：

1. 最大暴露板块是否属于当前主线（跳过「未覆盖」「其他」）。
2. 超配（≥25%）与低配（≤5%）清单。
3. 走弱（评级 C/D）但仍有暴露（≥10%）的清单 → 逐条给收紧方向。

ⓘ 交互：标题右侧圆形图标，可键盘聚焦，`aria-label` 写「查看计算思路」；点击在区块内展开浅底说明，再点收起；不跳页、不弹层、不遮挡表格；移动端同样可用。
ⓘ 内容：输入字段、阈值、缺项处理、以及「这条判断怎么约束下一层」。

→ 约束下一层：走弱板块对应的个股不得加仓；未覆盖的主线只能通过候选观察，不直接买。

#### 4.3.1 进场检查（选股三步）

| 步骤 | 要看到什么 | 页面显示 |

| 跌破 10 月线 | 20 | 跌破 20 / 未跌破 0；视为大波段结束硬止损信号 |
| 周线死叉 | 15 | 死叉 + 破 30 周线 15 / 仅死叉 10 |
| 情绪过热 | 10 | 板块成交占比 >15% 或热搜密集 10 / 偏高 5 |
| 龙头破位 | 10 | 最强个股月跌 >20% 得 10；>10% 得 5 |

两张一起看：底部高 + 顶部低 = 可加；底部低 + 顶部高 = 减；两张中性 = 持。
未接入的项（估值、领先股、景气）标「未接入，按已有项折算」，不假装有分。

顶部风险决策矩阵（先按底部评分定评级上限，再按这里压低，取更严者）：

| 顶部分 | 处理 |
|---|---|
| ≥80 | 上限清零，按减仓三批出清 |
| 60–79 | 上限压到 5% 以下，设硬止损 |
| 40–59 | 上限减半 |
| <40 | 不动 |

#### 4.3.3 评级与上限

| 底部分 | 评级 | 单只上限 | 处理 |
|---|---|---|---|
| ≥85 | S | 25% | 核心，回踩加 |
| 75–84 | A | 20% | 持有 |
| 60–74 | B | 10% | 中等，等升级 |
| 50–59 | C | 5% | 观察，不加 |
| <50 | D | 0% | 只保留 ≤3% 观察仓，反弹减 |

D 档不清零：A 股跳空多，一次清仓常卖在最低；写清「只保留观察，不加」。
观察仓同样受板块上限约束：所属板块为 D 级（单板块上限 0）时三者取小，观察仓也不留。

顶部风险按 4.3.2 决策矩阵压低上限，页面标「顶部风险」。

#### 4.3.4 多空分界（按品种类型）

| 品种 | 分界指标 | 多头确认 | 空头确认 |
|---|---|---|---|
| 进攻型（科技/算力/半导体） | 20 日线 | 站稳 20 日线 + 量 >5 日均量 1.2 倍 | 跌破 20 日线 + 缩量 |
| 防御型（红利/公用/绿电） | 30 日线 | 站稳 30 日线（原文另要求股息率 >3%，当前未接入，不作硬条件） | 跌破 30 日线 |
| 周期型（资源/有色/黄金） | MACD 零轴 + 60 日线 | 零轴上方 + 站上 60 日线 | 零轴下方 + 跌破 60 日线 |

多空区域：站上 20 日线且 20 日线向上 = 多头区域；跌破且向下 = 空头区域；20 日线走平 + 反复穿越 = 转换，轻仓观望。
日线信号服从周线方向：周线向上，日线回踩是买点；周线向下，日线反弹是卖点。

#### 4.3.5 结构图（缠论，明确边界）

分型 → 笔 → 中枢 → 背驰 → 买卖点。

| 步骤 | 规则 |
|---|---|
| 分型 | 左右各 2 根的顶/底 |
| 笔 | 顶底交替、间隔 ≥4 根、幅度 ≥1.5% |
| 中枢 | 最近三段笔的重叠区间：上沿 = min(各段高)，下沿 = max(各段低)，上沿>下沿才有效 |
| 底背驰 | 价格创新低而 MACD DIF 抬高 |
| 买卖点 | 只标「底背驰（一类买点候选）」「回踩中枢上沿不破（三类买点）」「跌破中枢下沿（卖点）」 |

不做线段、不做多级别递归，图注写「简化实现」。不许出现「第 18 根买点」这类固定位置标注。

#### 4.3.6 概率

用「20 日涨幅 + 20 日波动」找历史上最相似的样本，按距离加权统计未来 5/20/60 日上涨占比，同时给样本数、样本区间、中位涨幅。
样本 <30 显示「样本不足」；概率不改评级、不改动作。

#### 4.3.7 执行位（把纪律写进价格）

先分仓位用途，再谈止损——两套口径不能混用：

| 仓位类型 | 适用 | 止损 |
|---|---|---|
| 交易仓 | 试错/波段，单票 ≤10%，评级 C/B | 收盘连续 2 日跌破 10 日线 → 出局 |
| 核心仓 | 评级 A/S，目标仓位 ≥10% | 破 20 日线 2 日减半；破 30 日线 2 日清差额；破 60 日线立即 |

其余（两类共用）：

| 项 | 规则 |
|---|---|
| 买点一 | 缩量回踩 5 日线或震荡区上沿不破 |
| 买点二 | 沉淀区再次突破新高；跌破 5 日线即出 |
| 加仓确认 | 站上 10 日线 / MACD 金叉 / 主力连续 2 日净流入，至少两条 |
| 兑现 | +25% 减 1/4；+40% 再减 1/4；+50% 清 |
| 短线（小仓） | 3 日 10%+ 先保护利润；30 分钟放量滞涨或次日冲高无力先出 |

#### 4.3.8 改判

每只必须写两条，带阈值：一条「转好怎么办」，一条「恶化怎么办」。
示例：「站上 20 日线且周线转多 → 评级重估，目标回到对应上限；收盘连续两日破 30 日线 → 卖出全部剩余差额」。

实现：`legScore()`、`rsRenderDetail()`、`rsChanOf()`、`rsDrawChart()`、`rsForecast()`。

## 5. 第三部分 市场洞察及方向

定位：给位置、给冷热、给三种走法，不给「明天涨跌」。

### 5.1 今日定性（时段感知）

时段：盘前 05:00–09:25 / 盘中 09:30–11:30、13:00–15:00 / 午盘 11:30–13:00 / 盘后 / 周末 / 假日。
时段只决定看什么：盘前看隔夜与开盘预判，盘中看量能承接，盘后看次日与结构确认。

打分：大盘状态 ±2、5 日线与 20 日线关系 ±1、上涨家数占比 ±1、情绪分 ±1；|合计| ≥2 才给偏多/偏空，否则震荡。
依据要覆盖不同维度（位置、量能、情绪），不要几条都讲均线。

### 5.2 情绪与主线

- 涨停/跌停/连板、成交额与环比、恐慌形态、连续普跌天数（与 4.1.3 同一份数据，不另算）。
- 情绪周期：恐慌 → 怀疑 → 确认 → 贪婪 → 疯狂五阶段，按特征对号入座写当前位置。它与「恐慌形态」是两回事：前者是周期位置，后者是当日量价形态。
- 主线：写名字 + 三条判据（分歧节点、首次分歧是否已过、次日是否不破 5 日线），三条齐了才写「反包确认」。
- 落后方向：注明「没跌够的不追反弹」。
- 先跌先稳：列先跌板块与是否先企稳。

### 5.3 情景与触发

三行表：情景 / 触发 / 当前距离 / 动作。

| 情景 | 触发 | 动作 |
|---|---|---|
| 偏弱延续 | 收盘跌破近 120 日最低 | 按差额分批减，不抄底 |
| 震荡修复 | 在前低与 20 日线之间 | 只调结构，不加总仓 |
| 转强确认 | 站上 20 日线且 5 日线上穿 20 日线 | 差额可执行 |

触发值必须是真实价位，不许写「20 日线 ×0.96」；每行写「当前距离」：还差几个百分点。

### 5.4 新方向候选

筛选：观察池 → 去掉已持有 → 板块评级 B 及以上 → 近 5 日不弱于大盘 → 同类只留一只 → 看剩余额度。
额度闸门：剩余额度 <3 个百分点或目标仓位表缺失 → 一律「观察」并说明原因。
不内置固定名单；没额度不写「可分批」；不含不碰名单里的方向。

## 6. 一致性与关联还有哪些必须对齐

### 6.1 决策唯一入口

唯一出口是目标仓位表。差额 = 目标 − 现在；动作由差额与确认条件派生；订单由动作派生。
页面上任何动作（表格、个股卡、点评、洞察）都必须与它一致；不一致以它为准，并把不一致标出来。

### 6.2 规则卡的位置

规则卡只做两件事：

1. 数据闸门：数据不足就放弃，不给动作。
2. 最早减仓时点：跌破关键位后允许提前减，但不改变目标仓位的大小。

规则卡不覆盖目标仓位。这样「上下两套结论」从源头消失：规则决定「什么时候可以动」，目标仓位决定「动到多少」。

### 6.3 组合覆盖

组合层输出三件事供下层引用：主线覆盖情况、板块评级与单板块上限、超配与走弱清单。
个股加仓需同时满足：板块评级 ≥B、未超单板块上限、个股确认条件 ≥2 条。缺一条就不加，并在卡片写明缺哪条。

### 6.4 执行后估算

执行后仓位、现金、费用只能由订单派生（同一函数、同一份数量），不做第二遍估算。
页面显示为一行说明，不单独做卡片；数值与明细表逐行相加必须相等。

### 6.5 三层传导实例（照着写就一致）

```
大盘：空头排列 + 缩量 → 上限 35%（现在 40.6%）
  ↓
板块：电子 72 分 B 级、占比 16.1% 过热 → 电子不加；红利 58 分 C 级 → 只观察
  ↓
个股：沪深300ETF 底部 38 分 D 级、周线空头 → 上限 0%，只留 ≤3% 观察仓
  ↓
组合：目标 3.0%，现 20.3%，差额 −17.3 → 减仓，分三批（50/30/20）
  ↓
订单：首批卖 12,800 份，挂 4.051，费用 ¥10.4
  ↓
点评：「先降后看……今天动两笔……改判……」
```

任一行改动，下面五行必须同步；不同步就是 bug，不是文风问题。

| 页面上的数 | 来源 | 缺失时 |
|---|---|---|

| 隔夜美股、A50、商品 | 隔夜快照 | 「未取到」 |
| 情绪分、消息分、重要性 | 舆情快照 | 「缺失」 |
| 主线与落后 | 板块轮动 | 「无主线数据」 |
| 板块成交占比与涨跌 | 板块快照 | 该列隐藏 |
| 行业权重 | `data/snapshot/index_sector_weights.json` | 「未覆盖（数据日 X）」 |
| 国家队份额 | `data/national_team.json` | 「未纳入」 |
| 目标仓位、评级、动作 | 目标仓位表 | 「目标缺失」 |
| 均线、MACD、量比、相对强弱 | 行情计算 | 该只「数据不足」 |
| 点评 | `data/brief.json`，缺则现场生成 | 回退并标来源 |

### 7.2 数据日期

顶部同时显示「行情日」与「持仓快照日」；两者不同必须提示。盈亏按行情日算，数量按快照日算。

### 7.3 降级语义

| 状态 | 含义 | 页面 |
|---|---|---|
| 正常 | 全链路成功 | 正常 |
| 降级 | 非关键字段缺失 | 顶部提示 + 缺失处写「缺失」 |
| 放弃 | 关键数据不足 | 只显示事实，不给动作 |
| 演示 | 离线快照 | 顶部横幅，不得当真实数据 |

### 7.4 目标仓位

```
单只基础 = 单只上限 × 趋势系数（周线多头 1.0 / 金叉 0.9 / 粘合 0.7 / 空头 0.35）
目标仓位 = min(单只上限, 单板块上限, 总上限 × 单只基础 ÷ Σ单只基础)
目标合计 < 总上限时，差额留现金；不为用满额度倒推动作
```

### 7.5 差额与动作

```
差额 = 目标仓位 − 现在仓位
|差额| < 3 个百分点           → 持有
差额 > 3 且 周线向下          → 等待（写明等什么）
差额 > 3 且 加仓确认不足 2 条  → 等待确认
差额 > 3 且 确认 ≥ 2 条       → 加仓
差额 < −3 且 周线空头或日线弱  → 减仓，50/30/20 分批
差额 < −3 其余               → 先减一半差额
```

### 7.6 下单数量、挂单价、费用

```
挂单价  = 买：现价 × 1.0001，向上进位到 0.001；卖：现价 × 0.9999，向下截断到 0.001
        （取整朝更优成交一侧，限价保护不被取整吃掉）
建议数量 = 向下取整（总资产 × 目标仓位% ÷ 挂单价 ÷ 100）× 100
本次操作 = 建议数量 − 现在数量
首批     = 减仓时 |本次操作| × 50%，向下取整到 100 份（第二批 30%、第三批 20%）
费用    = max(5 元, 成交额 × 0.5bp) + 成交额 × 1bp
        （0.5bp 为佣金、最低 5 元；1bp 为滑点估计；ETF 免印花税）
```

`orderTicket` 参考实现：

```javascript
function orderTicket(r, targetW, total){
  if(targetW==null || r.last==null) return {note:'目标或价格缺失'};
  var side = targetW > r.weight ? 'buy' : 'sell';
  var limit = r.last * (side==='buy' ? 1.0001 : 0.9999);
  limit = side==='buy' ? Math.ceil(limit*1000)/1000 : Math.floor(limit*1000)/1000;  // 取整朝更优成交侧
  var shares = Math.floor(total*targetW/100/limit/100)*100;   // 100 份一手，向下取整
  var delta = shares - r.shares;
  if(Math.abs(delta) < 100) return {delta:0, note:'不足一手'};
  var amt = Math.abs(delta*limit);
  var fee = Math.max(5, amt*0.00005) + amt*0.0001;
  return {shares:shares, delta:delta, limit:limit, fee:fee, side:side};
}
```

`rsChanOf` 参考实现（分型 → 笔 → 中枢）：

```javascript
function rsChanOf(highs, lows, closes){
  var n=highs.length, w=2, pv=[];
  for(var i=w;i<n-w;i++){
    var isH=true,isL=true;
    for(var k=i-w;k<=i+w;k++){
      if(highs[k]>highs[i]) isH=false;
      if(lows[k]<lows[i]) isL=false;
    }
    if(isH) pv.push({i:i,px:highs[i],kind:'H'});
    else if(isL) pv.push({i:i,px:lows[i],kind:'L'});
  }
  var strokes=[], last=null;
  pv.forEach(function(p){
    if(!last){ last=p; strokes.push(p); return; }
    if(p.kind===last.kind){
      if((p.kind==='H'&&p.px>last.px)||(p.kind==='L'&&p.px<last.px)){ last=p; strokes[strokes.length-1]=p; }
      return;
    }
    if(p.i-last.i<4) return;
    if(Math.abs(p.px/last.px-1)<0.015) return;
    last=p; strokes.push(p);
  });
  var out={strokes:strokes,pivot:null};   // pivot = 中枢
  if(strokes.length>=4){
    var p4=strokes.slice(-4), hi3=[], lo3=[];
    for(var t=0;t<3;t++){ hi3.push(Math.max(p4[t].px,p4[t+1].px)); lo3.push(Math.min(p4[t].px,p4[t+1].px)); }
    var zg=Math.min.apply(null,hi3), zd=Math.max.apply(null,lo3);
    if(zg>zd) out.pivot={zg:zg,zd:zd,i0:p4[0].i,i1:p4[3].i};
  }
  return out;
}
```

function ntWindow(series){
  if(!series || !series.length) return null;
  var last = series[series.length-1];
  var ld = new Date(String(last.date)+'T00:00:00Z').getTime();
  for(var i=series.length-2;i>=0;i--){
    var d = new Date(String(series[i].date)+'T00:00:00Z').getTime();

function sectorScore(industry){
  var tech = techScoreOf(industry);     // 该行业代表 ETF 周线：均线排列 + MACD + 20 周线

  var wsum = items.reduce(function(s,x){ return s+x[1]; },0);

  var cap = {S:25,A:20,B:10,C:5,D:0}[grade];
  return {score:Math.round(score), grade:grade, cap:cap, missing:missing};

  top += heatScore(leg);              // 情绪过热 10

  var b = normalize(bottom), t = normalize(top);   // 缺项按已有项折算到百分制

  else if(t>=60) cap = Math.min(cap, 5);
  else if(t>=40) cap = Math.round(cap*0.5);
  return {bottom:b, top:t, grade:grade, cap:cap};
}
