# 持仓分析页 · 施工指南

这份指南按**页面从上到下的顺序**写：每一块显示什么、数字怎么来、没有数据时显示什么、在哪里实现。
开发现场按第 11 章的施工顺序干活，按第 12 章逐块验收。

适用范围：`web/index.html` 第 5 页「持仓分析」（含持仓概况、持仓分析、市场洞察及方向）。
不含投资建议，不预测点位。

---

## 1. 这份指南怎么用

| 角色 | 看哪几章 |

| 产品/复核 | 2、3、4、5、12 |
| 前端开发 | 3、4、5、7、8、11 |
| 数据开发 | 7、8、10（S1–S3） |

- 页面上不写死任何业务数字（行业权重、候选名单、评级分数线、点评句子）。
- 页面上每个数字都能说出出处（哪个数据文件、哪个字段）。
- 一句结论里出现的数字，必须能在同一页找到对应的那个数；找不到就不显示这句话。

## 2. 页面总览：三部分各自回答什么问题

| 部分 | 回答的问题 | 读者动作 |
|---|---|---|
| 一、持仓概况 | 我有多少钱、赚亏多少、今天买什么卖什么、多少钱多少价 | 直接照着下单 |
| 二、持仓分析 | 现在市场什么环境、我的组合跟不跟得上、每只基金该不该留 | 判断要不要改计划 |
| 三、市场洞察及方向 | 大盘处在什么位置、情绪冷热、接下来三种走法各怎么办、除了手上的还能看什么 | 做下周打算 |

顺序不能倒：先给结论（概况），再讲理由（分析），最后讲远景（洞察）。
理由只能收紧结论，不能推翻结论。

## 3. 第一部分 持仓概况

定位：一屏看完，不出现均线、缠论这类技术词。

版面自上而下：

```
① 四个数字
② 今日点评
③ 持仓明细表
```

不做：仓位条、持仓类别饼图、执行后估算卡、今日建议卡、表格下方小字说明、收益曲线。

### 3.1 顶部四个数字

| 卡 | 大字 | 小字 | 怎么算 | 没有数据时 |
|---|---|---|---|---|
| 总资产 | 总金额 | 其中现金多少 | 所有持仓市值 + 现金 | 显示「—」，小字写「有基金缺价格」 |
| 持仓市值 | 总金额 | 持有几只 | 每只：最新价 × 份额，再相加 | 同上 |
| 浮动盈亏 | 百分比 | 金额 | （最新价 − 成本价）× 份额，再相加 | 缺成本价时只显示「—」 |
| 当日盈亏 | 百分比 | 金额 | （最新价 − 昨收）× 份额，再相加 | 缺昨收时显示「—」 |

颜色：赚红亏绿，零值灰。金额取整到元并加千分位，百分比两位小数。
没有持仓时：只显示总资产与现金，后两张卡写「暂无持仓」。

实现位置：`app.js` 的 `calcPort()`（计算）与 `kpi()`（渲染）。

### 3.2 今日点评

页面上最重要的一段话。它不是一份数据罗列，而是一次**综合判断**：把市场环境、持仓结构、今天的动作、后面的改判条件串成一条完整的推理链。写法参照三套东西——沉关河的复盘口吻（结论先行、一句话一行、敢给动作）、缠论的分析思路（先定大级别方向，再找小级别点位，最后说背驰与确认）、以及「今日点评 skill」的输出规范。

**输出由 skill 产出，不是页面拼句子。**

- 主来源：`skills/portfolio-brief` 在每日运行时生成 `data/brief.json`，页面直接读。
- 兜底：文件缺失或数据日期与页面不一致时，页面用 `rsBriefSections()` 现场生成，标题后加「（本机引擎）」。

#### 一段合格的点评长什么样

以「下行趋势中的减仓日」为例（演示写法，实际内容每天不同）：

> **今日基调：先降后看。**
>
> 大盘还在 60 日线下方，5 日线压在 20 日线下，波动没有放大，基准仓位 35%。我们现在 40.6%，高出基准 5.6 个百分点，这一口钱要先还回去。
>
> 结构上，四只里三只周线仍是空头排列，只有 588000 日线先转强——但周线没跟上，按纪律不加。真正拖累的是 510300：月线在转换期，周线死叉，评分全场最低。
>
> 今天动三笔：510300 减 2400 份，挂 4.051；510500 减 800 份，挂 6.312；588000 不动，日线转强但周线未确认，等回踩 10 日线。剩余差额分三周减完，不一次清仓。
>
> 改判：基准收复 20 日线 4069.52 且 5 日线上穿 20 日线，基准仓位从 35% 上调到 45%；任何一只收盘跌破 30 日线两天，卖出该只全部剩余差额。
>
> 价格是执行价，不保证成交。

这段话的骨架是：**先定方向（环境）→ 再找主要矛盾（结构里谁最弱、为什么）→ 给出动作（带数量与价格）→ 写清改判（阈值 + 后果）**。不是「环境如何、结构如何、执行如何」三栏统计，而是一条顺着讲下来的推理。

#### 写作规范

| 要求 | 说明 |
|---|---|
| 结论先行 | 第一句就是基调，三选一：先降后看 / 按差额补仓,不满仓 / 不动,等条件。基调必须与多数动作一致 |
| 一条推理链 | 环境 → 结构 → 动作 → 改判，四层顺着讲；允许合并、允许展开，不强制分几段 |
| 有主次 | 指明「主要矛盾」是哪只、哪个板块、哪条线；不平均用力 |
| 有确认条件 | 写清「等什么信号才动手」，例如「周线转多 + 站上 10 日线」 |
| 有代价意识 | 给动作时同时给失效线与回补条件；结尾固定一句「价格是执行价，不保证成交」 |
| 数字可回溯 | 每个数字都要能在同一页找到出处；找不到就写「缺失」，不估算 |
| 禁空话 | 不说「注意风险」「保持谨慎」「密切关注」「综合来看」「整体合理」「酌情处理」 |
| 不预测 | 不给目标价，不说「明天会涨」，不写「概率很大」这类没有样本量的判断 |

篇幅不设硬上限：讲清楚为止，短可以三句，长可以到上面示例的长度。宁可少写一句空话，也不凑一段统计。

#### 内容从哪来

| 推理环节 | 用到的数字 |
|---|---|
| 环境定调 | 大盘状态、基准仓位、当前仓位与偏离、市场温度、涨跌家数、成交额环比、国家队近四周份额变化 |
| 结构找矛盾 | 有几只要减、几只要加、几只维持、评级最低的是哪只及其原因、最大板块及占比、现金比例 |
| 动作落地 | 今天几笔单、方向、数量、挂单价；没动的写明原因（差额不足 / 确认未齐 / 周线向下） |
| 改判条件 | 大盘 20 日线价位、5 日线与 20 日线关系、每只的 30 日线 |

#### 实现

| 项 | 位置 |
|---|---|
| skill 契约 | `skills/portfolio-brief/SKILL.md` |
| 产出文件 | `data/brief.json`（结构：`data_date` + `conclusion` + `blocks[]`，每块 `k/v/refs`） |
| 读取与校验 | `webgen._brief()`：数据日期、结构、禁用词 |
| 现场兜底 | `rsBriefSections()` 生成块，`rsRenderBrief()` 渲染 |
| 展示 | 块按 `k` 前缀一行；来源为引擎时标题加「（本机引擎）」 |

### 3.3 持仓明细表

一张表，一行一只基金，能直接照着下单。必备列如下（列的先后可按版面合并，但不能少）。

| 列 | 显示什么 | 怎么算 | 没有数据时 |
|---|---|---|---|
| 代码 / 名称 | 基金代码和简称 | 直接取 | 名称缺失只显示代码 |
| 板块 | 这只基金主要投向哪个行业 | 取指数行业权重里最大的一项 | 「行业未覆盖（数据日 X）」 |
| 现在仓位 → 目标仓位 | 当前占总资产比例，箭头后是计划比例 | 当前：市值 ÷ 总资产；目标：目标仓位表 | 目标缺失显示「目标缺失」 |
| 现在数量 → 建议数量 | 份额，箭头后是按目标算出的份额 | 目标份额 = 向下取整（总资产 × 目标仓位% ÷ 挂单价 ÷ 100）× 100 | 同上，只显示当前 |
| 本次操作 | 加多少 / 减多少（份），不动写「—」 | 建议数量 − 现在数量 | 「—」 |
| 挂单价 | 限价参考价 | 买入：现价 × 1.0001；卖出：现价 × 0.9999 | 不可交易时写「不挂单」并给原因 |
| 费用 | 本次预计花多少手续费 | 佣金 max(5 元, 成交额×0.5bp) + 滑点 成交额×1bp | 「—」 |
| 成本价 → 现价 | 你的成本与最新价 | 直接取 | 显示「—」 |
| 盈亏 | 百分比 + 金额 | （现价 − 成本）÷ 成本；金额 = 差价 × 份额 | 缺成本 → 「—」 |
| 全市场位置 | 比大盘强还是弱 | 近 5 日涨幅 − 大盘近 5 日涨幅 | 「—」 |
| 国家队 | 这只所属宽基近四周份额变化 | 取最新一期与 25 天前那期比 | 「未纳入」 |
| 动作 | 加 / 减 / 持有，附差额百分点 | 来自目标仓位表的结论 | 「—」 |

可选列：5 日 / 20 日上涨占比。任一列样本不足 30 个，整列隐藏，不留空表头。

其他约定：

- 排序：按「本次操作金额」从大到小，不操作的排后面。
- 数字格式：份额千分位；价格三位小数；费用到分。
- 行悬停显示规则编号，方便追查为什么给这个动作。
- 「动作」必须和订单一致；不一致时整行标橙，并写「以订单为准」。

实现位置：`rsPageHTML()` 拼表，`orderTicket()` 算数量/挂单价/费用，`rsSectorMap()` 取板块（改读 `sector_weights`），`nationalTeamText()` 取国家队。

下单信息的六条边界：

| 情况 | 处理 |
|---|---|
| 目标仓位缺失 | 不猜，数量与价格全「—」，备注「目标缺失」 |
| 价格缺失 | 同上，备注「价格缺失」 |
| 算出来不足 100 份 | 视为不动，备注「不足一手」 |
| 买入时现金不够 | 按可用现金下调手数，备注「受现金限制」 |
| 当天成交额低于 1000 万 | 不挂单，备注「流动性不足」 |
| 停牌 | 不挂单，备注「停牌」 |

## 4. 第二部分 持仓分析

定位：解释第一部分为什么这么定。顺序固定：先看市场，再看组合，最后看每只基金。

### 4.1 市场环境

四个小块。

| 小块 | 显示什么 | 数字来源 | 没有数据时 |
|---|---|---|---|
| 大盘走势 | 现在是什么状态、基准仓位多少、基准日、收盘价与 20 日/60 日线关系、5 日线是否在 20 日线上方、波动有没有放大 | 基准指数日线算出来 | 「基准数据不足」 |
| 市场热度与舆情 | 涨跌家数、成交额、情绪分、消息分 | 快照里的盘面与舆情 | 逐项「缺失」 |
| 国家队 | 六类宽基最新份额、比上次增减、近四周方向 | 交易所份额数据 | 「未纳入」 |
| 位置与赔率 | 近 120 天最高最低、现在距高点多远、距低点多远、向上空间、向下空间、赔率 | 基准指数日线 | 「缺少高低点」 |

写法要求：

- 每条写完要能回答「所以呢」，例如「成交额环比 −8.6%，缩量，缩量下跌不算恐慌」。
- 国家队只做背景，最多影响基准仓位 ±5 个百分点，不能突破上下限；单期变化超过 15% 时写「仅展示，不作判断」。
- 位置与赔率必须加一句解释：赔率是位置描述，不代表发生可能。

### 4.2 组合情况

四个小块。

| 小块 | 显示什么 | 怎么算 |
|---|---|---|
| 板块分布 | 各行业占组合多少，条形图按占比排序 | 每只基金按指数行业权重拆开，再按仓位加权求和 |
| 集中度 | 最大板块、前三大合计、持有只数、现金比例 | 直接汇总；最大板块超过 25% 标「超配」，低于 5% 标「低配」 |
| 板块健康度 ⓘ | 每个板块的技术面、资金面、政策面、情绪面四项分数与综合分 | 技术 40% + 资金 25% + 政策 20% + 情绪 15%；缺项按已有项折算，并标「缺 X 项」。**点 ⓘ 展开计算思路**（见下） |
| 与市场是否一致 ⓘ | 最大板块是不是当前主线、哪些超配低配、哪些板块走弱但还拿着 | 三条判断，逐条写结论。**点 ⓘ 展开计算思路**（见下） |

ⓘ 交互规范（两处通用）：

- 位置：区块标题右侧一个圆形 ⓘ 图标，键盘可聚焦，`aria-label` 写「查看计算思路」。
- 点击：在该区块内展开一块浅底说明区，再点收起；不跳页、不弹层、不遮挡表格。
- 内容：只讲**怎么算**，不复述结果；写清输入字段、公式、缺项处理、容易误解的地方。
- 移动端：ⓘ 与说明区同样可用，说明区宽度跟随容器。

板块健康度的计算思路（展开后显示）：

> 四个维度分别打分（0–100），再加权：
> · 技术面（40%）：该行业对应基金的周线状态——5/10/20/30 周均线的排列与方向，以及是否站在 20 周线上方。
> · 资金面（25%）：该行业板块成交额占全市场比重，近 5 日与再前 5 日相比是升是降；成交占比超过 15% 记「过热」。
> · 政策面（20%）：政策热度表里该主题的热度与变化幅度；没有对应主题记缺失。
> · 情绪面（15%）：该行业当日涨跌幅与涨跌家数占比。
> 缺某一项时，不直接不算，而是把该项权重按比例分给已有项（例：缺政策面，则技术 40→50、资金 25→31、情绪 15→19），并在标题旁标「缺 1 项」。
> 分数只描述状态强弱，不构成买卖信号。

与市场是否一致的计算思路（展开后显示）：

> 三条判断，逐条给结论：
> 1. 主线归属：取组合里占比最大的行业（跳过「未覆盖」和「其他」），看它是否出现在市场轮动的主线名单里。出现 → 「与主线一致」；没出现 → 「与主线背离」，并写出主线是哪几个。
> 2. 超配低配：最大行业占比 ≥25% 记「超配」，≤5% 记「低配」，其余为中性；超配行业列出名称与占比。
> 3. 走弱仍有暴露：板块健康度状态为「走弱」且组合占比 ≥10%，逐个列出；这类板块若对应持仓动作是「加仓」，按第 6 章裁决降级为「观察」，并在行内标橙。

写作要求：

- 行业名称必须和市场热点里出现的行业名一致，不能自造「其他」「未映射」以外的名字。
- 判定走弱但第一部分给的是「加仓」时，这里要标橙并写「以观察为主，不加仓」。
- 不合成单一「健康分」，只列四项与综合分。

实现位置：`rsSectorExposure()`（拆分与汇总）、`rsRenderSector()`（渲染）、`sector_weights`（行业权重唯一来源）。

### 4.3 个股分析

一只基金一张卡，用按钮切换。卡片从上到下七块。

| 顺序 | 块 | 内容 | 说明 |
|---|---|---|---|
| 1 | 结论 | 三个字：减 / 持 / 加；一行理由 | 必须等于第一部分的动作，不能给相反建议 |
| 2 | 三周期状态 | 月线、周线、日线各一行：状态 + 关键位 | 月线看 20 月线上下；周线看 5/10/20/30 周排列；日线看 10 日/20 日线与量比 |
| 3 | 评级与目标 | 评分（0–100）、评级（S/A/B/C/D）、对应上限、目标仓位、目标份额 | 评分四项：月线底背离 35 + 站上 20 月线 25 + 周线排列 25 + 日线确认 15 |
| 4 | 缠论图 | K 线 + 5/10/20 日线 + 笔 + 中枢 + 卖买点标注 + 成交量 + MACD | 只用分型→笔→中枢；没有线段与多级别，图注必须写「简化实现」 |
| 5 | 上涨概率 | 5 日、20 日、60 日上涨占比，样本数、样本区间、中位涨幅 | 样本少于 30 直接写「样本不足」，不显示百分比 |
| 6 | 怎么做 | 现在仓位 → 目标仓位、差额、确认条件（周线方向 + 日线确认 0–3 条）、挂单价、首批数量 | 分周减仓要写首批与后续条件 |
| 7 | 什么时候改判 | 两个条件 + 后果 | 例：站上 20 日线且周线转多 → 恢复到目标；跌破 30 日线两日 → 卖出全部差额 |

写法要求：

- 图上不允许出现「第 18 根买点」这类固定位置的标注；只在真出现底背驰或站上中枢上沿时标。
- 概率只作参考，不能改评级、改动作，出现矛盾时以评级为准。
- 每只基金都要有「改判」一行，不许省略。

实现位置：`rsRenderDetail()`、`rsChanOf()`（分型/笔/中枢）、`rsDrawChart()`（绘制）、`rsForecast()`（概率）。

## 5. 第三部分 市场洞察及方向

定位：给位置、给冷热、给三种走法，不给「明天涨跌」。

### 5.1 今日定性

- 按当前时间自动判断时段：盘前、盘中、午盘、盘后、周末，标题写明当前是什么时段、关注什么。
- 结论三选一：偏多 / 偏空 / 震荡。四条打分：大盘状态（±2）、5 日线与 20 日线关系（±1）、上涨家数占比（±1）、情绪分（±1），绝对值 ≥2 才给方向。
- 结论下面必须列三条依据，每条带数字。

### 5.2 情绪与主线

一行一件事，全部带数字：

- 涨停跌停家数、连板高度
- 成交额与环比；环比下降超 5% 写「缩量」，缩量下跌不算恐慌
- 恐慌判定、连续普跌天数
- 情绪节点、首次分歧是否已过
- 主线是哪几个行业，判断是否「扛过分歧后反包」，并写次日要不跌破 5 日线才算确认
- 落后行业，注明「没跌够的不追反弹」

### 5.3 情景与触发

一张三行表：情景 / 触发条件 / 现在的距离 / 对应动作。

| 情景 | 触发 | 对应动作 |
|---|---|---|
| 偏弱延续 | 收盘跌破近 120 天最低 | 按差额分批减，不抄底 |
| 震荡修复 | 在最低与 20 日线之间来回 | 只调整结构，不加总仓位 |
| 转强确认 | 站上 20 日线且 5 日线上穿 20 日线 | 差额可以执行 |

触发值必须用真实价位（最低价、20 日线），不能用「20 日线 ×0.96」这类硬编码系数。
「现在的距离」要写清差多少个百分点。

### 5.4 新方向候选

一张表：方向、代码、名称、5 日/20 日上涨占比、20 日中位、建议、理由、风险。

筛选顺序：从观察池取 → 去掉已持有的 → 只留 A/B 级 → 近 5 日不弱于大盘 → 同类只留一只 → 看还剩多少仓位额度。

额度闸门：剩余额度小于 3 个百分点或目标仓位表缺失时，建议一律写「观察」，并说明原因。
禁止内置固定候选名单，禁止在没额度时写「可分批」。

## 6. 三部分之间怎么衔接

| 关系 | 规则 |
|---|---|
| 概况 → 分析 | 分析只能解释概况的动作，不能给出相反建议 |
| 环境 → 组合 → 个股 | 上层给额度，下层只能收紧，不能放大 |
| 洞察 → 概况 | 洞察的定性与概况的点评用同一套环境数据，不许各算一套 |
| 数据不足 | 一律写「缺失」，不补脑，不用别的数据替代 |

出现分歧时按下面八条裁决，并在页面标橙写清：

| 分歧 | 以谁为准 |
|---|---|
| 日线转强但周线空头 | 周线定方向，日线只定节奏 |
| 月线在转换但周线空头 | 按周线，不提前加仓 |
| 目标仓位高于现在但周线向下 | 不买，改为等待 |
| 评级上限与环境额度冲突 | 取小的那个 |
| 缠论出现买点但目标是减 | 不做多，缠论只用来定卖出时点 |
| 概率低但评分高 | 概率只作参考，不改评级 |
| 舆情或国家队与仓位区间冲突 | 最多 ±5 个百分点，不破上下限 |
| 组合判断某板块走弱但该只给加仓 | 标橙，改为观察 |

## 8. 页面上的固定口径

所有数字按这张表算，别在别处另定一套。

### 8.1 大盘状态与基准仓位

| 条件 | 状态 | 基准仓位 |
|---|---|---|
| 收盘在 60 日线上方，且 5 日线在 20 日线上方 | 上行趋势 | 85% |
| 收盘在 60 日线下方，且 5 日线在 20 日线下方 | 下行趋势 | 35% |
| 其余 | 震荡区间 | 65% |
| 20 日波动 > 60 日波动 × 1.25 | 追加「波动抬升」，基准仓位下调 10 个百分点 | — |

### 8.2 单只评级

| 项 | 分值 | 判据 |
|---|---|---|
| 月线底背离 | 35 | 双背离 35、单背离 25、未确认 15、无 5、顶背离 0 |
| 站上 20 月线 | 25 | 站上 25，否则 0 |
| 周线排列 | 25 | 多头 25、金叉初期 18、粘合 10、空头 4、死叉 0 |
| 日线确认 | 15 | 站上 10 日线 7 + MACD 多头 5 + 量比 >1.1 得 3 |

估值、景气、资金三项没接入时，页面标「按已有项折算」。

| 总分 | 评级 | 单只上限 |
|---|---|---|
| ≥85 | S | 25% |
| 75–84 | A | 20% |
| 60–74 | B | 12% |
| 50–59 | C | 8% |
| <50 | D | 5%（观察仓，不清零） |

### 8.3 目标仓位

```
单只基础 = 单只上限 × 趋势系数（多头 1.0 / 金叉 0.9 / 走平 0.7 / 空头 0.35）
目标仓位 = min(单只上限, 基准仓位 × 单只基础 ÷ 所有基础之和)
合计低于基准仓位时，差额留现金，不为用满额度倒推动作
```

### 8.4 动作

```
差额 = 目标仓位 − 现在仓位
|差额| < 3 个百分点            → 持有
差额 > 3 且 周线向下           → 等待，不买
差额 > 3 且 日线确认不足 2 条  → 等待确认
差额 > 3 且 确认 ≥ 2 条        → 加仓
差额 < −3 且 周线空头或日线弱  → 减仓，分批
差额 < −3 其余                → 减一半差额
```

减仓节奏：单周最多卖三分之一，且不少于 5 个百分点，直到减到目标。

### 8.5 下单数量、挂单价、费用

```
挂单价  = 买入：现价 × 1.0001；卖出：现价 × 0.9999
建议数量 = 向下取整（总资产 × 目标仓位% ÷ 挂单价 ÷ 100）× 100
本次操作 = 建议数量 − 现在数量
费用    = max(5 元, 成交额 × 0.5bp) + 成交额 × 1bp
```

### 8.6 概率

用「20 日涨幅 + 20 日波动」两个特征，找历史上最像的样本，按距离加权统计未来 5/20/60 日上涨占比。
必须同时显示样本数；样本少于 30 不显示。

## 9. 方法借鉴：五套做法各取了什么

页面上的判断不是凭感觉来的，每一类判断都来自一套已经写清的做法。先知道出处，再照着实现。

### 9.1 沉关河（交易思维，人物方法）

| 他怎么做 | 我们怎么用 |
|---|---|
| 看大盘定仓位 → 看板块定方向 → 看个股定动作 → 看均线定出局 | 就是第 4 章的三层顺序，不能倒 |
| 指数站回 5 日线才算短线回暖，站不上只是反弹 | 市场定性里加「五均线开关」一句 |
| 缩量的下跌不算恐慌，放量急杀才算 | 情绪块的判定条件，写进文案 |
| 主线要「扛过分歧后再反包」，等它自证 | 主线确认的三条判据（分歧节点、首次分歧、次日不破 5 日线） |
| 3 个交易日涨 10% 先保护利润 | 个股卡片的「怎么做」里给兑现线 |
| 单票试错不超过 10% | 目标仓位与评级上限取小的那条 |
| 结论先行、一句话一行、给动作时补一句「止损自己先想好」 | 点评与个股卡的写法模板 |

### 9.2 拐点体系（ETF 波段方法）

| 他的规则 | 我们怎么用 |
|---|---|
| 月线定方向、周线定节奏、日线定点位 | 三周期状态表与评分 |
| 20 月线是分界线：站上进入可重仓区，站下只做反弹 | 月线状态判据与 25 分的权重 |
| 评分卡：月线底部结构 40 + 周线趋势 30 + 资金面 30 | 改成可接入的版本（见 8.2），缺数据的项按已有项折算 |
| 分数对应评级与上限：S25 / A20 / B10 / C5 | 8.2 的评级表（D 档设 5% 观察仓，不清零） |
| 板块强弱 = 技术 40% + 资金 25% + 政策 20% + 情绪 15% | 组合情况的板块健康度四维 |
| 板块成交占比 >15% 记过热 | 板块表加「过热」标记 |
| 单板块上限分级，重仓须评分 ≥75 | 目标权重与评级上限联动 |

### 9.3 topnews（舆情简报）

| 他的做法 | 我们怎么用 |
|---|---|
| 按交易时段出不同简报（盘前/盘中/午盘/盘后/周末） | 洞察的时段判断与标题 |
| 情感分 -1 到 +1、重要性 1 到 10 | 情绪块与「消息 Top3」 |
| 每条结论标数据来源与时间 | 页脚数据来源条 |
| 结论分风格给操作建议 | 候选表的「建议」列，但受额度闸门约束 |

### 9.4 量化平台（回测与执行口径）

| 他的规范 | 我们怎么用 |
|---|---|
| 佣金、滑点、印花税都要计入 | 下单信息的费用公式（ETF 免印花税） |
| 每个数据标来源与延迟，降级要写明 | 页脚来源条与降级提示 |
| 回测结果必须带「历史不代表未来」 | 概率块与点评结尾的固定短句 |
| 不承诺收益、不接实盘 | 全站只给限价参考，不自动下单 |

### 9.5 国家队宽基份额

只当背景：近四周份额变化只影响基准仓位 ±5 个百分点，不能突破区间上下限；单期变化超过 15% 只展示、不作判断。

按第 11 章的施工顺序展开。每步写清：做什么、动哪些文件、怎么验证、常见坑。

### 10.0 先认识代码结构

| 文件 | 干什么 |

| `src/etfquant/pipeline.py` | 每天的总调度：取数 → 算指标 → 给动作 → 出目标仓位 → 生成页面 |

### 10.1 S1 行业权重数据（最先做）

**做什么**：做一份「指数 → 行业权重」的数据文件，让页面知道每只基金投在哪些行业、各占多少。

**怎么做**

1. 新建 `scripts/fetch_index_sector_weights.py`：
   - 读 `config/universe.yaml`，拿到每只基金的跟踪指数（`benchmark`）；
   - 对每个指数，取公开的行业权重（中证指数官网或同源数据）；
   - 写成 `data/snapshot/index_sector_weights.json`，格式见 7 章；
   - 抓失败不报错退出，沿用上一次的文件并在 `stale` 写 `true`。
2. 校验写进脚本里：每个指数的权重之和必须在 99 到 101 之间；行业名必须出现在 `market.flow` 的列表里。
3. 加一个测试 `tests/test_sector_weights.py`：权重和、行业名集合、文件缺失时的降级。

**验证**

```bash
python3 scripts/fetch_index_sector_weights.py
python3 -c "import json;d=json.load(open('data/snapshot/index_sector_weights.json'));print(d['as_of'])"
```

**常见坑**

- 权重是「占指数的比重」，不是「占我仓位的比重」；换算在页面里做。
- 不同数据源的行业名字会差一个字（「电子」vs「电子一级」），统一按 `market.flow` 的名字。

### 10.2 S2 页面读取行业权重

**做什么**：让页面不再写死四只基金的行业，改读 S1 的文件。

**怎么做**

1. `webgen.py` 里加 `_load_sector_weights()`，读文件后放进 JSON 的 `sector_weights` 字段；文件不存在就放 `null`。
2. `app.js` 里把 `rsSectorMap()` 改成：
   - 有数据：按 `etf_index[code]` 找到指数，返回该指数的行业权重（从大到小）；
   - 没数据：返回「未覆盖」，页面显示「行业未覆盖（数据日 X）」；
   - 删掉 `RS_SECTOR_MAP` 常量和「看名字猜行业」的分支。
3. 组合暴露的汇总也改：未覆盖的基金单列一行，不并入其他行业。

**验证**

```bash
node --check src/etfquant/web_assets/app.js
grep -c "RS_SECTOR_MAP" src/etfquant/web_assets/app.js   # 应为 0
```

**常见坑**

- 页面上的「板块」和市场热点的行业名必须同一套词；不一致时以 `market.flow` 为准。
- 改完要重新生成页面：`python3 scripts/run_update.py --json`。

### 10.3 S3 顶部四个数字

**做什么**：总资产、持仓市值、浮动盈亏、当日盈亏。

**怎么做**：`calcPort()` 里逐只算 `最新价 × 份额`，相加得市值；市值加现金得总资产。任一基金缺价就把相关数字置空，不猜。渲染用 `kpi()`。

**验证**：打开 `docs/page_demo.html`（离线 demo），对照表里数字手算一遍。

**常见坑**

- 「最新价」优先用实时接口，取不到才用日线最后收盘价，页面上要能看出用的是哪个（数据时间）。
- 缺成本价时不显示盈亏比例，只显示「—」。

### 10.4 S4 明细表与下单信息

**做什么**：一张表能直接下单。核心是新增 `orderTicket()`。

**怎么做**（按 8.5 的公式）：

```javascript
function orderTicket(r, targetW, total){
  if(targetW==null || r.last==null) return {note:'目标或价格缺失'};
  var side = targetW > r.weight ? 'buy' : 'sell';
  var limit = r.last * (side==='buy' ? 1.0001 : 0.9999);
  var shares = Math.floor(total*targetW/100/limit/100)*100;
  var delta = shares - r.shares;
  if(Math.abs(delta)<100) return {delta:0, note:'不足一手'};
  var fee = Math.max(5, Math.abs(delta*limit)*0.00005) + Math.abs(delta*limit)*0.0001;
  return {shares:shares, delta:delta, limit:limit, fee:fee, side:side};
}
```

表头按 3.3 的 12 列顺序拼；动作列读 `plan.items[].action`，与订单不一致就标橙。

**验证**

- 随便挑一行：建议数量 × 挂单价 ≈ 总资产 × 目标仓位%（误差小于一手）。
- 费用合计与订单里的费用对得上。
- 把价格改成缺失，确认这一行显示「—」和原因，不显示 0。

**常见坑**

- 减仓的「本次操作」和「建议数量」不是一回事：建议数量是终点，本次操作是首周批次。
- 100 份取整：向下取整（买入不超支，卖出不超持）。

### 10.5 S5 今日点评

**做什么**：页面上的点评不再写死，改成「skill 产出优先、本机引擎兜底」。

**怎么做**

1. 新建 `skills/portfolio-brief/SKILL.md`（已建），规定输出 `data/brief.json`。
2. `webgen.py` 加 `_brief()`：读文件、校验结构（数据日期、必备要素、无禁用词），合格才放进 JSON 的 `brief` 字段。
3. `app.js` 的 `rsRenderBrief()`：有 `brief` 就用它；没有就调 `rsBriefSections()` 现场生成，标题加「（本机引擎）」。
4. `rsBriefSections()` 按 3.2 的「内容从哪来」表取数，拼句子；每句都从变量来，不写死。

**验证**

```bash
python3 scripts/gen_page_demo.py   # 生成离线 demo
```

打开 demo，确认点评是一条完整推理链（基调 → 依据 → 动作 → 改判）、每句有数字；把 `data/brief.json` 的日期改错，确认回退到「（本机引擎）」。

**常见坑**

- 点评里的数字必须能在同一页找到；写完自己抽查三句。
- 禁用词表（附录 B）加进 `_brief()` 的校验里，命中就不采用。
- 没有持仓时不报错，只保留基调与一句说明。

### 10.6 S6 市场环境

**做什么**：市场环境四块（大盘走势、热度舆情、国家队、位置与赔率）。

**怎么做**

1. 后端：`signals/market_regime.py` 的 `classify()` 已经输出 `regime`、`fit_lo/fit_hi`、`position`（近 120 天高低、上下空间、赔率）。缺 70 根日线时返回「未知」，前端按「基准数据不足」显示。
2. 前端：`rsRenderMarket()` 读 `D.market.regime` 与 `D.plan.total_target`，填四个小块；`nationalTeamTable()` 读 `national_team.series`，近四周按**日期回溯 25 天**取基准期（不要按条数取）。

**验证**：把 `data/snapshot/index_daily/000300.csv` 临时截断到 60 行，确认页面显示「基准数据不足」而不是崩掉。

**常见坑**

- 近四周不要用「往前数 4 条」：日频数据 4 条只有 4 天。用日期差 ≥25 天。
- 国家队单期变化 >15% 时写「仅展示，不作判断」。

### 10.7 S7 组合情况

**做什么**：板块分布、集中度、板块健康度、与市场是否一致。

**怎么做**

1. `rsSectorExposure()`：按 S1 的行业权重把每只基金的仓位拆到行业，再相加；未覆盖单列。
2. 集中度：最大板块、前三合计、持有只数、现金比例，超过 25% 标超配、低于 5% 标低配。
3. 板块健康度四维：技术面用该行业对应基金的周线状态，资金面用板块成交占比变化，政策面用政策热度，情绪面用当日涨跌；权重 40/25/20/15，缺项按已有项折算并标「缺 X 项」。
4. 「与市场是否一致」三条判断写成一个函数 `portfolioRead()`，输出三条带结论的句子；若判定走弱但该只动作是加仓，标橙写「以观察为主」。
5. 两处 ⓘ：按 4.2 的交互规范实现，展开内容直接用 4.2 给出的文字。

**验证**：把某只基金的权重临时调到 30%，确认「超配」标记出现；点 ⓘ 能展开、再点能收起。

**常见坑**

- 四维缺项时不要直接不算，要按已有项重新折算，否则分数会偏低。
- 行业名不一致是这里最容易翻车的地方，统一用 `market.flow` 的列表。

### 10.8 S8 个股卡片

**做什么**：一只基金一张卡，七块内容（见 4.3）。

**怎么做**

1. 三周期状态：月线看 20 月线，周线看 5/10/20/30 周排列，日线看 10 日/20 日线与量比。
2. 评分与评级：按 8.2 的四项打分，评出 S/A/B/C/D 与上限。
3. 缠论：`rsChanOf()` 只做三件事——找顶底分型、连成笔、取最近三笔的重叠区间当中枢；只在出现底背驰或站上中枢上沿时标买卖点。图上必须写「简化实现」。
4. 概率：`rsForecast()` 用「20 日涨幅 + 20 日波动」找历史相似样本，输出 5/20/60 日上涨占比、样本数、样本区间；样本少于 30 显示「样本不足」。
5. 怎么做与改判：目标、差额、确认条件（周线方向 + 日线确认 0–3 条）、挂单价、首批数量；改判至少两条。

**验证**

- 打开 demo 切到任意一只，确认七块都在。
- 把某只的日线数据临时砍到 20 根，确认显示「数据不足」而不是画错图。

**常见坑**

- 不要在第 18、44、68 根这种固定位置标买卖点——那是假信号。
- 概率不能改评级；两者矛盾时以评级为准，并写明。

### 10.9 S9 市场洞察

**做什么**：定性、情绪与主线、情景与触发、新方向候选。

**怎么做**

1. `marketOutlook()`：一次算出时段、定性、温度四项（情绪 40% + 涨跌家数 35% + 成交额 15% + 趋势 10%）、位置赔率、情绪条目、三情景；页面三处共用它，不许各算一套。
2. `buildIdeas()`：按 5.4 的顺序筛候选，先看剩余额度，不足 3 个百分点就全部写「观察」。

**验证**：把基准的 MA20 改到现价上方，确认定性从「偏空」变「偏多」，且温度的分项数字跟着变。

**常见坑**

- 情景的触发值用真实价位（近 120 天最低、20 日线），不要写「20 日线 × 0.96」。
- 候选名单不能写死；每次运行都会变。

### 10.10 S10 发布与每日运行

**做什么**：把改动变成线上页面。

**怎么做**

```bash
python3 -m pytest tests/ -q                     # 先跑测试
python3 scripts/run_update.py --json            # 生成页面（实时取数）
python3 scripts/run_update.py --verify          # 只校验，不取数

```

`daily.sh` 会提交 `web/index.html` 与数据文件，GitHub Pages 自动发布。

**验证**

- 看仓库提交记录，确认 `web/index.html` 有更新。

**常见坑**

- 本机没有持仓解密口令时，`daily.sh` 会跳过持仓分析，页面显示演示数据；这是正常的。
- 改字段要同时改 `webgen.py` 里的版本号，否则页面会读到旧结构。

## 13. 风险与边界

- 缠论是简化实现（分型→笔→中枢），不做线段与多级别，图注必须写明。
- 概率是历史相似条件的统计，不代表未来；样本少时不显示。
- 行业权重来自公开披露，拿不到就显示「未覆盖」，不猜。
- 挂单价是限价保护，不保证成交；全部数字都是执行参考，不是承诺。
- 持仓只在本机解密，任何情况下不写入仓库。
