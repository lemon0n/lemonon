# 数据与新鲜度审计（2026-11-26）

> 目标：找出“当前页面/研究实际使用了过往快照”的路径，并区分**意外误用**与**明确标注的降级兜底**。
> 本轮只读审计 + 代码修复；没有改投资阈值，没有伪造数据。

## 1. 结论

修复前存在 5 条会主动误用旧产物的路径，不是单纯的文件堆积：

| 级别 | 问题 | 实际后果 |
|---|---|---|
| P0 | `--finish` 不带 `--run-dir` 只扫描旧 `agent_output.json` | 11-26 已 prepare 但没写输出时，会跨到 11-24 旧运行重放分析、点评和页面 |
| P0 | `_render_page()` 无条件注入全局 `data/brief.json` | 新研究旁边可能出现 11-24 的“今天做什么” |
| P0 | 旧 `market.json` 新闻生成当日 `event:market:2026-11-26:*` 证据 | 11-12 的快讯被伪装成 11-26 当日事实 |
| P1 | `news_note` 用 `market.as_of` 而非页面 `data_date` 校验 | 11-26 页面携带 11-12 的消息解读 |
| P1 | 行业权重 `stale=true`、逐指数日期不展示 | 399006 的 11-19 旧权重被总日期 11-25 掩盖，静默参与组合结构判断 |

另外发现两类工程污染：

- `data/cache/daily_*.csv` 只写不读，文件新旧会误导“本次是否刷新”的判断；
- 测试运行曾写入生产 `data/ledger/etf_llm.sqlite3`，产生 94 条 runs / 101 条 recommendations 的测试噪声。

## 2. 已修复

### 2.1 最新 prepare 是唯一可收尾对象

- `prepare` 写显式 `data/.pending_run` 指针。
- `--finish` 只读该指针；指针缺失时只扫描 `manifest.status=AWAITING_AGENT` 的最新 prepare。
- **不再扫描 `agent_output.json` 的存在时间，也不向旧日期回退。**
- 最新 prepare 没写输出时，明确报缺少 `agent_output.json`，退出码 2；旧运行保持不变。

### 2.2 点评绑定当前 run

- `brief.json` 增加 `run_id`，同时保存到当前 `data/runs/<日期>/<run>/brief.json`。
- 页面只读当前 run 的 brief 快照；没有新 brief 时 `data['brief']=None`。
- demo 生成器也只接受当前 run、当前状态为 `APPROVED + executable` 的研究与点评。

### 2.3 旧快照新闻/主线不再进入当日研究

- `market.as_of` 早于行情日的新闻整批排除，不生成当日证据 ID。
- 市场主线、情绪、轮动文本标记 `market_snapshot_as_of` 与 `auxiliary_stale`；旧快照的 leaders/laggards 从研究上下文剔除。
- `news_note` 改用页面权威 `meta.data_date` 校验；旧日期解读不再注入当前页面。

### 2.4 latest 与研究状态保护

- `research_latest.json` 只允许标准正式运行目录发布，`_repro`、`_nohold` 等目录不能发布。
- 发布带单调保护：旧数据日、旧上下文时间不能覆盖新指针。
- 前端只有在 `status=APPROVED` 且 `executable=true` 时才用研究提案生成计划；`REJECTED/LLM_FAILED` 不驱动交易表。
- 本轮没有新深度持仓报告时删除旧报告，不保留“上一交易日分析”冒充今日。

### 2.5 行业权重逐指数披露

- 页面保留并展示 `as_of`、`weights_date`、`stale`、`errors`。
- 抓取失败的指数（如 399006）其旧权重不参与映射；页面明确写“失败指数的旧权重不参与映射”。
- 组合一致性判断附带逐指数权重日期，不再只显示一个总日期。

### 2.6 删除无输入缓存与测试污染

- 删除从未读取的 `data/cache/daily_*.csv` 写入逻辑及本地缓存。
- 删除无调用者的 `data/snapshot/benchmark_ret.json` 固定区间收益。
- 测试隔离 `RUNS_ROOT` 时，SQLite 记忆库与持仓报告路径同步隔离到临时目录。
- 清理本地生产记忆库中的测试/`repro` 行，仅保留正式历史 run。
