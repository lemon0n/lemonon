# 每日更新执行指令（复制给每日 runner）

> 版本：2026-11-26 · 对应仓库 main
> 用途：把下面整段交给每天执行更新的 agent（例如 /workspace 环境的执行器）。
> 这份指令只描述**当前仓库真实行为**；`scripts/daily.sh` 是唯一入口。

---

## 指令正文

在 `/workspace` 执行 `lemon0n/lemonon` 的每日更新，只使用唯一入口：`bash scripts/daily.sh`。

**要求：**

1. **先确认环境**：`/workspace` 必须是 `lemon0n/lemonon` 仓库（`git remote -v` 里 `origin` 指向该仓库），并且当前分支是 `main`。
   如果不是，直接停止并报告实际路径与 remote；**不要**自行 clone 到其他目录。

2. **两种执行模式，按 `config/llm.yaml` 的 `provider` 自动分流**（`daily.sh` 会自己判断，不要手动改配置）：

   - **agent 模式（默认）**：本机没有模型服务，研究由你（执行器）完成。分两步，**两步都是同一个入口**：
     ```bash
     bash scripts/daily.sh                       # ① 抓数 + 冻结事实 + 出任务卡，打印 run_dir
     #   读 <run_dir>/AGENT_TASK.md 与 context.json，写 <run_dir>/agent_output.json
     #   （可选：加 "brief" 八块今日点评，结构见 prompts/brief.md）
     bash scripts/daily.sh --finish --push       # ② 证据校验 → 风控 → 订单 → 报告 → 页面 → 推送
     ```
   - **openai_compatible 模式**：本机/容器里已有 OpenAI 兼容服务，一条命令跑完：
     ```bash
     bash scripts/daily.sh
     ```

3. **不要使用 `--snapshot`**；不要手动修改这些生成物：
   `web/index.html`、`web/analysis_packet.json`、`data/last_run.json`、
   `docs/持仓分析报告.md`、`data/packets/positions_packet.json`。
   页面、数据包、报告、清单都由脚本产出，手改会导致无法重放。

4. **不要修改 `config/` 下的阈值、规则或参数来让校验通过**。
   风控不通过（退出码 4）就改建议（`<run_dir>/agent_repair.json`），不是改阈值。

5. **执行完成后读取 `data/last_run.json` 并汇报**（`bash scripts/daily.sh --status` 会直接打印下面这些字段）：

   | 字段 | 含义 |
   |---|---|
   | `status` | 研究结论状态：`APPROVED` / `REJECTED` / `ABSTAIN` / `LLM_FAILED` |
   | `data_date` | 行情数据日（页面所有价格/均线都以此为准） |
   | `degraded` / `synthetic` | 是否降级 / 是否合成数据 |
   | `levels` | 本次研究覆盖的标的数（= 持仓条数） |
   | `level_count` | 决策档位分布：`{"EXIT":n,"REDUCE":n,"HOLD":n,"ADD":n}` |
   | `action_count` | 订单方向分布：`{"SELL":n,"BUY":n}` |
   | `validation.ok` + `validation.violations` | 证据/契约校验是否通过、风控违规码 |
   | `fallback` | 数据回退明细（正常情况下为空） |

   另外核对：`ok`（整体是否成功）、`run_id`、`html`（页面路径）。

6. **退出码处理**：

   | 退出码 | 含义 | 动作 |
   |---|---|---|
   | `0` | 成功：页面已刷新（带 `--push` 时已推送） | 汇报结果 |
   | `4` | 校验或风控未通过 | **报告校验错误，不要重试**；按提示改建议后由人确认 |
   | `3` | 产物已生成但提交/推送失败 | 说明推送失败（通常远端有新提交），**可重跑一次** `bash scripts/daily.sh --finish --push` |
   | `2` | 运行异常（解释器/依赖/prepare 失败） | 报告异常原因，**不要盲目重试** |

7. **没有持仓（未设置口令）时的正常结果**：`status=APPROVED`、`trades=[]`、`orders=[]`、现金 100%，
   页面只有市场层与点评；这不是失败，也不要为了让它有交易去改配置或补口令。
   真正的失败只有 `LLM_FAILED`（模型输出不可用）与 `REJECTED`（风控未通过）。

8. **持仓分析被跳过是正常情况**：未设置 `POSITIONS_PASSPHRASE`（或 `positions/.passphrase` 不存在）时，只更新市场层，页面仍是完整可用的；不要因此报错，也不要去设置口令。

9. **不要输出或记录任何口令、Token、持仓明文**：日志里不要 `echo` 口令；不要打印 `positions/`、`docs/持仓分析报告.md`、`data/runs/*/context.json` 里的持仓内容；推送凭据用环境变量，不写进仓库。

10. **每日收工前自检**（可选但建议）：
   ```bash
   bash scripts/daily.sh --status
   python -m pytest -q        # 期望全绿
   ```

---

## 附：为什么是这两步（agent 模式）

`daily.sh` 的 agent 分支只做三件事：抓数 → 冻结事实（`context.json`）→ 生成任务卡（`AGENT_TASK.md`），
然后打印 `run_dir` 与下一步命令。研究内容必须由执行器（模型）写进 `agent_output.json`，
再走 `--finish` 完成证据校验、确定性风控、订单、报告、页面与推送。这样保证：

- 研究结论有证据、有反方、有失效条件，不是规则模板冒充；
- 页面、报告、订单、`last_run.json` 出自同一次运行（可对账、可重放）；
- 风控未通过时不会推送页面（退出码 4）。
