# portfolio-brief · 今日点评

## 它解决什么

页面上的「今日点评」曾经是页面里拼的固定句子，读起来空。改成 skill 之后：

- 输入是当次的结构化数据（行情、仓位账本、逐腿动作、组合暴露）；
- 输出是四段带数字的结论，写进 `data/brief.json`；
- 页面只负责渲染；没有产出时回退到前端引擎，不会白屏。

## 何时运行

每个交易日，`scripts/run_update.py` 生成页面之后、发布之前跑一次。
必须能读到本机解密后的持仓（`positions.enc.json` 解密结果），因此这一步在**本机**执行，不在 CI 里执行。

## 输入

| 来源 | 取什么 |
|---|---|
| `web/index.html` 内嵌 `window.DASHBOARD` | `market.regime`（含 `position`）、`market.breadth`、`market.sentiment`、`market.national_team`、`plan.items`（目标权重/评分/档位）、`legs[]`（动作/证据/相对强度） |
| 本机持仓 | 份额、成本、现金 → 当前权重、浮盈亏、仓位 |
| `data/brief_engine.json`（可选） | 前端引擎已算好的四段，可作为草稿，禁止原样照抄 |

## 输出（唯一契约）

写入 `data/brief.json`：

```json
{
  "data_date": "2026-11-19",
  "source": "llm",
  "conclusion": "今日基调：先降后看",
  "sections": [
    {"k": "环境", "v": "盘后：大盘下行趋势，定性偏空（MA5 低于 MA20）；仓位 40.6%，高于锚 35% 达 5.6pct；温度 51/100；上涨家数占 53.7%，成交额环比 -8.6%（缩量）；国家队近四周减持 1.2%（全宽基合计）。"},
    {"k": "结构", "v": "逐腿分布：3 只触发退出、1 只减仓；最弱 588000（D 级，数据不足）；最大暴露 电子 18.4%（未超配）；现金 21.3%。"},
    {"k": "执行", "v": "今日 4 笔：CLEAR 510300、CLEAR 510500、CLEAR 588000、TRIM 159915；其余差额不足 3pct。"},
    {"k": "改判", "v": "基准站上 MA20 4069.52 且 MA5 上穿 MA20 → 仓位锚由 35% 上调 10pct；任一腿跌破 MA30 两日 → 卖出该腿全部差额。"}
  ]
}
```

字段约束：

- `data_date` 必须等于当次 `meta.data_date`，不一致页面不采用。
- `sections` 必须四段且顺序为 环境 → 结构 → 执行 → 改判；`k` 只能是这四个词。
- `v` 里出现的每个数字，必须能在 `DASHBOARD` 或持仓里找到出处；找不到就写「缺失」，不许估算。
- `conclusion` 只能取三种基调之一：`先降后看` / `按差额补，不满仓` / `不动，等条件`，并且必须与 `plan.items[].action` 的多数方向一致。

## 写作规则

1. 每段一句话，全文 ≤ 200 字；短句，不用「综上所述」。
2. 禁止空话：`注意风险`、`保持谨慎`、`密切关注`、`整体合理`、`酌情处理`。
3. 不给目标价，不预测点位，不写「概率高/低」这类没有样本量的表述。
4. 环境段只解释环境，不得出现个股买卖；执行段的动作必须与账本 `action` 完全一致。
5. 出现跨层分歧时，在对应段末写「裁决：…」，例如「日线转强但周线空头，裁决：不加仓」。

## 校验与回退

写入后由 `run_update.py --verify` 校验：

| 检查 | 不过的处理 |
|---|---|
| JSON 结构与四段顺序 | 不采用，回退前端引擎 |
| `data_date` 与页面一致 | 不采用 |
| 出现禁用词 | 不采用 |
| `conclusion` 与账本方向矛盾 | 不采用 |

页面标题会标注来源：采用 skill 时不加后缀，回退引擎时显示「（本机引擎）」。
