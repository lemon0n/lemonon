## 一、Context（为什么做）

现有页面本质是"持仓规则解释器"，用户要的是"全组合资金运营与决策辅助台"：每天回答四个问题——资金现在怎么样、为什么、是否需要行动、不行动的原因。

审计（会话 5m40s 轮）确认了 14 项系统性缺陷，并在真实代码中全部定位。基线 60 项测试通过只说明已覆盖场景通过，**没有覆盖**订单计数、执行后模拟、建仓授权、绩效口径、前后端执行一致性。

同时确认了 8 处指导书弱化/缺失项，本次一并补入（下文标【补】）：

1. 【补】"组合快照完整"拆四层：价格 / 技术面 / 分类与基准 / 综合分析可用；
2. 【补】动作必须携带理由编号、证据 ID、反向证据、触发/失效条件、数据日期、执行后约束结果；
3. 【补】不展示未校准的概率数字（如"上涨概率 87%"）；
4. 【补】ADD 不得仅因浮亏或"价格便宜"触发；
5. 【补】P3 持续评估（引用覆盖率、数值一致性、无动作合理性、规则冲突、时间外回测）；
6. 【补】外部事实需可核查引用，不依赖模型记忆；
7. 【补】ETF 分类与跟踪指数映射需"补齐"，不只在缺失时标不可用；
8. 【补】仓位区间由 市场状态 + 风险预算 + 现金需求 + 集中度 共同决定。

目标产出：单一决策契约 + 三段式页面 + 完整建仓链路 + 可回放审计。

## 三、契约设计

新增 `src/etfquant/portfolio/decision.py`，唯一生成点：

```text
meta               contract_version / run_id / input_hash / config_hash / data_date / mode(python|browser)
portfolio_before   总资产 / 现金 / 持仓市值 / 总仓位 / 权益风险仓位 / 风险桶 / 盈亏口径
market_context     regime / fit_lo,hi / position_band{basis} / benchmark{code,scope} / evidence[]
holding_decisions  action / candidate_state / current_weight / target_weight / current_shares /
                   target_shares / delta_shares / reason_ids / evidence_ids / counter_evidence /
                   trigger / invalidation / data_date / constraints_after / funding_source
opportunities      候选池：READY / WAIT_CONFIRMATION / WATCH / AVOID / ABSTAIN
orders             仅可执行单（delta≠0 且门禁全过）
portfolio_after    静态模拟
validation         checks[] 逐项布尔 + violations
audit              sources / skipped / signal_fingerprint / prev_run
```

- Python：`analysis.analyze()` 产出 `decision`，旧字段保留一版兼容。
- 浏览器：`web_assets/decision.js` 用 `D.contract` 中的约束原值运行同一套规则，`meta.mode='browser'`。
- 幂等：`signal_fingerprint = sha(input_hash + code + rule_ids + 目标方案)`；ADD 基数永远取快照实际份额，不从上次目标累加。
- 动作对外统一 `EXIT`，内部 `CLEAR` 为别名。

## 六、风险与回退

1. **重写 `plan` 改变全部目标份额**（最高风险）：保留 `plan_v1` + `cfg.execution.engine` 开关一轮，用现有 `positions_packet.json` 双跑对比；阶段 2 单独提交。
2. **前端删本地推导引发连锁**（`legDetail/renderLocalLeg/draftCalc` 依赖旧形状）：先加 `PDEC` 适配层，`grep` 确认零调用后再删；`render(decision=False)` 兜底。
3. **刷新行情不再重算动作**被误解为"信号过期"：固定徽标 + `stale_signal` + 测试断言刷新前后 action 不变。
4. 其他风险：配置迁移改错作用域（用 `validate_config` 拦截）；密文兼容（先写兼容读、再写新格式）。

## 七、不在本轮范围

真实净值/交易流水绩效、券商与自动交易、任何阈值调整、多智能体或 LLM 参与数值、盘中信号、服务端持仓存储、税务与多账户。
