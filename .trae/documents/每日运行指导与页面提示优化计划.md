# 每日运行指导与页面提示优化计划

## Context

用户试跑每日运行指导后发现：页面存在固定解释性提示与重复门禁文案，且个人 LLM 没有固定位置输出“市场解读、组合解读、逐仓解读、行动结论”，导致低能力模型只复述字段，无法形成专业但可控的判断。本轮需要同时优化外部 LLM 指导文本和 HTML 展示：固定文案只保留必要的动态数据状态；专业解释由每日 LLM 按固定模板生成；机器规则、阈值、动作和执行门禁不改变。

## 推荐方案

### 1. 每日 LLM 输出固定为五段

在 `docs/持仓分析每日运行指导.md` 中新增强制输出模板，每天必须按以下顺序输出：

1. **数据可信度与可判断范围**：运行时间、行情日、来源、状态、缺失字段、基准覆盖率。说明本次哪些结论可做、哪些不能做。`ABSTAIN/DEMO/ERROR` 时先降级，不得补猜。
2. **市场状态解读**：使用基准收盘、MA5/20/60、20/60日波动、行业涨跌/成交、宏观、政策、消息字段。按“事实 → 当前所处状态 → 对风险预算/仓位的含义 → 支持证据 → 反证/未知”写解读。不得只复述“这是风险过滤器，不是方向预测”；应给出条件式解读，例如趋势偏弱/震荡/修复、波动是否抬升、行业是否扩散或集中，并明确仅能得出风险偏好与观察结论，不预测明日涨跌。
3. **组合资金与持仓解读**：总资产、现金、总仓位、风险仓位、浮盈亏口径、集中度、类别/风险桶、相关性、基准比较和执行后模拟。用“市场状态 × 当前仓位 × 组合约束”解释加仓/减仓/保持观察的原因；区分规则动作、可执行订单和静态模拟。
4. **逐只 ETF 解读**：每只按“事实 → 匹配基准/板块关系 → 对组合影响 → 支持证据 → 反证与未知 → 当前动作 → 下一次触发/失效条件”输出。没有明确 ETF-行业/宏观/政策/新闻映射时必须写“无可验证关联”，不从名称推断因果。
5. **行动结论与观察清单**：只引用结构化动作和候选状态，按优先级列出减仓/加仓/建仓/保持观察；无信号时明确“继续观察”。列出下一次只需核对的条件，不新增价格、代码、目标仓位、胜率或新闻。

每个“判断”必须同时给出：判断、证据字段/日期、反证或未知、实际影响。证据不足时使用“无法判断”，不得用固定话术代替分析。

### 2. 解释标准

- 市场状态解读：
  - 收盘低于 MA20 且 MA20 低于 MA60：趋势偏弱；若 MA5 重新站回 MA20，只能称短线修复，不能称趋势反转。
  - 20日波动高于60日：波动抬升，降低新增风险暴露的确定性；20日波动未抬升，不得写“风险正在扩大”。
  - 行业上涨集中、成交集中：描述结构性行情；行业涨跌分散且成交同步放大，才可描述市场参与面改善；无历史对照时不称“新变化”。
  - 宏观/政策/新闻为快照或日期不完整时，只作组合背景，不解释为单只 ETF 涨跌原因。
- 组合解读：
  - 当前仓位高于区间且存在减仓动作，先处理风险暴露，不因为浮亏自动加仓。
  - 当前仓位在区间内但单类/单只超限，优先调结构，不扩大总仓位。
  - 现金不足、分类缺失、基准缺失或综合分析不可用时，解释为“本次无法形成可执行建议”，不要把它写成“继续持有”或“买入”。
  - 执行后校验失败时只说明失败原因和受影响的动作；删除重复的“本次未发布订单/仅保留诊断草案”套话。
- 逐仓解读：
  - 只引用 facts/comparisons/rules/portfolio_impact/counter_evidence/unknowns/invalidation/links。
  - `CLEAR/TRIM/ADD/HOLD/WATCH/ABSTAIN` 原样解释，不重算、不升级、不降级。
  - 行业、宏观、政策、新闻没有明确映射时，写“无可验证逐仓关联”，不套用全市场叙事。

### 3. HTML 提示精简

- 市场概况：删除固定句“该判定是风险过滤器，不是方向预测；情绪类指标来自离线快照，不参与定仓”。保留市场状态事实数据；行业标题改为“板块概况”，旁边使用 `i`，悬浮/点击后显示“申万一级行业 · 面积=流通市值 · 颜色=涨跌幅”。
- 持仓分析：删除“信号基于某日收盘……刷新行情不改变日频动作……”常驻提示；该信息如仍必要，只保留为状态徽标或 `i` 说明。
- 删除重复的执行后失败说明和订单未发布说明；只有当日动态异常时显示一条易懂原因，例如“分类缺失：5 只持仓无法完成结构核对，因此本次不生成调仓单”。
- 删除“完整市场概况见市场概况页”等导航说明；删除固定“当前没有满足组合约束的新增方向，继续观察”之外的重复解释，保留动态结果本身。
- 删除 p5 标题前的 `①/②/③` 编号，改用较大加粗分区标题；保留四区导航：组合概览、逐仓分析、市场与外部驱动、结构与回溯。
- 固定份额回溯的限制只保留一个 `i`，不重复长段免责声明；动态加载失败和数据缺失仍保留。

### 4. 动态提示改为易懂中文

将“综合分析不可用”“类别未分类执行后超过上限”等内部字段转译为：

- “有 5 只持仓没有类别/基准映射，无法判断结构是否合理；本次不生成调仓单。”
- “未分类资产合计约占组合 67.54%，超过 60% 结构上限。先补齐分类，再判断是否需要调仓。”
- “执行校验未通过：分类信息缺失。不是市场卖出信号，本次只是不具备可靠的组合执行条件。”

仅在能从结构化字段确定原因时显示；无法确定时显示“执行条件不足，详情见数据质量”，不输出内部错误堆栈或重复门禁句。

## 验证

- 检查 HTML 源模板而不是手改生成产物；确认 p1/p5/p7 的固定重复话术已移除，动态状态仍可见。
- 确认 `methodology.yaml` 规则 ID、阈值、优先级、动作和执行逻辑无变化。
- 运行现有测试和页面静态语法检查；不读取或修改真实持仓密文。
- 用一个缺分类/缺价/综合不可用的夹具确认提示能说明实际原因；用正常夹具确认“每日分析”模板字段可以由外部 LLM 读取并生成固定五段结果。

## 范围边界

本轮不在应用内接入 LLM，不自动保存或上传 LLM 文本，不改变交易规则，不新增数据源，不把“沉关河”原文变成不可观测的机器因果规则。
